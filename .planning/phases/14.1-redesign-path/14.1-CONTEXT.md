### Starter-Bug Repair Strategy (Requirement 1)

- **D-01 — Repair via filter + warn, EmptyState fallback if all 3 drift.** [`getStarterSongs()`](../../../src/lib/gamification/starter-songs.ts) at line 106-112 currently throws unconditionally if any of the 3 approved slugs (`under-the-tree-sim`, `misa-no-uta-aya-hirano`, `yume-wo-kanaete-doraemon-mao`) is missing from `songs` table or has no non-null lesson. New behavior: drop missing/lessonless slugs from the result, log a `console.warn` (or use the existing logger pattern — verify in plan-phase), render whatever remains (1–3 cards). If ALL three drift, return `[]` and `<StarterPick>` renders an `<EmptyState>` (Phase 14 primitive) with copy like "More starter songs coming soon — explore the catalog" + a CTA to `/songs`. Reject try-catch at the call site (confusing UX — user falls into PathMap with no progress). Reject DB-fix-and-keep-throw (doesn't address future drift). Reject replacement-list (dilutes the user-curated triple from Plan 03 Task 2 decision checkpoint).

- **D-02 — StarterPick visual restyle is OUT of 14.1 scope.** Only the bug-fix lands in 14.1. `<StarterPick>` keeps its existing token-migrated shape (Plan 14-09 D-22 already cleaned the palette). Full cover-art-as-background restyle of starter cards moves to a follow-up plan after 14.1 lands. Recorded in `<deferred>` below. This keeps phase scope tight and ships faster — first-visit users see brief visual inconsistency between the new `/path` and the older starter cards, accepted trade-off.

### Kana Checkpoint Data Source + Links (Requirement 6)

- **D-03 — Client-island KanaCheckpointNode reads `useKanaProgress` zustand store directly.** Kana progress lives only in [`src/stores/kanaProgress.ts`](../../../src/stores/kanaProgress.ts) (zustand + localStorage persist, key `kitsubeat-kana-mastery-v1`, `MasteryMap = Record<string, 0..10>`). No server-side `kana_progress` table exists. `<KanaCheckpointNode>` becomes a `'use client'` component that reads the store directly. First paint renders a `<Skeleton>` (Phase 14 primitive — pick the closest-shaped variant during plan-phase, likely a card-row variant); on hydration, real progress shows. `<PathMap>` itself stays server-rendered — only the kana checkpoint nodes become client islands (one per checkpoint, ~2 islands). Reject cookie-bridged SSR (would write a kana update on every answer, cookie growth + sync hook complexity, doesn't survive cross-device). Reject new server-side `kana_progress` table (out of stated scope; SPEC says no new tables; would need migration + backfill + sync logic).

- **D-04 — Mastery threshold: per-char ≥7 stars; checkpoint = mastered when 90%+ of basic-row chars at that threshold.** The `useKanaProgress` 0–10 star scale treats 7+ as the comfortable tier (verify exact threshold semantics in [`src/lib/kana/mastery.ts`](../../../src/lib/kana/mastery.ts) during plan-phase — `applyStarDelta` shape will tell us if 7 maps to a meaningful FSRS-lite milestone). Concretely: hiragana-checkpoint mastered when `Object.values(hiragana).filter(s => s >= 7).length >= 0.9 * BASIC_HIRAGANA_COUNT` (BASIC_HIRAGANA_COUNT = 46 per the Phase 9 a/i/u/e/o-row through wa + ん). Same logic for katakana. **In-progress** = any non-zero mastery below the mastered threshold. **Locked** = empty `{}` map for that script. Plan-phase: extract this logic into a shared helper (likely `src/lib/kana/checkpoint-state.ts`) so the checkpoint state computation is unit-testable and reused if future phases need it.

- **D-05 — All checkpoint states route to `/kana?script={hiragana|katakana}`.** No new routes. Mastered + in-progress + locked all link to the existing `/kana` grid page with a script query param. Plan-phase: verify [`src/app/kana/page.tsx`](../../../src/app/kana/page.tsx) accepts `script` as a query param OR add minimal handling to default the visible script to the param value (small change inside `/kana` only, not a route addition). Reject mastered → `/kana/session?mode=review` (would require extending kana session selection logic — out of 14.1 scope, expands SPEC). Reject all → `/kana` no-param (extra tap for katakana users hitting hiragana-default).
