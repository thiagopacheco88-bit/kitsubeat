## Summary

Token discipline is consistently observed: I found zero raw hex utilities in component code; the few `style={{ background: "linear-gradient(...)" }}` and `rgba(0,0,0,0.65)` uses are inline (outside the no-raw-tokens rule's `className` scope) and acceptable for gradients with transparency endpoints. The findings below are non-blocking but worth addressing — three carry real bug or a11y consequences (WR-01, WR-02, WR-03), one is a minor maintainability concern (WR-04), and the Info items are cleanup-grade.

## Warnings

### WR-01: PathMap secondary sort by `popularity_rank` is dead code (field never selected)

**File:** `src/app/path/components/PathMap.tsx:30-37`
**Issue:** The sort comparator coerces `song` to `{ popularity_rank?: number | null }` via `as unknown as`, then falls back to `999999` when missing. But `getAllSongs()` in `src/lib/db/queries.ts` (lines 136-292) does NOT select `popularity_rank` — it only orders by it (line 304). So `song.popularity_rank` is always `undefined`, every comparison returns `999999 - 999999 = 0`, and the secondary sort is a no-op. This works today only because the DB pre-sorts the array and `Array.prototype.sort` is stable, so within-tier order is preserved by accident. Any future change that ever pre-sorts by something else would silently break tier-internal ordering, and the `as unknown as` cast hides the bug from the type checker.
**Fix:** Either (a) add `popularity_rank: songs.popularity_rank` to the `getAllSongs()` select so the cast becomes a real read, or (b) drop the secondary sort entirely and document that input order is the authoritative tiebreaker:
```ts
// In src/lib/db/queries.ts getAllSongs select:
popularity_rank: songs.popularity_rank,

// Then in PathMap.tsx, remove the cast:
const ra = a.popularity_rank ?? 999999;
const rb = b.popularity_rank ?? 999999;
```

### WR-02: Nested `role="list"` containers without explicit `role="listitem"` children

**File:** `src/app/path/components/PathMap.tsx:60-68, 89`
**Issue:** Two ARIA list-role issues:
1. The outer container at line 89 declares `role="list"` but its children are `<TierDivider>`, the kana-checkpoint `<div>`, and per-song wrapper `<div>`s — none expose `role="listitem"`. WAI-ARIA requires a `list` to contain `listitem` children. axe-core's `aria-required-children` rule will flag this.
2. The kana-checkpoint row at line 61 nests another `role="list"` inside the outer list, also without `role="listitem"` children. Doubled violation.

The path-a11y.spec.ts threshold of `<= 5` minor/moderate violations may absorb this in the short run, but it consumes budget and is a real screen-reader bug — VoiceOver/NVDA will not announce a coherent list count.
**Fix:** Either drop the `role="list"` declarations (semantic `<ul>` would be cleaner) or add `role="listitem"` to each child wrapper. Minimal patch:
```tsx
// PathMap.tsx — kana row
<div
  key="kana-checkpoint-row"
  className="grid grid-cols-1 sm:grid-cols-2 gap-2 my-2"
  role="list"
  aria-label="Kana checkpoints"
>
  <div role="listitem"><KanaCheckpointNode script="hiragana" /></div>
  <div role="listitem"><KanaCheckpointNode script="katakana" /></div>
</div>

// PathMap.tsx — per-song wrapper
<div key={song.slug} role="listitem" className={`${alignClass} w-full max-w-xs`}>
  <PathNode ... />
</div>
```

### WR-03: `gap-2` and `space-y-1` both applied to the same flex container — conflicting spacing systems

**File:** `src/app/path/components/PathMap.tsx:89`
**Issue:** `className="flex flex-col gap-2 space-y-1"` combines flexbox `gap-2` (8px between items) with `space-y-1` (which sets `margin-top: 0.25rem` on each non-first child). Both apply, so each item ends up with 8px of gap **plus** 4px of top margin = 12px effective spacing, and the spacing is non-uniform (the first/last items behave differently from middle ones depending on browser). This was almost certainly meant to be one or the other.
**Fix:** Pick one spacing system:
```tsx
<div className="flex flex-col gap-2" role="list" aria-label="Learning path">
```

### WR-04: `getStarterSongs()` `lessonMissing` derivation iterates `rows` twice and has subtle ordering coupling

**File:** `src/lib/gamification/starter-songs.ts:100-122`
**Issue:** The "all 3 drift" branch is gated on `lessonedRows.length === 0` AND `allFiltered.length > 0`. When every row in `rows` has `has_lesson === null`, `lessonedRows.length === 0` and `allFiltered.length === 3`, so the all-drift warn fires correctly. But if `rows` is empty (DB returned zero rows because all 3 slugs were renamed/deleted), `lessonedRows.length === 0` AND `allFiltered.length === 3` (all 3 in `dbMissing`) — the all-drift warn also fires, masking the per-slug detail. Test 3 covers the all-`has_lesson:null` case but no test covers the all-DB-missing case, so this regressing to single-warn behavior would slip past the suite.
**Fix:** Add a Test 5 covering the empty-rows path, and consider emitting both the all-drift summary AND the per-slug list so the operator sees which 3 slugs vanished:
```ts
if (allFiltered.length > 0 && lessonedRows.length === 0) {
  console.warn(
    "[starter-songs] ALL approved starter slugs missing — rendering EmptyState fallback. " +
      "Update STARTER_SONG_SLUGS or restore DB rows: " +
      allFiltered.join(", "),
  );
  // Optional: also emit per-slug detail
  for (const slug of allFiltered) {
    console.warn(`[starter-songs] ${slug} missing or lessonless`);
  }
}
```

## Info

### IN-01: `"use client"` directive on `ContinueAnchor.tsx` is unnecessary

**File:** `src/app/path/components/ContinueAnchor.tsx:1`
**Issue:** The component renders a static `<Link>` with no client hooks (no `useState`, `useEffect`, `useRouter`, no event handlers). The `"use client"` directive forces it onto the client bundle for no benefit. Removing it would let Next bundle it as a server component and shrink the /path client bundle slightly.
**Fix:** Delete the `"use client";` line.

### IN-02: `MASTERY_STAR_THRESHOLD` imported but never referenced in the test

**File:** `src/lib/kana/checkpoint-state.test.ts:6`
**Issue:** `MASTERY_STAR_THRESHOLD` is destructured from the import but never used in any assertion. The tests use the literal `7` directly. This is dead-import noise.
**Fix:** Drop it from the import:
```ts
import {
  computeCheckpointState,
  BASIC_HIRAGANA_COUNT,
  BASIC_KATAKANA_COUNT,
} from "./checkpoint-state";
```

### IN-03: Hardcoded magic number `999999` for null popularity_rank fallback

**File:** `src/app/path/components/PathMap.tsx:34-35`
**Issue:** `999999` is a magic sentinel for "missing rank, sort last". If anyone ever has a real `popularity_rank` >= 999999, the sort breaks silently. Use `Number.MAX_SAFE_INTEGER` or `Infinity` for self-documenting "always-last" semantics.
**Fix:**
```ts
const ra = a.popularity_rank ?? Number.POSITIVE_INFINITY;
const rb = b.popularity_rank ?? Number.POSITIVE_INFINITY;
```
(This applies regardless of whether WR-01's primary fix is taken.)

### IN-04: `KanaCheckpointNode` "in-progress" and "locked" states share the same `pillClass`

**File:** `src/app/path/components/KanaCheckpointNode.tsx:81-82, 98-99`
**Issue:** Both branches assign exactly `"bg-[var(--color-card-2)] text-[var(--color-text-muted)]"` to `pillClass`. The duplication suggests either an unintentional copy-paste or a deferred styling decision. If they're meant to differ visually (e.g., locked could be slightly dimmer), document it; if not, hoist to a constant.
**Fix:** Hoist:
```ts
const NEUTRAL_PILL = "bg-[var(--color-card-2)] text-[var(--color-text-muted)]";
// then both branches: pillClass = NEUTRAL_PILL;
```

### IN-05: `PathNode.test.tsx` fixture types `difficulty_tier` as `2` (number) but DB enum returns `"basic" | "intermediate" | "advanced"` (string)

**File:** `src/app/path/components/PathNode.test.tsx:42`
**Issue:** `difficulty_tier: 2` is cast to `SongListItem` via `as unknown as`. The real type from `getAllSongs()` (queries.ts line 151, `difficultyEnum`) is the postgres enum string. The cast hides the mismatch from TypeScript. PathNode itself doesn't read `difficulty_tier`, so the test still passes — but the fixture is misleading and would not exercise PathMap's tier-sort path correctly if reused.
**Fix:** Use the real enum value:
```ts
difficulty_tier: "basic" as const,
```

### IN-06: Pre-baseline pixeldiff script writes to a hardcoded `_temp/` path with no directory-existence check

**File:** `scripts/debug/path-baseline-pixeldiff.mjs:22-24, 40, 62`
**Issue:** `fs.writeFileSync(LIVE_PNG, ...)` and `fs.writeFileSync(DIFF_PNG, ...)` will throw `ENOENT` if `_temp/path-redesign/` does not exist on a fresh checkout. The script comment promises a one-shot pre-Playwright gate, but the failure mode is opaque.
**Fix:** Add an idempotent mkdir before writing:
```js
fs.mkdirSync(path.dirname(LIVE_PNG), { recursive: true });
```
(One-shot operator script, low impact, but a 30-second papercut for any new contributor running the gate.)
