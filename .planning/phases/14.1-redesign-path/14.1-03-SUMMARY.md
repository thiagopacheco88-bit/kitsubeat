## Implementation Notes

### BASIC_HIRAGANA_CHARS / BASIC_KATAKANA_CHARS sourced from KANA_CHART

Both character sets are derived at module load by filtering `KANA_CHART` for `rowKind === "base"` and mapping to the respective glyph:

```ts
const BASIC_HIRAGANA_CHARS = KANA_CHART.filter(c => c.rowKind === "base").map(c => c.hiragana);
const BASIC_KATAKANA_CHARS = KANA_CHART.filter(c => c.rowKind === "base").map(c => c.katakana);
```

Runtime count verified by vitest test: both equal 46 (a-row 5 + ka-row 5 + sa-row 5 + ta-row 5 + na-row 5 + ha-row 5 + ma-row 5 + ya-row 3 + ra-row 5 + wa-row 2 + n-row 1 = 46). Results are frozen with `Object.freeze` to prevent accidental mutation.

### Math.ceil Rounding Decision (41 vs 42 cutoff confirmed)

`MASTERY_RATIO_THRESHOLD = 0.9` applied via `Math.ceil(0.9 * 46) = Math.ceil(41.4) = 42`. This means:
- 41 chars at ≥7 stars -> `in-progress` (41 < 42 required)
- 42 chars at ≥7 stars -> `mastered` (42 >= 42 required)

Both boundary cases are explicitly tested (tests 7 and 8), confirming the rounding decision.

### Cross-Script Key Handling (Test 9)

The helper iterates only over `basicChars` (script-specific set), never over `Object.keys(map)`. This means katakana glyphs present in a hiragana MasteryMap are naturally excluded — the loop never encounters them. Explicitly tested: `{あ: 7, ヤ: 7}` with `script="hiragana"` yields `masteredCount: 1` (only `あ` counted).

### Locked Detection

Uses `Object.values(map).some(stars => stars > 0)` rather than `Object.keys(map).length > 0`. This treats a map of all-zero star values identically to an empty map — both indicate "user hasn't engaged yet." Consistent with the CONTEXT D-04 semantics.
