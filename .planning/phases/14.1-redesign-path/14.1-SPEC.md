# Phase 14.1: Redesign /path — Specification

**Created:** 2026-05-02
**Ambiguity score:** 0.18 (gate: ≤ 0.20)
**Requirements:** 8 locked

## Goal

Apply the locked **CA-hybrid** design language (cover-art-as-background nodes + lantern-streak header + hero-progress block + visual-only locked treatment + Japanese-co-headed tier dividers + sticky Continue CTA, plus first-class kana checkpoints) to the `/path` surface, using only the Phase 14 token system extended with 4 new tokens — and unblock visual verification by repairing the existing `getStarterSongs()` runtime error.

## Background

`/path` is the smallest in-scope surface (5 files, ~280 LOC) and the first target of the post-Phase-14 surface revamps (briefings 2 and 3 cover `/` and `/songs/[slug]`).

**What exists today (master HEAD, post-Phase-14):**
- [src/app/path/page.tsx](src/app/path/page.tsx) — server component: parallel-fetches `state` + `songs`, fetches `rewardSlotDefinitions`, computes `nextReward`, conditionally fetches `starterCandidates` when `state.current_path_node_slug === null`.
- [src/app/path/components/PathHud.tsx](src/app/path/components/PathHud.tsx) — server component: fox-avatar SVG + level + XP `<progress>` bar + 🔥 emoji streak + optional next-reward chip.
- [src/app/path/components/PathMap.tsx](src/app/path/components/PathMap.tsx) — client: sorts songs by `difficulty_tier` + `popularity_rank`, renders inline tier-divider chips (`Beginner / Intermediate / Advanced`, plain English), alternates left/right offset, threads `currentNodeSlug`. **Songs only — no kana checkpoints.**
- [src/app/path/components/PathNode.tsx](src/app/path/components/PathNode.tsx) — client: wraps `CardLink` (variant=flat), renders thumbnail + title + anime + completed-check + "Next up" pill. **M1 invariant: every node clickable, no disabled/pointer-events:none anywhere.** Completion derived from `ex1_2_3_best_accuracy > 0`.
- [src/app/path/components/StarterPick.tsx](src/app/path/components/StarterPick.tsx) — client: 3-card welcome modal when `current_path_node_slug === null`. Uses Button primitive + token recipes.

**Locked design direction:** `_temp/path-redesign/demo-CA-hybrid.html` (633 LOC React-on-Babel prototype). Demo introduces:
- `LanternStreak` — SVG paper lantern with flame intensity scaling (`<7` dim / `7-29` warm / `30+` blazing); replaces 🔥 emoji; lives in **header**, not HUD.
- `PathHeader` — fox-mark wordmark "Kitsu**Beat**" + LanternStreak.
- `HeroProgress` — level + XP bar + "Now Learning · {current song title}" callout.
- `TierDivider` — Japanese co-heading (`Side A · 基礎 · Beginner`), tier-specific SVG icon (bamboo / torii / mountain), 1px rule + card-2 chip.
- `PathNode` (cover-art-as-background) — 84px tall, ~38% cover panel + 62% info panel, 3-star aura halo (`ka-aura` keyframe, reduced-motion safe), PLAY ▶ pulse on current, mist + grayscale on locked, "Next Up" / "Mastered" / "In progress" / "霧 · Locked" state pill.
- `KanaCheckpointNode` — NEW node type, 64px tall, large kana glyph (`あ` / `ア`) in circle badge, dashed border, inline progress bar for in-progress.
- `ContinueAnchor` — sticky bottom CTA (`min-height: 56px`, brand-red, gradient-fade fixed at bottom); virality #2 (one clear action) + #3 (thumb-zone).

**4 new tokens needed** (not currently in `globals.css`):
- `--shadow-cta-red` — Continue CTA glow
- `--shadow-hero-glow` — hero-card accent shadow (already declared in Phase 14 SPEC §A.6 but not yet authored — confirm during plan)
- `--mist-fill` — locked-node overlay gradient
- `--aura-color` — 3-star aura radial-gradient color (theme-scoped alpha)

**Known blocker (must be unblocked for visual verify to work):** `/path` currently throws at runtime when an unauthenticated/new user hits the `getStarterSongs()` branch — the function returns slugs that are no longer in the live `songs` table, and `<StarterPick>` renders a `<Button>` against an undefined card. Without repair, the post-execution visual verify gate cannot run.

**Source briefing:** `HUASHU-BRIEFINGS.md` — Briefing 1 (`/path`) + Virality Goals (5 principles applied to all surfaces).

## Requirements

1. **Starter-bug repair (prerequisite)**: `/path` renders without runtime error for both authenticated and unauthenticated/first-visit users.
   - Current: `getStarterSongs()` returns at least one slug not present in the `songs` table; `<StarterPick>` render throws when an undefined candidate hits `<Button>` / image rendering.
   - Target: `getStarterSongs()` either filters to slugs proven to exist in the `songs` table at query time, or `<StarterPick>` skip-renders missing candidates. `/path` route returns 200 with renderable HTML for `current_path_node_slug === null` users.
   - Acceptance: Playwright test seeds `current_path_node_slug = null`, navigates to `/path`, asserts `<StarterPick>` renders ≥1 valid card (or graceful empty state), with `expect(page).not.toHaveBeenInError()`. Manual smoke on dev server confirms no console errors.

2. **PathHeader (NEW component)**: Streak migrates out of HUD into a persistent header chip; KitsuBeat wordmark accompanies it.
   - Current: No `/path`-specific header; the streak (🔥 + count) lives in `PathHud` body.
   - Target: New `<PathHeader>` server component renders KitsuBeat fox-mark + wordmark on left, `<LanternStreak>` on right. Replaces the inline streak block in `PathHud`. Uses Phase 14 tokens only.
   - Acceptance: Rendered `/path` HTML contains `[data-testid="path-header"]` containing both the wordmark and the lantern streak; `PathHud` no longer renders any 🔥 emoji or streak number.

3. **LanternStreak (NEW component)**: SVG paper lantern replaces 🔥 emoji with intensity scaling.
   - Current: 🔥 emoji + numeric count + "Best: N" sub-line in `PathHud`.
   - Target: New `<LanternStreak count={state.streak_current} />` component — inline SVG lantern (paper warm + bamboo ribs + flame core), flame opacity tier `<7` dim (0.45) / `7-29` warm (0.70) / `30+` blazing (1.0). `streak_best` displayed in HUD or omitted (resolve in plan-phase). `ka-flicker` keyframe animation, suppressed by `prefers-reduced-motion`.
   - Acceptance: Vitest renders `<LanternStreak count={N}>` for N ∈ {3, 15, 60} and asserts the flame `<ellipse>` opacity attribute matches the corresponding tier value. Playwright reduced-motion spec asserts the `animation-duration` resolves to `0ms` on the flicker element.

4. **HeroProgress block**: Level + XP bar + "Now Learning · {current song}" callout replaces the inline level/XP/avatar layout in `PathHud`.
   - Current: `PathHud` shows fox-avatar + Level N + `<progress>` bar + XP-to-next text + (now-removed) streak. No "Now Learning" callout.
   - Target: New `<HeroProgress>` component (or refactored `PathHud` body) — left column = label "Level" + numeric level (28px tnum), right column = label "Now Learning" + current song's `title` in Noto Sans JP. Token-driven XP bar with red accent fill + soft red glow (`var(--color-accent)` + box-shadow). Avatar is **dropped** in this phase (move to plan-phase decision if it should reappear elsewhere).
   - Acceptance: For a user with `current_path_node_slug = "silhouette-kanaboon"` and `xp_total` mid-level, `/path` renders an element with `[data-testid="hero-progress"]` containing the song's display title and the percent-complete computed by `xpWithinCurrentLevel(state.xp_total)`.

5. **PathNode redesign (cover-art-as-background)**: Each song node becomes a 2-panel card with cover-art panel (~38%) and info panel (~62%), 84px tall.
   - Current: 56px-tall horizontal `CardLink` with 48×36 thumbnail + title + anime + check + "Next up" pill.
   - Target: Cover-art panel on the left uses `https://img.youtube.com/vi/${youtube_id}/maxresdefault.jpg` (fallback to `default.jpg` if needed) as full-bleed background with bottom-fade gradient; Japanese title overlays the gradient in Noto Sans JP. Info panel on the right shows romaji (uppercase tracking), anime, and a state row containing one of: `<StarAura>` (1–3 stars + aura on 3-star), "Next Up" (red), "In progress" (muted), "霧 · Locked" (dim). PLAY ▶ pulse overlay on `state === 'current'`. Mist + grayscale on `state === 'locked'`. **M1 invariant preserved: every node remains clickable regardless of state.**
   - Acceptance: `<PathNode>` renders for each of the 4 states (mastered / current / in_progress / locked) and (a) every state's root element is a `<CardLink>` (no `disabled` attr, no `pointer-events:none` style); (b) the locked state's mist overlay has `pointer-events: none` so the underlying link still receives taps; (c) the current state renders the PLAY pulse with reduced-motion fallback to `animation: none`.

6. **KanaCheckpointNode (NEW node type)**: Hiragana / Katakana milestones become first-class path nodes.
   - Current: `PathMap` renders songs only; kana progress lives in a separate route (`/kana`).
   - Target: New `<KanaCheckpointNode>` (~64px tall, dashed border, large kana badge `あ` / `ア`) renders inline at the start of the relevant tier (basic). Real progress data is wired from the existing kana progress source (resolve specific data path during plan-phase) — at minimum: `mastered`, `in_progress` (with percent), `locked`. Mastered nodes link to `/kana/{script}/review` (or equivalent), unmastered link to `/kana/{script}` (resolve in plan-phase). Visual treatment matches demo: mastered → accent kana color + "Mastered" pill; in-progress → orange progress bar + "{N}%" pill; locked → mist overlay + "霧 · Locked".
   - Acceptance: At least 2 kana checkpoints (hiragana + katakana) render in the basic-tier section of `/path`; each renders a kana glyph, script name, and one of the 3 state pills; clicking a checkpoint navigates to a `/kana/...` route (verified by Playwright `expect(page).toHaveURL(/^\/kana/)`).

7. **TierDivider (full demo treatment)**: Tier dividers gain Japanese co-heading + tier-specific SVG icon + restyle.
   - Current: Inline `<span>` chip in `PathMap` rendering English-only labels (`Beginner` / `Intermediate` / `Advanced`).
   - Target: New `<TierDivider>` component rendering 1px rule + card-2 chip containing `<TierIcon kind={bamboo|torii|mountain}>` SVG (16px, `currentColor`) + bilingual label (`Side A · 基礎 · Beginner` / `Side B · 中級 · Intermediate` / `Side C · 上級 · Advanced`) in Noto Sans JP, uppercase tracking. `aria-label` preserves full label for screen readers.
   - Acceptance: `<PathMap>` rendered with songs spanning all 3 tiers contains exactly 3 `<TierDivider>` instances, each with a `<svg>` (one of bamboo/torii/mountain) and the bilingual text label.

8. **ContinueAnchor (sticky CTA)**: A persistent bottom-anchored "Continue · {song}" button replaces "scroll-and-tap" navigation as the primary action.
   - Current: No persistent CTA. User scrolls the path, finds the "Next up"-pilled node, and taps it.
   - Target: New `<ContinueAnchor>` client component — fixed-bottom 56px-min-height button (`var(--color-accent)` background, `var(--shadow-cta-red)` glow), gradient-fade above it so content scrolls underneath, render only when a current song exists. Tap routes to `/songs/{currentNodeSlug}`. Suppressed (or replaced with "Pick a starter song" CTA) on the `<StarterPick>` branch.
   - Acceptance: Playwright on `/path` (authenticated, `current_path_node_slug !== null`) at viewport 390×844 finds a button at `position: fixed`, `bottom: 0`, `min-height >= 56px`, with text containing the current song's title; tap navigates to `/songs/{slug}`. On the StarterPick branch, no `<ContinueAnchor>` renders (or alternative starter-flow CTA renders).

## Boundaries

**In scope (this phase produces):**
- Visual + structural redesign of `/path` to match `_temp/path-redesign/demo-CA-hybrid.html`.
- New components: `<PathHeader>`, `<LanternStreak>`, `<HeroProgress>`, `<TierDivider>` (extracted), `<KanaCheckpointNode>`, `<ContinueAnchor>`.
- Refactored components: `<PathHud>` (becomes thin shell or merges into `<HeroProgress>`), `<PathMap>` (delegates to extracted divider + adds kana row), `<PathNode>` (cover-art-as-background rewrite).
- 4 new tokens added to `src/app/globals.css` for both dark + light themes: `--shadow-cta-red`, `--shadow-hero-glow`, `--mist-fill`, `--aura-color`. Confirm `--shadow-hero-glow` is not already authored from Phase 14-01 (per Phase 14 SPEC §A.6) — if so, treat as 3 new tokens.
- 3 new keyframes in `globals.css` (or scoped CSS): `ka-pulse` (PLAY overlay), `ka-flicker` (lantern flame), `ka-aura` (3-star halo) — each with `prefers-reduced-motion` fallback.
- Wiring `/path` to the existing kana progress data source so kana checkpoints render real state.
- Repair of the `/path` runtime error in `getStarterSongs()` (Plan 14.1-00 prerequisite).
- Documentation entries appended to `docs/motion-catalog.md` for `ka-pulse`, `ka-flicker`, `ka-aura` (Phase 14 motion-catalog convention).

**Out of scope:**
- Home redesign (`/`) — covered by Phase 14.2 per `HUASHU-BRIEFINGS.md` Briefing 2.
- Lesson redesign (`/songs/[slug]`) — covered by Phase 14.3 per `HUASHU-BRIEFINGS.md` Briefing 3.
- Visible social activity (cross-user feeds, "X learners on this song now", leaderboards, follows) — explicitly DEFERRED to Phase 14.4-virality-engagement (see `.planning/phases/14.4-virality-engagement/INTENT.md`).
- Streak behavioral systems (push notifications, streak-saver token, weekly recap email, daily reminder system) — explicitly DEFERRED to Phase 14.4. Lantern is **visual amplification only** here.
- True progression gating (locking advanced nodes behind completion of N prior nodes) — `state === 'locked'` is **visual-only**; M1 invariant preserved (every node remains clickable). Real progression gates remain a future-phase decision.
- Avatar redesign or new avatar tokens (`--color-avatar-bg` etc.) — `PathHud`'s fox-avatar SVG is **dropped** from `/path` in this phase per the demo; if/where the avatar reappears in profile/HUD is out of scope.
- `<StarterPick>` visual redesign beyond the bug repair — full restyle to match the new design language is deferred (resolve scope during plan-phase if user wants to fold it in).
- Cross-surface header changes — the new `<PathHeader>` lives in `/path` only this phase; promotion to a global `RootLayout` header (so streak shows on every surface) is virality #5's eventual destination but is out of scope for 14.1.
- Backend / data-shape changes — no new tables, no schema migrations, no new server actions beyond what's needed to surface kana progress and repair `getStarterSongs()`.

## Constraints

- **Token system (hard):** Every new color / shadow / spacing / radius / motion value MUST resolve to a `var(--*)` token. The `kitsubeat-tokens` ESLint plugin must report 0 violations across changed files. New tokens (4) MUST be authored in `src/app/globals.css` for both `[data-theme="dark"]` and `[data-theme="light"]` scopes.
- **Both themes (hard):** Every new component MUST render correctly in both dark (default) and light themes — no theme-flip-incoherent backgrounds, no hardcoded white/black on theme-flipping surfaces. Manual visual check at both themes is required before merge.
- **Reduced-motion (hard):** All 3 new keyframes (`ka-pulse`, `ka-flicker`, `ka-aura`) MUST honor `@media (prefers-reduced-motion: reduce)` via `globals.css` global override (Phase 14-01 belt-and-suspenders pattern). Reduced-motion Playwright spec MUST cover all 3.
- **M1 invariant (hard):** No `disabled` attribute, no `pointer-events: none` on any interactive node — including locked-state path nodes. Mist overlays MUST set `pointer-events: none` so taps fall through to the underlying `<CardLink>`.
- **Mobile-first (hard):** Baseline viewport 390×844 (iPhone 14 Pro). All tap targets ≥44px (Phase 14 SPEC AC #11 carry-over). `<ContinueAnchor>` ≥56px.
- **Bundle budget (soft):** `/path` is not on the Phase 13 50KB budget list, but the additions (new components + 3 keyframes + 4 tokens) should not push `/path` First Load JS regression beyond ~10KB from current baseline. Capture pre/post bundle size in plan-phase verification.
- **Data shape (hard):** No changes to `GamificationState` shape, `SongListItem` shape, or `current_path_node_slug` semantics. New components consume existing data. Kana progress data path may require a new query or hook but MUST NOT alter the existing gamification schema.
- **Accessibility (hard):** axe-core score ≥95 on `/path` post-redesign (Phase 14 SPEC AC #12 carry-over). All SVG decorative graphics get `aria-hidden="true"`; `<LanternStreak>` exposes `aria-label="{N}-day streak"`.
