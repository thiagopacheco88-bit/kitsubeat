**Gathered:** 2026-05-10

<domain>
## Phase Boundary

Build a `/journal` content section on KitsuBeat to drive organic traffic via SEO-optimised articles covering anime culture, song translations, and Japanese language explainers. Articles are generated by Subutai (external content tool) as MDX files. The section must feel native to the app — same session-14 design system, not a bolted-on blog. No headless CMS; MDX is the source of truth.

**This phase does NOT include:**
- Domain purchase (no domain yet — build on existing Vercel deployment)
- Content generation (Subutai handles that separately)
- A commenting system or newsletter signup (deferred)

</domain>

<decisions>
## Implementation Decisions

### Routes
- Index: `/journal` — card grid of articles
- Article: `/journal/[slug]` — individual article page, MDX-rendered

### Content Storage
- MDX files in `src/content/journal/` — Subutai drops `.mdx` files here
- Frontmatter fields per article:
  - `title` (string, required)
  - `slug` (string, required — matches filename)
  - `date` (ISO date string, required)
  - `coverImage` (string path or URL, required)
  - `category` (enum: `lore` | `language` | `translation`, required)
  - `summary` (string, required — used for OG description and card preview)
  - `tags` (string[], optional)
  - `author` (string, optional — defaults to "KitsuBeat")
  - `readingTime` (string, optional — e.g. "5 min read")

### Design System
- Use session-14 design tokens throughout (Stage Lights on a Route: C+A hybrid)
- Cover-art-as-background nodes on the index card grid
- Article hero = `coverImage` as background with dark overlay and title on top
- Same shell/nav/footer as the rest of the app — no context switch for the user
- Category badge on each card (lore / language / translation)

### SEO Layer (mandatory)
- `<title>` and `<meta description>` per article from frontmatter
- Open Graph tags: `og:title`, `og:description`, `og:image` (coverImage), `og:type=article`
- `schema.org/Article` JSON-LD on each article page
- Add `/journal` and `/journal/[slug]` to `sitemap.xml` (static or dynamic)
- Canonical URL on every article page

### Content Strategy (informs design, not scope)
- First article planned: Magikarp/Gyarados + koi waterfall legend (category: lore)
- Mix of top-of-funnel (anime lore) and mid-funnel (language/translation) content
- Each article should bridge naturally to the app (e.g., "learn this vocab in KitsuBeat")

### Claude's Discretion
- MDX parsing library choice (next-mdx-remote vs @next/mdx vs contentlayer)
- Reading time calculation approach
- Image handling (next/image with priority vs lazy)
- Category filter UI on index (can be added or deferred)

</decisions>
