# Phase 14.3 SPEC: Redesign Lesson (`/songs/[slug]`)

## Goal

Apply the Phase 14.1 and 14.2 visual language to the core lesson surface so the video and lyrics read as a music-player experience, practice reads as a game loop, and moving from lyrics to practice feels like a single gear shift inside the lesson rather than route navigation.

- New database fields or lesson JSON shape changes.
- Changing SRS, scoring, quota, premium, or question generation logic.

- Moving practice to a separate route.

## Requirements

1. The lesson top area must read as a compact song session header, not a generic document heading.
2. The video and lyrics must live inside a unified music-player stage with tokenized dark/light surfaces.
3. The lyrics panel must keep synchronized verse behavior, click-to-seek, dominated-verse stars, token popups, furigana, romaji, and translations.
4. Opening practice must be a gear-shift moment from the lesson page: a prominent in-page control must switch to the Practice tab and preserve Phase 13 force-mount behavior.
5. Exercise setup must read as a game lobby: tracks, progress rings, locks, and start actions are clear at a glance.
6. Exercise sessions must keep existing question types, feedback, retry, star-shine, level-pop, and confetti behavior, with reduced-motion fallbacks intact.
7. Mobile must keep the primary lesson and practice flows available without horizontal scroll at 390px width.
8. Desktop may add peripheral context, but no desktop-only primary action is allowed.
9. In-scope 14.3 chrome must use Phase 14 tokens instead of raw gray/red palette utilities, except for existing semantic grammar/JLPT/achievement colors.
10. `/songs/[slug]` must stay under the existing 50 KB gzipped route budget.
11. Dark and light themes must both be checked; axe score must remain at or above the Phase 14 gate.

## Acceptance Checks

- Playwright mobile parity for `/songs/again-yui` no horizontal scroll.
- Playwright visual or smoke coverage for the lesson stage and practice tab.
- Component or integration tests for new tab/gear-shift wiring.
- `npm run build`.
- Bundle check with the existing size-limit route budget.
