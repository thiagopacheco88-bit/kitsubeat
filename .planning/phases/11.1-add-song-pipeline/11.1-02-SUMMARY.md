# Phase 11.1 Plan 02: DB Transaction Wrap + Integration Test Summary

**One-liner:** Per-song songs+song_versions upserts wrapped in db.transaction() via script-local WebSocket pool, with Vitest integration test verifying rollback on FK/NOT NULL violation.

## What Was Built

### Task 1: Migrate 05-insert-db.ts to script-local WebSocket pool + db.transaction()

**Import block (as it appears in 05-insert-db.ts):**
```typescript
import { Pool } from "@neondatabase/serverless";
import { drizzle as drizzlePool } from "drizzle-orm/neon-serverless";
```

**Pool instantiation in main():**
```typescript
if (!process.env.DATABASE_URL) {
  throw new Error("DATABASE_URL is not set in .env.local — required for WebSocket pool.");
}
const pool = new Pool({ connectionString: process.env.DATABASE_URL });
const db = drizzlePool(pool);
```

**The pool is closed in a finally block:**
```typescript
try {
  for (const song of manifest) { ... }
} finally {
  await pool.end();
}
```

### Exported insertSongTransactional signature:
```typescript
export interface InsertSongInputs {
  lesson: Lesson;
  lyricsSource: string | null;
  syncedLrc: LyricsCacheEntry["synced_lrc"] | null;
  canonicalLyrics: CanonicalLyricsJson | null;
  whisperLyrics: WhisperLyricsJson | null;
  timingYoutubeId: string | null;
  timingData: TimingCacheEntry | null;
}

export async function insertSongTransactional(
  db: ReturnType<typeof drizzlePool>,
  song: { slug, title, artist, anime, season_info?, year_launched?, genre_tags?, mood_tags?, youtube_id? },
  inputs: InsertSongInputs,
): Promise<void>
```

The helper calls `db.transaction(async (tx) => { ... })` with all inserts via `tx.insert()` (not `db.insert()`).

### Task 2: Integration test

**Test results (verified against dev DB with TEST_DATABASE_URL set):**
- Test 1 — "forced failure mid-transaction rolls back BOTH songs and song_versions for failing slug": PASSED (1388ms)
- Test 2 — "mixed batch: passing slug writes both rows; failing slug writes none": PASSED (3516ms)

Both tests used `lesson: null as any` as the forcing function — the NOT NULL constraint on `song_versions.lesson` causes the transaction to abort after the `songs` row is inserted but before the `song_versions` row commits, proving the rollback works.

**Without TEST_DATABASE_URL:** suite skips cleanly, 2 tests skipped, exit 0.

**1. [Rule 2 - Missing critical functionality] Guard main() against running on module import**
- **Found during:** Task 2 — first test run showed `=== 05-insert-db: Upsert Songs into Neon Postgres ===` in vitest stdout, confirming main() ran against the dev DB when the test imported the module
- **Issue:** The script had `main().catch(...)` at module level with no guard. Test imports triggered a full 300-song upsert against dev DATABASE_URL (threat T-11.1.02-06 partially triggered)
