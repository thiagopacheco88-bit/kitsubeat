<objective>
Wrap each per-song `songs` + `song_versions` upsert pair in `scripts/seed/05-insert-db.ts` inside a single `db.transaction(async (tx) => { ... })` so partial failures (network blip, FK violation, schema drift) roll back the entire song, eliminating the half-written-row failure mode that ships a broken `/songs/<slug>` page. Add a Vitest integration test (`tests/integration/seed-05-insert-db-rollback.test.ts`) proving rollback semantics against a real test DB.

Purpose: The streak-killer second to "wrong audio" is "broken page". When `05-insert-db.ts` writes the `songs` row but fails before `song_versions`, the catalog lists a song the user can click — and the click crashes. This plan installs the transactional guard + the test that locks the invariant.

Output: A modified `05-insert-db.ts` using a script-local WebSocket-pooled Drizzle client (per CONTEXT D-04 + PATTERNS.md "Neon driver + transactions" — neon-http does NOT support callback transactions; the WebSocket fallback is the only viable path). Per-failure stderr in the locked format `[insert-fail] slug=<slug> error=<msg>`. End-of-run summary `N songs failed: foo, bar`. Non-zero exit ONLY if every song failed (matches SPEC AC #9). A Vitest integration test that simulates a forced FK violation, asserts zero rows for the failing slug, and asserts mixed-batch isolation.

**Critical scope guardrails:**
- The driver swap is **script-local** — do NOT extend `src/lib/db/index.ts`. The app's `getDb()` proxy stays HTTP.
- The test file lives at `tests/integration/seed-05-insert-db-rollback.test.ts` (NOT `scripts/seed/__tests__/...`) — `vitest.config.ts` only globs `tests/integration/**` and `tests/unit/**` (PATTERNS.md "No Analog Found" entry).
- `vocabulary_items` writes are NOT wrapped in this transaction (out of scope per SPEC).
</objective>
