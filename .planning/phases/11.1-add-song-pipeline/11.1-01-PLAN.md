<objective>
Build the cross-song youtube_id uniqueness audit (`scripts/seed/audit-yt-ids.ts`) and wire it as the final step of both `run-pending-batch.sh` and `overnight-orchestrator.sh` so any batch that introduces a cross-slug duplicate halts loudly with `exit 1`.

Purpose: A streak-killer is the worst outcome. The TV backfill once had 5 different slugs sharing `gX9WX_NP5Ug` — a user clicking "song A" got "song B's" audio. This plan installs the automated guard that catches the next occurrence at batch end, before the catalog ships broken.

Output: A read-only audit script that writes `data/yt-id-audit.csv` on every run, prints `OK: N rows checked, 0 duplicates` on a clean run (exit 0), and prints a stderr summary + exits 1 on any cross-slug duplicate group. Both batch shells call it as the final step and propagate its exit code.

Note: `.gitignore` is intentionally NOT modified — `data/` (line 55) already ignores `data/yt-id-audit.csv`. Adding an explicit entry is redundant; CONTEXT D-02 says "gitignored", which is satisfied.
</objective>

    Block 1 — DB query (read-only, innerJoin):

    ```typescript
    const db = getDb();
    const rows = await db

        youtube_id: songVersions.youtube_id,
        slug: songs.slug,
        version_type: songVersions.version_type,
      })

    ```

    Block 2 — Group by youtube_id, flag CROSS-SLUG ONLY (D-01 — set.size > 1, NOT array.length > 1):
    ```typescript
    const byYtId = new Map<string, { slugs: Set<string>; versionTypes: string[] }>();
    for (const r of rows) {
      if (!r.youtube_id) continue;
      const g = byYtId.get(r.youtube_id) ?? { slugs: new Set(), versionTypes: [] };
      g.slugs.add(r.slug);
      g.versionTypes.push(`${r.slug}:${r.version_type}`);
      byYtId.set(r.youtube_id, g);
    }
    const dupes = [...byYtId.entries()]
      .filter(([, g]) => g.slugs.size > 1)
      .map(([youtube_id, g]) => ({
        youtube_id,
        count: g.slugs.size,
        slugs: [...g.slugs].sort(),
        version_types: g.versionTypes.sort(),
      }));
    ```

    Block 3 — Write CSV (header line + pipe-separated multi-value cells per D-02; column order locked: `youtube_id,count,slugs,version_types`):
    ```typescript
    const csvLines: string[] = ["youtube_id,count,slugs,version_types"];
    for (const d of dupes) {
      csvLines.push(
        [
          d.youtube_id,
          String(d.count),
          d.slugs.join("|"),
          d.version_types.join("|"),
        ].join(","),
      );
    }
    writeFileSync(resolve(process.cwd(), "data/yt-id-audit.csv"), csvLines.join("\n"), "utf-8");
    ```

    Block 4 — Exit-code + summary (per CONTEXT D-03 + SPEC AC #2 + AC #3):
    ```typescript
    if (dupes.length > 0) {
      console.error(`[audit-yt-ids] FAIL: ${dupes.length} duplicate youtube_id group(s)`);
      for (const d of dupes) {
        console.error(`  ${d.youtube_id} → ${d.slugs.join(", ")} (${d.count} slugs)`);
      }
      console.error(`See data/yt-id-audit.csv`);
      process.exit(1);
    }
    console.log(`OK: ${rows.length} rows checked, 0 duplicates`);
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

| T-11.1.01-03 | Denial of Service | audit query against song_versions | accept | Single SELECT against a table currently ~600 rows (273 songs × ~2 versions). innerJoin + isNotNull filter is O(N) in row count. No risk at current scale. Revisit if catalog exceeds ~50k rows. |
| T-11.1.01-04 | Repudiation | audit miss (dupe slips through) | mitigate | Audit is wired into BOTH batch shells with `|| exit 1`. A single missed wiring would defeat the guard — covered by acceptance criteria grep on both shells. Manual invocation also supported as fallback. |
