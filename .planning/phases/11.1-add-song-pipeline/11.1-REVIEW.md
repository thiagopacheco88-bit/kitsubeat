## Summary

Phase 11.1 delivers three correctness/quality guards on the add-song pipeline: a cross-slug `youtube_id` audit, a transactional `05-insert-db.ts` (with integration test), and a one-page operator README. All plan locks (D-01..D-09 stderr/CSV/anchor formats, `set.size > 1` cross-slug filter, `|| exit 1` propagation, `pool.end()` cleanup, `describeIfTestDb` skip-guard) are honoured and visible in the diff.

Overall the code is solid and the SPEC acceptance criteria are met. No Critical issues. The Warnings cluster around two themes: (1) shell-orchestrator robustness — `overnight-orchestrator.sh` lacks `set -u`, the audit step bypasses the `run_step` wrapper so its rc is never recorded in the summary JSON, and `run-pending-batch.sh` swallows step exits behind `|| log` while still running under `set -e`; (2) `audit-yt-ids.ts` writes CSV without escaping commas/newlines that could appear in `version_type` strings — currently safe because `version_type ∈ {"full","tv"}` and slugs are kebab-case, but the format will silently corrupt if a future slug or version contains a `,`. None of these block the merge; all are tractable follow-ups.

## Warnings

### WR-01: `overnight-orchestrator.sh` missing `set -u` makes typo'd vars silently expand to empty

**File:** `scripts/seed/overnight-orchestrator.sh:24`
**Issue:** The shell uses `set -o pipefail` only — no `set -e` and no `set -u`. The companion `run-pending-batch.sh` uses `set -euo pipefail`. The intentional design here is "never fail the chain" (run_step swallows exits into `step_status`), so omitting `-e` is justified. But omitting `-u` means any future typo like `"${stepstatus[$step]}"` (instead of `step_status`) silently expands to empty and produces malformed JSON in the summary heredoc — the bug only surfaces when an operator reads `data/overnight-summary.json` the next morning. `set -u` is independent of `set -e` and would catch this without changing chain-tolerance.
**Fix:**
```bash
# Line 24 — add -u (keeps chain-tolerance, gains undefined-var detection)
set -uo pipefail
```

### WR-02: Audit step in `overnight-orchestrator.sh` bypasses `run_step` wrapper, so its rc is missing from `step_status` and the summary JSON

**File:** `scripts/seed/overnight-orchestrator.sh:94-95`
**Issue:** Steps 1–7 use `run_step "name" <cmd>` which records the rc into `step_status[$name]` and never aborts the chain. The newly added Step 8 audit invokes `npx tsx ... || exit 1` directly, bypassing the wrapper. Two consequences: (a) the `step_status` JSON in `data/overnight-summary.json` will never include the audit's exit code — the operator cannot tell from the summary whether the audit ran clean or was the reason the chain ended; (b) on a dupe, the script `exit 1` jumps past the entire summary heredoc (lines 98-128), so the operator wakes to a chain that ran 7+ steps but produced NO summary file. The summary file is the orchestrator's primary deliverable. The plan (11.1-01-PLAN.md task 2 action note) explicitly chose `|| exit 1` over `run_step` "because the run_step helper does not propagate exit codes" — that's the correct decision for `run-pending-batch.sh` (which has no orchestrator summary to lose), but for `overnight-orchestrator.sh` the trade-off is reversed: silent overnight exit costs more than late detection.
**Fix:** Run the audit through `run_step` so its rc lands in the summary, then check the recorded rc AFTER the heredoc emits and exit 1 if non-zero. This preserves both the locked SPEC AC ("propagates non-zero exit on dupe") and the orchestrator's summary contract:
```bash
# Replace lines 94-95 with:
run_step "audit-yt-ids" \
  npx tsx --tsconfig tsconfig.scripts.json scripts/seed/audit-yt-ids.ts

# ... existing summary heredoc (lines 97-128) runs unchanged ...

# At the very end (after the final `log` lines), propagate audit failure:
if [ "${step_status[audit-yt-ids]:-1}" -ne 0 ]; then
  log "FAIL: cross-song youtube_id audit detected duplicates"
  exit 1
fi
```

### WR-03: `run-pending-batch.sh` runs under `set -e` but uses `|| log "..."` to swallow step failures — interaction is fragile

**File:** `scripts/seed/run-pending-batch.sh:18,66,70-71,75-76`
**Issue:** Line 18 sets `set -euo pipefail`. Steps 2/3/4 then suffix `|| log "..."` to "complete with non-zero exit" without halting. This works (the `||` rescues `set -e`), but the pattern is brittle: any future maintainer who adds an unguarded `npx tsx ...` call inside a step will halt the chain unintentionally, AND the log line is the only signal that a step failed — there is no recorded `step_status` like the orchestrator has. If 04b backfill silently exits 1 because the venv broke, the chain still writes the status JSON and exits 0 — operator sees "done" with no transcribed-count regression unless they read the log. Either the chain wants strict-fail (drop `|| log`) or it wants accumulated status (mirror `overnight-orchestrator.sh`'s `run_step`). The current half-and-half makes failures invisible.
**Fix:** Pick one model. Recommended: extend the orchestrator's `run_step`/`step_status` pattern into this shell so the status JSON gains a `steps` field documenting per-step rc. Lower-effort alternative: change `|| log "..."` to `|| { log "..."; failed_steps+=("step-name"); }` and surface `failed_steps[@]` in the JSON. At minimum, document the deliberate choice in the file header so a maintainer knows the swallowing is intentional.

### WR-04: `audit-yt-ids.ts` CSV writer does not escape commas / quotes / newlines in field values

**File:** `scripts/seed/audit-yt-ids.ts:53-63`
**Issue:** The CSV is built by `[...].join(",")` with no quoting or escaping. Today this is safe because `youtube_id` is `[A-Za-z0-9_-]{11}`, `count` is a number, `slugs` are kebab-case (`a-z0-9-`), and `version_type ∈ {"full","tv"}`. But the column is typed `text` in the schema (no CHECK constraint visible) and the audit's whole purpose is catching anomalous catalog data. If a future slug or version_type string ever contains a comma, embedded `"`, or newline (e.g. import bug, test fixture, manual SQL edit), the CSV row will silently shift columns and the next consumer (Excel, the human reading it) will misread the dupe — which defeats the audit. The cost to harden is ~5 lines.
**Fix:**
```typescript
function csvEscape(v: string): string {
  // RFC 4180: wrap in quotes if value contains comma, quote, CR, or LF; double internal quotes.
  return /[",\r\n]/.test(v) ? `"${v.replace(/"/g, '""')}"` : v;
}
// Then in the push:
csvLines.push(
  [
    csvEscape(d.youtube_id),
    String(d.count),
    csvEscape(d.slugs.join("|")),
    csvEscape(d.version_types.join("|")),
  ].join(","),
);
```

### WR-05: `clearTestSlugs` runs in `beforeEach` and `afterAll` against the same pool that's recreated in `beforeEach` — `afterAll` may operate on a stale pool

**File:** `tests/integration/seed-05-insert-db-rollback.test.ts:90-99`
**Issue:** `beforeEach` reassigns the outer `pool` and `db` references each test (`({ pool, db } = buildTestPool())`), but never closes the previous pool. After two tests the test process holds two open Pools; only the most recent is closed by `afterAll`. The first pool's connection is leaked and (worse) the `afterAll` cleanup runs against the same pool that the LAST test's `beforeEach` created — fine if the last test passed, but if the last test's `beforeEach` threw before assigning, `pool`/`db` could be undefined or stale. Practical impact today is minimal (vitest reuses the process and Neon serverless tolerates dangling connections), but this pattern leaks file descriptors in CI and the pool re-creation per-test is unnecessary anyway — `buildTestPool` is identical every call.
**Fix:** Build the pool once in `beforeAll`, reuse across tests, end once in `afterAll`. `beforeEach` then only does cleanup:
```typescript
let pool: Pool;
let db: TestDb;

beforeAll(() => {
  ({ pool, db } = buildTestPool());
});

beforeEach(async () => {
  await clearTestSlugs(db);
});

afterAll(async () => {
  if (db) await clearTestSlugs(db);
  if (pool) await pool.end();
});
```
This also makes the `if (db)` / `if (pool)` guards in `afterAll` redundant in the happy path, which is good — they currently mask "test never started" failure modes.

### IN-02: `count_pending_done` shells out to Node for trivial JSON parsing — slow and brittle

**File:** `scripts/seed/run-pending-batch.sh:28-35,37`
**Issue:** Each progress check spawns `node -e "console.log(require('./$PENDING_MANIFEST').map(s=>s.slug).join('\n'))"` (~150 ms cold-start each iteration of the 5-min poll loop). It works, but `jq -r '.[].slug'` would be faster, more readable, and avoid embedding shell-interpolated paths into a Node `require` call (the `$PENDING_MANIFEST` value is hardcoded so this is safe today, but `require` resolving a shell-interpolated path is the kind of thing that surprises future maintainers).
**Fix:**
```bash
count_pending_done() {
  local count=0
  while IFS= read -r slug; do
    [ -z "$slug" ] && continue
    [ -f "$TIMING_DIR/$slug.json" ] && count=$((count + 1))
  done < <(jq -r '.[].slug' "$PENDING_MANIFEST")
  echo "$count"
}
total=$(jq 'length' "$PENDING_MANIFEST")
```
If `jq` is not guaranteed in the operator's WSL/Git-Bash, leave the Node form but switch to `node -e "const m = require('./$PENDING_MANIFEST'); ..."` so the path is bound to a local variable rather than interpolated mid-expression.

### IN-03: `ls | wc -l` for file counts is fragile under filenames with spaces and inflates by `total` lines on some shells

**File:** `scripts/seed/run-pending-batch.sh:81-84`, `scripts/seed/overnight-orchestrator.sh:98-103`
**Issue:** `ls public/audio/*.mp3 2>/dev/null | wc -l` works for the current naming convention (kebab-case slugs, no spaces) but is a known shell anti-pattern: `wc -l` counts newlines, not files, and busybox `ls -l` adds a `total N` line. Counts also break if the glob expands to zero matches (then `ls` lists the literal pattern, which `2>/dev/null` masks but `wc` still counts as 1). The codebase's typical seed-script pattern uses Node `readdirSync` with a filter; bash equivalents below are robust.
**Fix:**
```bash
# Both shells, in the count block:
audio_count=$(find public/audio -maxdepth 1 -name '*.mp3' -type f 2>/dev/null | wc -l)
# or the array idiom:
shopt -s nullglob
files=(public/audio/*.mp3); audio_count=${#files[@]}
shopt -u nullglob
```

### IN-04: `slugArg` parsing accepts only the first `--slug=` occurrence — silent UX trap if operator passes two

**File:** `scripts/seed/05-insert-db.ts:307-310`
**Issue:** `process.argv.find((a) => a.startsWith("--slug="))` returns the first match. An operator running `npx tsx ... --slug=foo --slug=bar` gets `foo` only, with no warning. The current behaviour is consistent with most one-shot CLIs, but the `,`-separated form (`--slug=foo,bar`) handles the multi-slug case and the duplicate-flag form is almost certainly an unintended copy-paste. Worth a one-line warning.
**Fix:**
```typescript
const slugArgs = process.argv.filter((a) => a.startsWith("--slug="));
if (slugArgs.length > 1) {
  console.warn(`[warn] multiple --slug= flags passed; using only the first. Use comma-separated form: --slug=a,b`);
}
const slugArg = slugArgs[0];
```

### IN-06: Test fixture loads `data/lessons-cache/again-yui.json` with no fallback — test breaks if seeded slug is renamed or pruned

**File:** `tests/integration/seed-05-insert-db-rollback.test.ts:175-178`
**Issue:** Test 2 reads `data/lessons-cache/again-yui.json` directly with no `existsSync` check or fallback. Plan 11.1-02 explicitly notes this risk ("If `again-yui.json` does not exist OR LessonSchema rejects it: fall back to constructing the minimal lesson inline") but the implementation skipped the fallback. Cost of the fallback is ~10 lines; benefit is the test surviving any future cache-cache reorganisation or the cleanup of `again-yui` if it's ever re-classified.
**Fix:**
```typescript
const FALLBACK_SLUG_CANDIDATES = ["again-yui", "sign-flow", "fly-higher"];
let minimalLesson: unknown = null;
for (const slug of FALLBACK_SLUG_CANDIDATES) {
  const p = `data/lessons-cache/${slug}.json`;
  if (existsSync(p)) {
    minimalLesson = JSON.parse(readFileSync(p, "utf-8"));
    break;
  }
}
if (!minimalLesson) {
  throw new Error(
    `No seeded lesson cache found in ${FALLBACK_SLUG_CANDIDATES.join("/")}; ` +
    `cannot run mixed-batch test. Re-seed lessons or update FALLBACK_SLUG_CANDIDATES.`,
  );
}
```
