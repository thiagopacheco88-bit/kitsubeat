## What Was Built

### Task 1 — Double-gated bypass in `src/lib/user-prefs.ts`

Added a triple-gated bypass branch BEFORE the Clerk `auth()` call in `getCurrentUserId()`:

- **Gate 1:** `process.env.NODE_ENV !== "production"` — production deploys always set `NODE_ENV=production` via Next.js runtime, providing the strongest barrier
- **Gate 2:** `process.env.KB_E2E_AUTH_BYPASS_ENABLED === "true"` — explicit per-CI-run opt-in; never set in any deploy pipeline
- **Gate 3:** `process.env.KB_E2E_AUTH_BYPASS` is non-empty — the actual bypass user id

Every bypass invocation emits `console.warn("[e2e] auth bypass active — DO NOT enable in production")` so any misconfigured build floods logs immediately.

`.env.example` verified clean — bypass vars intentionally NOT documented (explicit per-CI-run only, per threat model).

### Task 2 — Playwright authenticated fixture + smoke spec

**`tests/support/auth-fixtures.ts`:**
- Exports `authenticatedTest` (extends Playwright `test` with `authedUserId` fixture)
- Defensive guard: checks `PLAYWRIGHT_AUTH=true` and `KB_E2E_AUTH_BYPASS` in the Playwright runner process
- Note: `KB_E2E_AUTH_BYPASS_ENABLED` is injected into the Next.js SERVER process by `playwright.config.ts` — it is not available in the Playwright runner process itself
- Cleanup: calls `resetTestProgress(bypassId)` guarded on `TEST_DATABASE_URL` — no-ops in environments without test DB

**`tests/e2e/_smoke-auth-bypass.spec.ts`:**
- Test 1: Verifies `authedUserId` fixture returns the bypass id value
- Test 2: Navigates `/`, checks for `[data-testid="global-lantern-streak"]` with graceful fallback for pre-14.2-11 state (logs vacuous pass when testid not yet present)

**`playwright.config.ts`:**
- Added conditional injection in `webServer.env` when `PLAYWRIGHT_AUTH=true`
- Injects both `KB_E2E_AUTH_BYPASS_ENABLED=true` and `KB_E2E_AUTH_BYPASS` into the Next.js dev server process
- Uses `process.env.KB_E2E_AUTH_BYPASS ?? "test-user-1"` as default

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed auth-fixtures defensive guard checking wrong env var**

- **Found during:** Task 2 execution (smoke spec run)
- **Issue:** Plan specified the fixture should check `KB_E2E_AUTH_BYPASS_ENABLED` in the Playwright process. However, `KB_E2E_AUTH_BYPASS_ENABLED` is propagated to the Next.js **server** process via `playwright.config.ts webServer.env`, NOT to the Playwright runner process. Checking it in the runner always evaluates to `undefined` (falsy), causing the defensive guard to fire even when `PLAYWRIGHT_AUTH=true KB_E2E_AUTH_BYPASS=test-user-1` are set.
- **Fix:** Revised guard to check only `PLAYWRIGHT_AUTH` and `KB_E2E_AUTH_BYPASS` (Playwright-process vars). Updated error message to clarify where `KB_E2E_AUTH_BYPASS_ENABLED` lives. The server-side behavior is unchanged — `getCurrentUserId` still checks all three gates.
- **Files modified:** `tests/support/auth-fixtures.ts`
- **Commit:** `a1cb970`

**2. [Rule 2 - Missing critical functionality] Guard `resetTestProgress` on `TEST_DATABASE_URL`**

- **Found during:** Task 2 execution (smoke spec with env)
- **Issue:** The cleanup phase (`resetTestProgress`) unconditionally called `getTestDb()` which throws if `TEST_DATABASE_URL` is not set. The smoke spec passes without a test DB (it doesn't do DB writes), but the cleanup would fail.
- **Fix:** Added `if (process.env.TEST_DATABASE_URL)` guard around `resetTestProgress` call. Tests that actually write progress data still require `TEST_DATABASE_URL` to be set (the guard does not affect those — they will fail earlier via `getTestDb()` throw).
- **Files modified:** `tests/support/auth-fixtures.ts`
- **Commit:** `a1cb970`
