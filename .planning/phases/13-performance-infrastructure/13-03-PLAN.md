<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub PR → pr-checks workflow | Untrusted PR code runs in CI. The `permissions: pull-requests: write` adds the ability to post comments under the workflow's GITHUB_TOKEN identity |
| size-limit-action → andresz1/size-limit-action@v1 | Third-party action runs with workflow permissions; pinned to v1 (not main) to lock against tag drift |
| Workflow file → secrets.GITHUB_TOKEN | Default GITHUB_TOKEN; scope already constrained by `permissions:` block |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03-01 | Elevation of Privilege | `permissions: pull-requests: write` lets a malicious PR comment under the bot identity | mitigate | The `permissions:` block scopes the GITHUB_TOKEN to ONLY `pull-requests: write` — no `contents: write`, no `actions: write`, no `id-token: write`. Worst case: a malicious PR's workflow run posts an extra comment. Cannot push code, cannot release, cannot impersonate users. Standard GitHub Actions hardening pattern — see https://docs.github.com/en/actions/security-guides. |
| T-13-03-02 | Tampering | Compromised andresz1/size-limit-action upstream injects malicious code into PR runs | mitigate | Pin to `@v1` (major version tag) — not `@main` or unpinned. Periodically audit the action repo. Risk accepted for v1 of CI; if the project becomes a higher-value target, re-evaluate vendoring or SHA-pinning. Logged for Phase 16 IR runbook. |
| T-13-03-03 | Information Disclosure | Bundle analyzer report (`.next/analyze/client.html`) committed/leaked exposes internal module names | accept | `npm run analyze` is local-only — no CI step writes `.next/analyze/*` to the workflow artifacts. `.next/` is already in .gitignore. Worst case: a developer accidentally commits the report; pre-commit hook + .gitignore suffices. |
| T-13-03-04 | Denial of Service | A PR with intentionally pathological bundle (e.g., 500+ chunks) blows out the CI build time | accept | Existing job `timeout-minutes: 10` already caps runtime. size-limit-action runs after build; if build exceeds the budget, it fails at build time (Next.js timeout) before reaching size check. |
| T-13-03-05 | Information Disclosure | size-limit-action PR comment leaks chunk filenames containing implementation details | accept | Chunk filenames are hashed (e.g., `page-abc123.js`); they reveal nothing beyond what `next build` already prints to public CI logs. The /songs/[slug] route is publicly accessible — no auth-gated content in the chunks. |
</threat_model>
