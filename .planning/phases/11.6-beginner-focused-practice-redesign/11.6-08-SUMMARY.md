## New Files

### VerseStarIcon.tsx (33 lines)
5-point amber-400 filled SVG star, inline-flex span wrapper with `data-testid="verse-dominated-star"` and `aria-label="Verse dominated"`. Mirrors BonusBadgeIcon pattern. Used in VerseBlock (lyrics star) and SongContent header counter.

### VerseDominatedAnimation.tsx (87 lines)
"use client" component subscribing to `useExerciseSession.versesDominatedNow`. On non-empty transition:
1. Fires canvas-confetti burst (`disableForReducedMotion: true`) from element center
2. Shows "Verse dominated!" text overlay for 1.2s (data-testid="verse-dominated-overlay", role="status")
3. Calls `clearVersesDominatedNow()` to reset store slice

`lastFiredRef` stable-signature guard (sorted join of verse numbers) prevents double-trigger on same input.

### tests/e2e/verse-domination-ui.spec.ts (4 tests, HAS_TEST_DB-gated)
- Song page header shows X/Y verses counter
- Lyrics view shows star icon next to dominated verses
- Song catalog shows '% dominated' line on SongCard
- No star rendered for non-dominated verses

### tests/e2e/verse-dominated-animation.spec.ts (4 tests, HAS_TEST_DB-gated)
- Animation overlay text appears when verse tips to dominated
- Animation does NOT re-fire on re-answering already-dominated verse
- Animation does NOT re-fire on page reload (versesDominatedNow not persisted)
- prefers-reduced-motion: text overlay still appears, confetti canvas absent (reducedMotion: 'reduce' context option)

## queries.ts Additions

### getDominatedVerses(userId, songVersionId): Promise<number[]>
Queries `user_verse_domination` filtered by `(user_id, song_version_id)`. Returns array of dominated verse numbers. Used at SSR boundary in page.tsx.

### getAllSongs extended: verses_dominated_pct
Correlated subquery counting dominated verses / total distinct verse numbers from lesson JSONB for tv-preferred version. Returns null for unauthenticated callers. SongCard parses via `parseFloat()`.

## SSR userId Thread (Critical Success Requirement)

`page.tsx` calls `getCurrentUserId()` once to get `SONG_PAGE_USER_ID` (Clerk `auth().userId` or `PLACEHOLDER_USER_ID`). This resolved value is used for:
- `progressRows` query (existing, unchanged)
- `getDominatedVerses(SONG_PAGE_USER_ID, primaryVersion.id)` (new)

Never uses a hardcoded placeholder. All domination data is scoped to the correct authenticated user.

## Idempotency Proof

- Server layer (Plan 11.6-05): `INSERT ... ON CONFLICT (user_id, song_version_id, verse_number) DO NOTHING RETURNING verse_number`
- On revisit: server returns `versesDominatedNow: []` → `VerseDominatedAnimation.useEffect` gate (`if (versesDominatedNow.length === 0) return`) fires nothing
- On page reload: `versesDominatedNow` is excluded from zustand `partialize` (Plan 11.6-05) → always initializes to `[]` → no stale animation on fresh load
- Client-side: `lastFiredRef` prevents double-trigger on same React render cycle
