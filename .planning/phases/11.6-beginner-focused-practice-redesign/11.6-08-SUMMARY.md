## queries.ts Additions

### `getDominatedVerses(userId, songVersionId): Promise<number[]>`
Queries `user_verse_domination` filtered by `(user_id, song_version_id)`, returns array of dominated verse numbers. SSR-only — called once per song version at `page.tsx`.

### `getAllSongs.verses_dominated_pct` (correlated subquery)

```sql
SELECT CASE
  WHEN COALESCE(verse_total.cnt, 0) = 0 THEN NULL
  ELSE ROUND((COALESCE(dom.cnt, 0)::numeric / verse_total.cnt::numeric) * 100, 0)::text
END
FROM (
  SELECT jsonb_array_length(sv.lesson -> 'verses') AS cnt, sv.id AS sv_id
  FROM song_versions sv
  WHERE sv.song_id = songs.id AND sv.lesson IS NOT NULL
  ORDER BY CASE sv.version_type WHEN 'tv' THEN 0 ELSE 1 END
  LIMIT 1
) AS verse_total
LEFT JOIN (
  SELECT COUNT(*)::int AS cnt, uvd.song_version_id
  FROM user_verse_domination uvd
  WHERE uvd.user_id = ${userIdParam}
  GROUP BY uvd.song_version_id
) AS dom ON dom.song_version_id = verse_total.sv_id
```

Returns numeric-text or NULL (Pitfall 6 — neon-http boxes numeric as string). SongCard parses via `parseFloat(... as unknown as string)` then `Math.round`.

## Idempotency Proof (SPEC-REQ-15)

Three independent layers:

1. **Server-side (Plan 11.6-05):** `INSERT INTO user_verse_domination ... ON CONFLICT (user_id, song_version_id, verse_number) DO NOTHING RETURNING verse_number`. On revisit answer for an already-dominated verse, RETURNING yields zero rows → `versesDominatedNow = []`.
2. **zustand persist partialize (Plan 11.6-05):** `versesDominatedNow` excluded from the persist allowlist; reload always rehydrates with `[]`.
3. **Client-side `lastFiredRef`:** sorted+joined signature guard catches any in-render double-set race.

The static gold star (`<VerseStarIcon />` in VerseBlock, sourced from SSR `getDominatedVerses`) is the **persistent UI**; the animation is the **transient celebration** — separate concerns.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing critical functionality] `setVersesDominatedNow` was only wired in `ExerciseSession.tsx::handleVocabTypedAnswered` (Plan 11.6-05); three additional `recordVocabAnswer` call sites silently dropped the field.**

- **Found during:** Task 2 (FeedbackPanel wiring step).
- **Issue:** `recordVocabAnswer` is called from FOUR distinct sites in the codebase. The plan said "locate the recordVocabAnswer call site" implying one. The vocab_typed path (already wired) only fires for Kanji track + Advanced Drills. Star 1 (vocab MCQ via QuestionCard), Star 2 (fill_lyric via QuestionCard), Star 3 (Listening Drill via ListeningDrillCard), and Bonus (grammar conjugation via ConjugationCard) all call `recordVocabAnswer` but were ignoring `result.versesDominatedNow`.
- **Why critical:** SPEC-REQ-15 says "the animation fires once per (user, verse) on the tipping answer" — without these three additional setters, the animation would never fire on the most common Star 1/2/3 paths, breaking the spec.
- **Fix:** Added `setVersesDominatedNow` selector + `if (result.versesDominatedNow.length > 0) setVersesDominatedNow(result.versesDominatedNow);` after each `recordVocabAnswer` response.
- **Files modified:** `QuestionCard.tsx`, `ListeningDrillCard.tsx`, `ConjugationCard.tsx`.
- **Commit:** `e80b2b3`.

**2. [Rule 3 — Blocking issue] `getAllSongs.verses_dominated_pct` denominator SQL referenced columns that do not exist in the schema.**

- **Found during:** Task 3 (queries.ts extension).
- **Issue:** Plan suggested `SELECT count(*) FROM (SELECT DISTINCT verse_number FROM song_vocab WHERE song_version_id = sv.id UNION SELECT DISTINCT verse_number FROM song_version_grammar_rules WHERE song_version_id = sv.id) verses`. Neither `song_vocab.verse_number` nor `song_version_grammar_rules.verse_number` exists — `song_version_grammar_rules` is a song-level join table (no per-verse rows), and `song_vocab` is not a table in this codebase. The plan's SQL would not have compiled.
- **Why critical:** Without a working denominator the catalog `% dominated` line cannot ship — hard SPEC-REQ-14 acceptance criterion.
- **Fix:** Switched the denominator to `jsonb_array_length(sv.lesson -> 'verses')` against the tv-preferred song_version. `lesson.verses[]` is the canonical source of truth for verse count (used by SSR for verse rendering, and what Plan 11.6-05's recordVocabAnswer compares against when deciding tipping).
- **Files modified:** `src/lib/db/queries.ts`.
- **Commit:** `c13ab7a`.
