#### getVocabularyDashboard SQL diff

**Before (Plan 11-04, single-state):**
```sql
SELECT m.vocab_item_id, vi.*, m.state, m.due, ...
FROM user_vocab_mastery m
JOIN vocabulary_items vi ON vi.id = m.vocab_item_id
WHERE m.user_id = ? AND m.state IN (1, 2, 3) [tier clause]
ORDER BY m.state DESC, m.last_review DESC NULLS LAST
```

**After (Plan 11-11, GROUP BY card_kind aggregation):**
```sql
SELECT vi.id, vi.*,
  MAX(CASE WHEN m.card_kind = 'romaji_meaning' THEN m.state END) AS romaji_state,
  MAX(CASE WHEN m.card_kind = 'romaji_meaning' THEN m.due::text END) AS romaji_due,
  MAX(CASE WHEN m.card_kind = 'kanji_kana' THEN m.state END) AS kanji_state,
  MAX(CASE WHEN m.card_kind = 'kanji_kana' THEN m.due::text END) AS kanji_due,
  ...
FROM vocabulary_items vi
JOIN user_vocab_mastery m ON m.vocab_item_id = vi.id AND m.user_id = ?
WHERE vi.id IN (
  SELECT DISTINCT vocab_item_id FROM user_vocab_mastery
  WHERE user_id = ? AND card_kind = 'romaji_meaning' AND state IN (1, 2, 3)
)
GROUP BY vi.id, vi.*
HAVING MAX(CASE WHEN m.card_kind = 'romaji_meaning' THEN m.state END) = [tier]
ORDER BY MAX(CASE WHEN m.card_kind = 'romaji_meaning' THEN m.due END) [dir] NULLS LAST
```

Key: tier filter uses HAVING on romaji_meaning state (foundational track per SPEC R18).
Key: ORDER BY switches from `m.state` to `romaji_due` per plan requirement.

#### VocabularyList dual MasteryBadge structure

```tsx
<MasteryBadge state={row.romaji_state} label="romaji" testId={`mastery-romaji-${row.vocab_item_id}`} />
{showKanjiIndicator && (
  <MasteryBadge state={row.kanji_state} label="kanji" testId={`mastery-kanji-${row.vocab_item_id}`} />
)}
```

Where `showKanjiIndicator = hasKanji(row.dictionary_form)`.

`kanji_state=null` renders "—" with gray styling, NOT "New" — correctly represents "no kanji_kana card started yet".
