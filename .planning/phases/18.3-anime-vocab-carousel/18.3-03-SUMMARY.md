# Phase 18.3 Plan 03: Anime Vocabulary Carousel DB Query Functions Summary

**One-liner:** Drizzle LEFT JOIN queries for anime catalog index and per-slug vocab with user mastery states.

## What Was Built

Two exported async functions added to `src/lib/db/queries.ts`:

- **`getAnimeCatalog()`** — Returns `AnimeCatalogEntry[]` for all 6 anime slugs. Uses a LEFT JOIN with a CASE expression to map `anime_slug` → `animeMetadata.anime` (raw title PK). Word count via Drizzle `count()`, top JLPT level computed with a separate `selectDistinct` per row.

- **`getAnimeVocabBySlug(slug, userId)`** — Returns `{ animeMeta, words: AnimeVocabItem[] }`. Fetches vocabulary words via INNER JOIN of `animeVocabCatalog` → `vocabularyItems`, ordered by `display_order`. For authenticated users, fetches mastery states from `userVocabMastery` with `card_kind = "romaji_meaning"` using `inArray()`. Unknown slugs return `{ animeMeta: null, words: [] }`.

Two exported interfaces:
- **`AnimeVocabItem`** — shape of each word in the carousel
- **`AnimeCatalogEntry`** — shape of each row on the anime index page

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed TypeScript type predicate for jlpt_level filter**
- **Found during:** Task 1 GREEN implementation
- **Issue:** Drizzle infers `jlpt_level` as `"N5" | "N4" | "N3" | "N2" | "N1" | null` (enum type), not `string`. The plan's code used `l is string` predicate and `JLPT_ORDER.includes(l)` which TypeScript rejected.
- **Fix:** Changed `JLPT_ORDER` to `as const`, derived `JlptLevel` type from it, cast `JLPT_ORDER` to `readonly string[]` for the `.includes()` call.
- **Files modified:** `src/lib/db/queries.ts`
- **Commit:** `a005452`

**2. [Rule 2 - Improvement] Used inArray() instead of raw SQL ANY()**
- **Found during:** Task 1 — plan noted "prefer inArray() if already imported"
- **Fix:** Used `inArray(userVocabMastery.vocab_item_id, vocabIds)` directly — `inArray` was already imported.
