# Phase 18.3: Anime Vocabulary Carousel — Context

**Gathered:** 2026-05-23
**Status:** Ready for planning
**Source:** Design session — Instagram traction pivot

<domain>
## Phase Boundary

A new `/anime` section of KitsuBeat where users browse comprehensive, thematic vocabulary lists organized by anime series. Each anime page shows 100–200 curated words (world-building, power systems, factions, themes) sorted by JLPT difficulty. Users can study words and track mastery via the existing FSRS system.

This is **independent from songs**: vocabulary is thematic/worldbuilding vocab from the show itself, not song lyrics. A word may appear in both — that's intentional, not a duplicate.

The carousel is the intermediate layer in the user funnel:
```
Instagram quiz (5 words, viral) → Anime Vocab Carousel (100+ words, deep) → KitsuBeat lesson (FSRS, songs)
```

</domain>

<decisions>
## Implementation Decisions

### Data Source
- 6 pre-generated JSON files at `.planning/anime-vocab/[slug].json`
- One Piece: 109 words | Naruto: 128 | Bleach: 133 | FMA: 126 | AoT: 132 | SAO: 132 = **760 total**
- Each word has: `surface` (kanji), `reading` (hiragana), `romaji`, `meanings` (en/pt-BR/es), `jlpt_level`, `category`, `context` (anime-hook sentence)
- These files are the source of truth — do not modify them during implementation

### New DB Table: `anime_vocab_catalog`
- Join table between anime slug and `vocabulary_items`
- Columns: `id` (uuid pk), `anime_slug` (text not null), `vocab_item_id` (uuid fk → vocabulary_items), `category` (text), `display_order` (int), `context_note` (text), `created_at`
- UNIQUE constraint on `(anime_slug, vocab_item_id)`
- INDEX on `(anime_slug, display_order)`
- **Do NOT modify `vocabulary_items` table** — anime words slot in exactly like song words

### Seed Script: `scripts/seed/20-seed-anime-vocab.ts`
- Reads all `.planning/anime-vocab/*.json` files
- Upserts each word into `vocabulary_items` using `ON CONFLICT (dictionary_form, reading) DO UPDATE`
- `dictionary_form` = `surface` field from JSON; `reading` = hiragana reading
- `part_of_speech` defaults to `"noun"` (correct for ~85% of entries; enrichment can fix later)
- `jlpt_level` = null for anime-specific terms (correct as-is — no change needed)
- Computes `display_order`: N5=0, N4=1, N3=2, N2=3, N1=4, null=5, then sub-sort by array index within each level
- Upserts into `anime_vocab_catalog` — idempotent, re-runnable
- Uses `animeMetadata` table (already exists) for cover/banner images — link by slug derivation (lowercase + replace spaces with hyphens)

### Routes
- `/[locale]/anime` — index page: grid of all 6 anime cards
- `/[locale]/anime/[slug]` — carousel for one anime: all words with filters
- Both locale-mirrored (same pattern as existing `/[locale]/songs/` routes)
- Nav: add "Anime" link to header alongside existing songs nav item

### Anime Index Page (`/anime`)
- Server component
- Query: SELECT distinct `anime_slug`, COUNT(vocab_item_id), JOIN `animeMetadata` for display data
- Renders `AnimeIndexGrid` client component (search + filter, like `SongGrid`)
- Each card: cover image, anime label, word count badge, easiest JLPT badge, short description

### Anime Carousel Page (`/anime/[slug]`)
- Server component fetches: all vocab for slug (JOIN vocab_items) + user mastery states
- Passes `initialMasteryMap` to client carousel component
- Client: `AnimeVocabCarousel` with `JlptFilterBar`, `CategoryTabBar`, `VocabWordCard` grid

### Word Card Design
Each `VocabWordCard` shows:
- Surface (kanji, large)
- Reading (furigana — hiragana)
- Romaji
- Localized meaning (en/pt-BR/es based on locale)
- JLPT badge (existing `Badge variant="jlpt"` primitive)
- Category chip (Badge variant="mono")
- Context note (italic, muted — the anime-hook sentence)
- Mastery dot: grey=new, yellow=learning, green=mastered (from initialMasteryMap)

### JLPT Filter
- Chips: "All" / "N5" / "N4" / "N3" / "N2" / "N1" / "Anime-specific" (null jlpt_level)
- Same chip UI pattern as SongGrid difficulty filter

### Category Tabs
- Derived from distinct `category` values in the loaded word set
- "All" + each category (world, combat, themes, pirate, etc.)
- Horizontal scroll for overflow on mobile

### Exercise Session ("Practice these words")
- New function `buildAnimeCarouselQuestions()` in `src/lib/exercises/carousel-generator.ts`
- Input: filtered words + masteryMap; Output: `Question[]` (same shape as `buildQuestions`)
- Exercise types: `vocab_meaning` and `meaning_vocab` only (no verse context needed)
- Uses existing `pickDistractors` with same-anime word pool
- Respects existing `LENGTH_CAP` constants
- Calls existing `recordVocabAnswer` server action with `songVersionId: null` (already nullable)
- New thin server action `saveAnimeCarouselSession` (no `userSongProgress` upsert, yes gamification/XP/streak)
- `AnimeSessionSummary` component (lighter — accuracy, XP gained, "Back to carousel" button, no stars)

### Tracking & Dashboard
- `user_vocab_mastery` is source-agnostic — carousel words tracked exactly like song words
- Dashboard vocab count already includes all mastery rows — no new counter needed for v1
- `user_exercise_log.song_version_id` passes as null (already supported)
- No `source_context` column in v1 (deferred to v2)

### What is NOT in this phase (deferred)
- Self-rate affordance on word cards (v2)
- Source tagging column on exercise log (v2)
- "Anime vocab" section on dashboard (v2 — existing count already captures it)
- Scenes/video content (legally blocked — Phase 21 with lawyer sign-off)
- Grammar rule pages per anime (different cognitive mode — separate future feature)
- YouTube scenes embedded (copyright risk — not in scope)
- Additional anime beyond the 6 seeded (Demon Slayer, Dragon Ball, etc. — v2 batch)

</decisions>

<specifics>
## Specific Implementation Notes

### Drizzle schema addition
```typescript
export const animeVocabCatalog = pgTable("anime_vocab_catalog", {
  id: uuid("id").defaultRandom().primaryKey(),
  anime_slug: text("anime_slug").notNull(),
  vocab_item_id: uuid("vocab_item_id").notNull().references(() => vocabularyItems.id, { onDelete: "cascade" }),
  category: text("category").notNull(),
  display_order: integer("display_order").notNull(),
  context_note: text("context_note"),
  created_at: timestamp("created_at").defaultNow(),
}, (t) => ({
  unique: unique("anime_vocab_catalog_slug_vocab_unique").on(t.anime_slug, t.vocab_item_id),
  slugOrderIdx: index("anime_vocab_catalog_slug_order_idx").on(t.anime_slug, t.display_order),
}));
```

### Seed script JLPT sort order
```typescript
const JLPT_ORDER: Record<string, number> = { N5: 0, N4: 1, N3: 2, N2: 3, N1: 4 };
const jlptRank = (level: string | null) => level ? (JLPT_ORDER[level] ?? 4) : 5;
```

### Query: getAnimeVocabBySlug
Returns `{ animeMeta, words: AnimeVocabItem[] }` where AnimeVocabItem extends VocabularyItem with `category`, `context_note`, `display_order`.
Per-user mastery: JOIN `user_vocab_mastery` WHERE `user_id = userId` — returned as `MasteryStateMap`.

### carousel-generator.ts — key difference from generator.ts
No `example_from_song`, no verse references, no LearnCard verse display.
Distractor pool = other words in the same anime carousel (not global vocab pool).
Output shape: `Question[]` identical to buildQuestions output — downstream unchanged.

### saveAnimeCarouselSession action
Does NOT call `userSongProgress` upsert.
DOES call `applyGamificationUpdate` (XP + streak).
Returns same shape as saveSessionResults for session summary.
