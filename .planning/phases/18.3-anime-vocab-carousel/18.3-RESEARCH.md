## Summary

Phase 18.3 adds a standalone `/anime` section to KitsuBeat. It is an additive feature: a new DB table (`anime_vocab_catalog`), a seed script, four new pages, two new server actions, and a thin generator wrapper. Crucially, it does NOT modify any existing tables, server actions, or exercise engine code — it reuses them.

The central insight for planning: **`recordVocabAnswer` already accepts `songVersionId: null`** (confirmed in source). The `user_vocab_mastery` table is keyed on `(user_id, vocab_item_id, card_kind)` with no song reference — carousel words slot in identically to song words. The exercise session summary is the only net-new UI surface that diverges from the existing song pattern.

The nav addition requires edits in two files: `src/app/layout.tsx` (desktop link cluster) and `src/app/components/MobileNavSheet.tsx` (mobile sheet links array). Both need the `t('nav.anime')` translation key plus additions to `src/messages/en/common.json`, `es/common.json`, `pt-BR/common.json`.

**Primary recommendation:** 5 plans in 2 waves — Wave 0 (DB + seed), Wave 1 (pages + nav), Wave 2 (exercise session). Keep plans narrow; each plan has exactly one test file to create.

### Pattern 5: Server Action — saveAnimeCarouselSession

Modeled on `saveSessionResults` in `exercises.ts` but simpler (no `userSongProgress`):

```typescript
// Source: modeled on src/app/actions/exercises.ts saveSessionResults
"use server";
export async function saveAnimeCarouselSession(input: {
  animeSlug: string;
  answers: AnswerRecord[];
  tz?: string;
}): Promise<AnimeCarouselSessionResult> {
  const { userId } = await auth();
  if (!userId) throw new Error("Unauthorized");

  // Rate limit (same pattern as saveSessionResults)
  const { success } = await sessionRatelimit.limit(userId);
  if (!success) throw new Error("Rate limit exceeded.");

  // No userSongProgress upsert — carousel has no song-level star tracking
  // No userExerciseSongCounters — no premium quota for carousel

  // Gamification (identical call signature)
  const gamification = await applyGamificationUpdate({
    userId,
    tz: input.tz ?? "UTC",
    correctAnswers: answers.filter(a => a.correct).length,
    totalAnswers: answers.length,
    sessionType: "short",  // carousel sessions are "short" equivalent
    newStars: 0,           // carousel has no star concept
    previousStars: 0,
    songSlug: "",          // no path advancement for carousel
  });

  return { xpGained: gamification.xpGained, ... };
}
```

### Pattern 6: carousel-generator.ts

```typescript
// Source: modeled on src/lib/exercises/generator.ts buildQuestions
import { shuffle, pickDistractors } from "./generator";
import type { Question, ExerciseType } from "./generator";

export interface AnimeVocabItem {
  vocab_item_id: string;
  surface: string;   // = dictionary_form in vocabulary_items
  reading: string;
  romaji: string;
  meaning: Record<string, string>; // {en, "pt-BR", es}
  jlpt_level: "N5" | "N4" | "N3" | "N2" | "N1" | null;
  category: string;
  context_note: string | null;
}

export function buildAnimeCarouselQuestions(
  words: AnimeVocabItem[],
  masteryMap: Record<string, number>, // vocab_item_id → FSRS state
  cap = 10
): Question[] {
  const eligible = words.filter(w => w.vocab_item_id);
  const types: ExerciseType[] = ["vocab_meaning", "meaning_vocab"];
  const questions: Question[] = [];

  for (const word of eligible) {
    for (const type of types) {
      // Adapt AnimeVocabItem → VocabEntry shape for pickDistractors
      // distractor pool = same anime only (eligible)
      const distractors = pickDistractors(asVocabEntry(word), type, eligible.map(asVocabEntry), []);
      // ... build Question
    }
  }
  return shuffle(questions).slice(0, cap);
}
```

### Anti-Patterns to Avoid

- **Duplicating `pickDistractors`:** Do not re-implement distractor logic. Import `pickDistractors` from `generator.ts` directly. The carousel just uses a narrower pool.
- **Adding `song_version_id` column to new queries:** `anime_vocab_catalog` does NOT link to `song_versions`. Keep it fully separate.
- **Querying `animeMetadata` by slug:** The `animeMetadata` table's primary key is `anime` (the raw title string, e.g., `"One Piece"`). The link is by slug derivation: `anime_label.toLowerCase().replace(/\s+/g, '-')`. This derivation is in both directions: slug→label for queries.
- **Using `force-dynamic` unnecessarily:** The anime index page CAN be cached (it's not user-specific). Only the carousel page (with mastery overlay) needs `force-dynamic` or a revalidation strategy.
- **Route conflict with existing `/anime-list`:** `/anime-list` shows songs grouped by anime. `/anime` is the new vocab carousel. These are different routes — no conflict. Do not rename `/anime-list`.

## Common Pitfalls

### Pitfall 1: `animeMetadata` primary key mismatch
**What goes wrong:** `getAnimeVocabBySlug` tries to JOIN `anime_vocab_catalog` with `animeMetadata` by slug, but `animeMetadata.anime` stores the raw title ("One Piece"), not the slug ("one-piece").
**Why it happens:** The `animeMetadata` table was designed around `songs.anime` field values, not carousel slugs.
**How to avoid:** Store the slug in `anime_vocab_catalog.anime_slug`, and JOIN to `animeMetadata` via a derived lookup: `WHERE anime_metadata.anime = (SELECT label FROM mapping WHERE slug = ?)`. Alternatively, store the mapping in the seed script and pass the raw title to the query. The simplest pattern: include a `anime_title` field in `anime_vocab_catalog` or compute the slug→title lookup in the query layer.
**Warning signs:** NULL cover/banner images in the carousel page despite metadata existing in DB.

### Pitfall 2: `user_vocab_mastery` unique key requires `card_kind`
**What goes wrong:** The seed or carousel exercise writes a mastery row without `card_kind`, hitting the NOT NULL constraint.
**Why it happens:** Phase 11.6 changed the unique key from `(user_id, vocab_item_id)` to `(user_id, vocab_item_id, card_kind)`. The column is NOT NULL.
**How to avoid:** Always pass `card_kind: "romaji_meaning"` when writing carousel mastery. `recordVocabAnswer` already defaults to this via the `CardKindSchema.parse(input.cardKind ?? "romaji_meaning")` pattern — no change needed when calling it without `cardKind`.

### Pitfall 3: `VocabEntry` adapter for `pickDistractors`
**What goes wrong:** `carousel-generator.ts` passes raw `AnimeVocabItem` objects to `pickDistractors`, which expects `VocabEntry` (from `src/lib/types/lesson.ts`).
**Why it happens:** `VocabEntry` has `example_from_song`, `additional_examples`, and `meaning` as a `Localizable` type. `AnimeVocabItem` uses a plain `Record<string, string>`.
**How to avoid:** Write a thin `asVocabEntry(word: AnimeVocabItem): VocabEntry` adapter. Set `example_from_song: ""`, `additional_examples: []`. The `meaning` field type is compatible — `Localizable` accepts `{en: string, "pt-BR": string, es: string}`.

### Pitfall 4: locale route re-export pattern
**What goes wrong:** The `[locale]/anime/page.tsx` re-export misses `setRequestLocale(locale)`, causing next-intl to use the wrong locale in server components.
**Why it happens:** The re-export pattern `export { default } from '@/app/anime/page'` is clean for simple cases, but the locale-aware page needs `setRequestLocale`. The `/[locale]/songs/page.tsx` does NOT simply re-export — it's a full page that calls `setRequestLocale` and passes locale context.
**How to avoid:** For the locale variants, follow the `/[locale]/songs/page.tsx` pattern (full component with `setRequestLocale`), not the simple `[locale]/songs/[slug]/page.tsx` re-export. The distinction: `[slug]` re-exports because the slug page doesn't need locale for SSR (no translations in the server component). The index pages DO use `getTranslations`.

### Pitfall 5: `saveAnimeCarouselSession` calling `activityEvents` on wrong condition
**What goes wrong:** The gamification path in `applyGamificationUpdate` tries to emit `activityEvents` when `previousStars < 3 && newStars === 3`, which requires a `songSlug` that resolves to a real song UUID.
**Why it happens:** When passing `songSlug: ""`, the DB lookup `WHERE songs.slug = ""` returns no rows — the `activityEvents` INSERT is skipped (no crash, just no event). This is correct behavior.
**How to avoid:** Confirmed: passing `songSlug: ""` is safe [VERIFIED: session-integration.ts line 253 — `if (songRows[0])` guard].

### Pitfall 6: `db:generate` vs `db:push` workflow
**What goes wrong:** Developer adds `animeVocabCatalog` to `schema.ts` and runs `db:push` directly without `db:generate`, producing no SQL migration file.
**Why it happens:** `db:push` applies schema changes directly to the DB but skips generating the migration SQL file. The project needs the SQL in `drizzle/` for the CI pipeline and Neon branch management.
**How to avoid:** Always run `npm run db:generate` first. This creates `drizzle/0025_anime_vocab_catalog.sql`. Then run `npm run db:push` to apply.
