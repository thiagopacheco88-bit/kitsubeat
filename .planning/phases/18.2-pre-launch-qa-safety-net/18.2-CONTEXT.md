# Phase 18.2: Pre-Launch QA Safety Net - Context

**Gathered:** 2026-05-16
**Status:** Ready for planning
**Source:** Direct conversation — full context captured inline

<domain>
## Phase Boundary

A pre-launch test expansion that turns the Playwright suite into a reliable safety net for
multi-locale, multi-journey validation. The trigger: a locale+nav interaction bug (`/pt-BR/sign-in`
404) was not caught by any existing spec because tests only ran with the default English locale.

The deliverable is:
- New Playwright specs covering locale-aware journeys (every key nav action × all 3 locales)
- A `npm run test:qa` command that runs the full suite in parallel and finishes fast
- Verified: zero locale 404s, all nav links reachable, onboarding gate non-looping, API health green

This phase does NOT touch unit tests, integration tests, or type-strictness — those are Phase 20.

</domain>

<decisions>
## Implementation Decisions

### D-01 — Locale-journey matrix is the #1 priority
Test the 5 highest-risk nav actions with each non-English locale cookie set:
- Actions: click Sign in, click Sign up (link from sign-in), click Trilha/Path, click Kana, click a song player
- Locales to inject via cookie before each test: `kb_locale=pt-BR`, `kb_locale=es`
- Assert: resulting URL does NOT contain `/pt-BR/sign-in` (or locale-prefixed auth paths) AND page is not 404
- New spec: `tests/e2e/i18n-nav-locale-matrix.spec.ts`

### D-02 — Full nav sweep spec (all locales)
Every visible header link on the home page (`/`) must be clickable and lead to a page that:
- Returns HTTP status < 500
- Does not show "This page could not be found" text
- Tested for: en (no cookie), pt-BR cookie, es cookie
- New spec: `tests/e2e/nav-sweep-all-locales.spec.ts`

### D-03 — Sign-in/sign-up reachability per locale
Dedicated spec separate from nav sweep, because this is the class of bug that bit us:
- Set `kb_locale=pt-BR` cookie
- Navigate to `/` 
- Click the "Sign in" link in the nav header
- Assert URL is `/sign-in` (NOT `/pt-BR/sign-in`)
- Assert page does not 404 (look for Clerk sign-in form OR absence of "page could not be found")
- Repeat for `kb_locale=es`
- New spec: `tests/e2e/auth-reachability-locale.spec.ts`

### D-04 — Onboarding/terms gate smoke test
The middleware terms gate can silently break all authenticated users if misconfigured.
- Test: authenticated user with missing `terms_version` metadata gets redirected to `/onboarding/age-gate`
- Test: redirect does NOT loop (onboarding route is excluded from the gate)
- Test: authenticated user with correct `terms_version` passes through to destination
- Use `PLAYWRIGHT_AUTH=true` bypass pattern already established in `_smoke-auth-bypass.spec.ts`
- New spec: `tests/e2e/onboarding-terms-gate.spec.ts`

### D-05 — API health spec
Key `/api/*` routes should return expected status codes:
- `GET /api/songs` (or equivalent catalog endpoint if it exists) — 200
- `GET /api/cron/daily-reminder` without auth header — 401 (already covered in cron-auth.spec.ts, reference it)
- Focus on routes that would silently break the app if they went down
- New spec: `tests/e2e/api-health.spec.ts`

### D-06 — Parallel runner config + `npm run test:qa` script
- Set `workers` in playwright.config.ts to use all available CPUs for the QA run
- Add `"test:qa": "playwright test --workers=4"` to package.json scripts
- Goal: full suite completes in <5 minutes
- Do NOT change the default `test` script (preserves existing sequential behavior for dev)

### D-07 — Existing i18n specs are already in main
`i18n-language-picker.spec.ts`, `i18n-locale-routing.spec.ts`, `i18n-text-deep.spec.ts` already exist.
New specs complement them — do NOT duplicate their coverage.
The gap those specs miss: they test routing behavior but not "click a specific nav link while
a non-English locale cookie is set and verify the destination loads."

### D-08 — Cookie injection pattern
Use Playwright's `context.addCookies([{ name: 'kb_locale', value: 'pt-BR', domain: 'localhost', path: '/' }])`
before `page.goto('/')` — consistent with the `kb_locale` cookie pattern in `i18n-language-picker.spec.ts`.
Do NOT use the language picker click to set locale in the matrix tests (that's a separate concern already tested).

### D-09 — Zero-flake policy applies
All new specs must pass consistently. Locale-matrix tests are deterministic (cookie-set before navigate,
no async picker interaction). Use `timeout: 10_000` on initial page load assertions.

### Claude's Discretion
- Exact worker count for `test:qa` script (4 is a reasonable default; adjust based on CI constraints)
- Whether to add a `test:qa:headed` variant for local debugging
- Whether `api-health.spec.ts` needs a test DB or can run purely on the dev server

</decisions>

<specifics>
## Specific Ideas

**The bug that prompted this phase (2026-05-16):**
- User had `kb_locale=pt-BR` cookie set (from using the language picker)
- Clicked "Sign in" in the nav → Next.js navigated to `/sign-in`
- next-intl middleware detected pt-BR locale and redirected to `/pt-BR/sign-in`
- `src/app/sign-in/[[...sign-in]]/page.tsx` lives at root (not under `[locale]/`)
- Result: 404
- Fix: Added `isAuthRoute` matcher in middleware to skip intl processing for `/sign-in(.*)` and `/sign-up(.*)`
- The new spec `auth-reachability-locale.spec.ts` must reproduce this scenario and assert it stays fixed

**Existing suite size:** ~67 specs covering player, exercises, home variants, kana, path, a11y, visual regression, theme, mobile, i18n routing. This phase adds 4-5 new specs targeted at the gaps.

**Workers note:** Playwright's default is `workers: undefined` (uses CPU count). The `test:qa` script should explicitly set workers to ensure predictable parallelism.

</specifics>
