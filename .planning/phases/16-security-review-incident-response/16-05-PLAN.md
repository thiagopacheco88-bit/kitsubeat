<!-- RLS policy pattern with Clerk JWT. From RESEARCH.md Pattern 2. -->

```sql
-- Key difference from native Supabase Auth:
-- auth.uid() does NOT work with Clerk. Use auth.jwt()->>'sub' instead.
-- Clerk user IDs are text (e.g. user_abc123), matching the text user_id column.

-- Enable RLS:
ALTER TABLE user_song_progress ENABLE ROW LEVEL SECURITY;

-- SELECT own rows:
CREATE POLICY "user_song_progress_select_own"
ON user_song_progress FOR SELECT TO authenticated
USING ((SELECT auth.jwt()->>'sub') = user_id);

-- INSERT own rows:
CREATE POLICY "user_song_progress_insert_own"
ON user_song_progress FOR INSERT TO authenticated
WITH CHECK ((SELECT auth.jwt()->>'sub') = user_id);

-- UPDATE own rows:
CREATE POLICY "user_song_progress_update_own"
ON user_song_progress FOR UPDATE TO authenticated
USING ((SELECT auth.jwt()->>'sub') = user_id)
WITH CHECK ((SELECT auth.jwt()->>'sub') = user_id);
```

Catalog table pattern:

ALTER TABLE songs ENABLE ROW LEVEL SECURITY;

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQL Editor / direct psql → Neon Postgres | RLS is the PRIMARY security boundary here — Drizzle bypasses it, but direct SQL access is governed by RLS |
| Drizzle ORM → Neon Postgres | RLS is NOT enforced (Drizzle connects as owner role); server action auth() is the primary boundary for this path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-05-01 | Elevation of Privilege | Direct SQL access to user tables without RLS | mitigate | ENABLE ROW LEVEL SECURITY on all user-data tables with auth.jwt()->>'sub' = user_id policy |
| T-16-05-02 | Information Disclosure | Catalog data via direct SQL (acceptable) | accept | Catalog tables are public-read by design; no PII in catalog tables |
| T-16-05-03 | Tampering | Enabling RLS without policies = deny all (Pitfall 5) | mitigate | Every ENABLE ROW LEVEL SECURITY immediately followed by at least one CREATE POLICY in the same migration; IF NOT EXISTS guards make migration idempotent |
| T-16-05-04 | Tampering | auth.uid() used instead of auth.jwt()->'sub' for Clerk | mitigate | Explicitly use auth.jwt()->>'sub' in all policies; grep for auth.uid() as acceptance criterion |
</threat_model>
