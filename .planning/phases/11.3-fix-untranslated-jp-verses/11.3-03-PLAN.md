<objective>
Extend the existing `scripts/seed/apply-verse-patch.ts` (currently append-only) to support a new `replace_verse_number` patch entry shape, so a single `.planning/verse-patches/<slug>.json` file can mix `after_original` (append) and `replace_verse_number` (in-place edit) entries — and the applier processes them in the locked D-11 order: ALL replaces first, THEN appends operating on the post-replace state. Without this extension, every drafted replacement would have to live in a separate file system, doubling complexity and breaking the "patches coexist in one slug.json" invariant called out in CONTEXT.md `code_context`.

           // the replacement's signature, the patch was applied in a prior run.

             merged.push(v);

             // In-place edit: keep the slot, replace the body. The final renumber
             // pass sets verse_number = i + 1 — so the slot index is preserved.
             merged.push({ verse_number: 0, ...replacement });
           }
         } else {
           merged.push(v);

         for (const p of appendPatches) {
           if (p.after_original !== v.verse_number) continue;
           const patchSurface = patchSig(p.verse);
           const nextInOriginal = original[i + 1];
           if (nextInOriginal && patchSig(nextInOriginal) === patchSurface) {
             skipped++;
             continue;
           }
           merged.push({ verse_number: 0, ...p.verse });
         }
       }
