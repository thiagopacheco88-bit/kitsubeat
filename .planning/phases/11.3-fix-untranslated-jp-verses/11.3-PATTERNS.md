## Schema Caveat (read first)

CONTEXT.md `D-05` says **"`kanji_breakdown` required when the token's surface contains kanji"**, but the live `TokenSchema` (`scripts/types/lesson.ts` lines 38–46) does NOT include `kanji_breakdown` at the verse-token level. That field exists only on the `VocabEntrySchema` (line 131 of the same file) — i.e., on the lesson's top-level `vocabulary[]` array, not inside verse tokens.

**Current verse Token shape (the only one the renderer accepts):**
```ts
{ surface, reading, romaji, grammar, grammar_color, meaning: { en, "pt-BR", es }, jlpt_level }
```

Existing clean tokens in `data/lessons-cache/sign-flow.json` verses 7, 8, 10 confirm this — none carry `kanji_breakdown`. The Ollama prompt and JSON schema in this phase MUST emit the verse-token shape above (no `kanji_breakdown`). If the planner wants kanji-character data for the UI, that's a follow-up phase touching the vocabulary array, not the verses being patched here. Flag this in the SPEC-vs-schema reconciliation step of the plan.

```ts
// Per CONTEXT.md + SPEC.md: stub signature catches all 3 locales
function isStub(v: Verse): false | { locales_broken: string[] } {
  const broken: string[] = [];
  if (v.tokens.length === 1) {
    const surface = v.tokens[0].surface ?? "";
    const hasJp = /[぀-ヿ㐀-鿿]/.test(surface);
    if (!hasJp) return false;
  } else {
    return false;
  }
  for (const locale of ["en", "pt-BR", "es"] as const) {
    const t = v.translations?.[locale] ?? "";
    if (typeof t === "string" && t.startsWith("(")) broken.push(locale);
  }
  return broken.length > 0 ? { locales_broken: broken } : false;
}
```

### `scripts/seed/apply-verse-patch.ts` (MODIFIED — extend with `replace_verse_number` mode)

**Analog:** itself — the modification extends the existing per-slug merge loop.

**Existing append-mode loop to preserve** (`apply-verse-patch.ts` lines 41–75):
```ts
function applyPatch(slug: string): { before: number; after: number; skipped: number } {
  const lessonPath = join(LESSONS_DIR, `${slug}.json`);
  const patchPath = join(PATCHES_DIR, `${slug}.json`);
  if (!existsSync(lessonPath)) throw new Error(`lesson missing: ${lessonPath}`);
  if (!existsSync(patchPath)) throw new Error(`patch missing: ${patchPath}`);

  const lesson = JSON.parse(readFileSync(lessonPath, "utf-8"));
  const patch: Patch = JSON.parse(readFileSync(patchPath, "utf-8"));
  const original: Verse[] = lesson.verses;
  const merged: Verse[] = [];
  let skipped = 0;
  for (let i = 0; i < original.length; i++) {
    const v = original[i];
    merged.push(v);
    for (const p of patch.patches) {
      if (p.after_original !== v.verse_number) continue;
      // Idempotency guard (lines 60-66): if the very next verse in the current
      // lesson already matches this patch's verse (by surface signature), the
      // patch was applied in a prior run — skip it.
      const patchSurface = patchSig(p.verse);
      const nextInOriginal = original[i + 1];
      if (nextInOriginal && patchSig(nextInOriginal) === patchSurface) {
        skipped++;
        continue;
      }
      merged.push({ verse_number: 0, ...p.verse });
    }
  }
  merged.forEach((v, i) => (v.verse_number = i + 1));
  lesson.verses = merged;
  writeFileSync(lessonPath, JSON.stringify(lesson, null, 2), "utf-8");
  return { before: original.length, after: merged.length, skipped };
}
```

**`patchSig` helper to reuse for replace-mode idempotency** (line 38):
```ts
const patchSig = (v: { tokens: VerseToken[] }): string =>
  v.tokens.map((t) => t.surface).join("");
```

**Required modifications (per SPEC Req 5 + D-11):**

1. **Extend the `Patch` type** (line 34) to permit both entry shapes:
   ```ts
   type AppendPatch = { after_original: number; verse: Omit<Verse, "verse_number"> };
   type ReplacePatch = { replace_verse_number: number; verse: Omit<Verse, "verse_number"> };
   type PatchEntry = AppendPatch | ReplacePatch;
   type Patch = { patches: PatchEntry[] };
   ```

2. **Two-pass merge per D-11 ordering** (replace first, then append):
   ```ts
   // Pass 1: build a replacement map for in-place edits
   const replaceMap = new Map<number, Omit<Verse, "verse_number">>();
   for (const p of patch.patches) {
     if ("replace_verse_number" in p) replaceMap.set(p.replace_verse_number, p.verse);
   }

   // Pass 2: walk original, apply replacements in place + collect appends
   const appendPatches = patch.patches.filter(
     (p): p is AppendPatch => "after_original" in p
   );

   for (let i = 0; i < original.length; i++) {
     const v = original[i];
     const replacement = replaceMap.get(v.verse_number);
     if (replacement) {
       // Idempotency (lines 60-66 contract): if the current verse already
       // matches the replacement's surface signature, no-op.
       if (patchSig(v) === patchSig(replacement)) {
         skipped++;
         merged.push(v);
       } else {
         merged.push({ verse_number: 0, ...replacement });
       }
     } else {
       merged.push(v);
     }
     // Then run the existing append loop using `appendPatches` (not `patch.patches`)
     for (const p of appendPatches) { /* … existing body lines 55-69 … */ }
   }
   ```

3. **Preserve sequential renumbering** (line 71) — `merged.forEach((v, i) => (v.verse_number = i + 1))` — replace-mode should NOT shift numbers, but the renumber step is still safe because non-replaced verses keep their relative order and replaced verses occupy the same slot.

4. **Preserve `JSON.stringify(lesson, null, 2)`** (line 73) — `data/lessons-cache/*.json` is checked-in 2-space-indent JSON.

**Mirror this pattern:** Keep the function signature, `applyPatch(slug)`, the `--all` runner (lines 78–86), and the existing console output format. Add only the replace-pass — do not refactor the append-pass.
