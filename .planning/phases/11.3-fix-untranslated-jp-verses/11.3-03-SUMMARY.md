## Decisions Made

- **Replace idempotency by signature-scan-on-build, not per-iteration verse_number match** (load-bearing). The naïve approach (check if `currentVerse.signature === replacement.signature` at the slot) fails on the second apply of a mixed patch: the first apply's renumber pass shifts the replaced row's verse_number (any `after_original` BEFORE it bumps the slot index), so on second apply the slot at `verse_number=N` no longer holds the previously-replaced row — it holds the inserted row. The fix: when building `replaceMap`, scan the entire `original` lesson; if any verse's signature already matches the replacement, the patch was applied → skip enrolling that replace entry. Signature collisions on real lyrics are vanishingly unlikely (multi-token surface concat). Same primitive the append-mode idempotency check already uses.
- **Entry-point guard wraps the ENTIRE CLI block, including the error-exit branch.** The regression came from the `else { process.exit(1) }` branch firing during import (Vitest provides no slug arg). Initial instinct was to gate just the error branch — but that would still leak the `--all` and single-slug branches into module load if `process.argv[2]` happened to look slug-like. The clean fix: gate the entire dispatch tree behind `if (isMain)`. CLI behavior is unchanged when invoked normally.
- **Test fixture writes into REAL dirs under a synthetic slug, not into a tmp dir.** The applier reads module-level `LESSONS_DIR` / `PATCHES_DIR` consts, so DI or env-var override would have required production refactoring just for testability. Trade-off accepted: the synthetic slug `__test_apply_patch_fixture__` is unmistakable (any post-test `ls` shows it immediately), and `afterEach` unlinks both files. No leakage observed across multiple `vitest run` invocations.
- **vitest.config.ts include glob extended (per plan note).** Alternative (move test to `tests/unit/seed/...`) would have left Plan 05+ test fixtures in the wrong tree. Adding `scripts/**/*.{test,spec}.ts` is one line and opens the door for any future seed-script test fixture without further config edits.

## Issues Encountered

- **Idempotency required two implementation iterations** (in-loop, no extra commits — debugged within the GREEN phase). First attempt: per-iteration check `if (patchSig(v) === patchSig(replacement)) skip`. Failed Test 2 because the replaced row's verse_number had shifted post-first-apply (`INSERTED` now occupied `verse_number=3` so the replaceMap lookup fired against the wrong row). Second attempt: signature-scan-on-build at replaceMap construction time. Passed.
- **Vitest CLI-passed file paths don't override the `include` glob.** `npx vitest run scripts/seed/apply-verse-patch.test.ts` returned "No test files found" with the original config.
