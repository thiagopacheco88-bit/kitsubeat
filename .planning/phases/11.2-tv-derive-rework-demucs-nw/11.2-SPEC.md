# Phase 11.2: TV-Derive Rework with Demucs + Needleman-Wunsch — Specification

**Created:** 2026-04-26
**Ambiguity score:** 0.122 (gate: ≤ 0.20)
**Requirements:** 6 locked

## Goal

Replace the LCS-based TV-lesson derivation (which fails on clean Demucs-stem WhisperX input) with a Demucs+WhisperX+Needleman-Wunsch pipeline, then re-derive and reload all 60 TV lessons — including the 4 currently-failing stragglers — gated by an objective per-verse onset spot-check and a regression-guarding audit script.

## Background

The catalog has 60 songs with `song_versions.version_type='tv'`. 56 of those have lessons loaded today via the legacy pipeline (`10b-derive-tv-lessons.ts` per-verse romaji LCS → `10c-load-tv-lessons.ts`); the other 4 are flagged `[no_detected_verses]` stragglers (`my-answer-seamo`, `mountain-a-go-go-too-captain-straydum`, `newsong-tacica`, `whats-up-people-maximum-the-hormone`).

Sign-flow shipped to Vercel with a degenerate TV lesson — 5 verses spanning 73s with verse #3 stretching 38s — and was hand-fixed via [scripts/debug/rebuild-sign-flow-tv.ts](../../../scripts/debug/rebuild-sign-flow-tv.ts), a one-off segment-anchored projection. Empirical re-runs of `10b` against a cleaner sign-flow Demucs-stem WhisperX transcript (2026-04-26) still returned `[no_detected_verses]` at every threshold tried (0.4, 0.2, 0.1) — the per-verse romaji LCS scatters matched chars across the entire transcript, and `MAX_SPAN_RATIO=2.0` rejects every verse on principle. This is an algorithm-vs-input-quality mismatch, not a tunable threshold.

The full-version A/B Demucs+WhisperX pipeline ([scripts/seed/ab-demucs-isolate.py](../../../scripts/seed/ab-demucs-isolate.py) + [ab-transcribe-stems.py](../../../scripts/seed/ab-transcribe-stems.py)) operates on `public/audio/{slug}.mp3` → `data/vocal-stems/` → `data/timing-cache-stem/`. No TV equivalent exists; one TV song (sign-flow) was processed manually and lives at `data/audio-tv/sign-flow.mp3`, `data/vocal-stems-tv/htdemucs/sign-flow/`, `data/timing-cache-tv-stem/sign-flow.json`.

There is no audit script today that reports "loaded but degenerate" TV lessons — `10c` schema-validates only, so structurally-valid-but-unusable lessons (like sign-flow's) load silently.

## Requirements

1. **TV Demucs+WhisperX pipeline**: A TV-mode equivalent of the full-version Demucs+WhisperX pipeline produces clean stem timing for every TV song.
   - Current: Only `ab-demucs-isolate.py` + `ab-transcribe-stems.py` exist, hardcoded to full-version paths (`public/audio/`, `data/vocal-stems/`, `data/timing-cache-stem/`). One TV song (sign-flow) was processed by hand; no script reads TV YouTube IDs or writes to TV paths.
   - Target: Scripts (new files mirroring the full-version pair, or `--tv` flags on the existing scripts) that read TV `youtube_id` from `song_versions WHERE version_type='tv'`, download to `data/audio-tv/{slug}.mp3` via yt-dlp, isolate vocals to `data/vocal-stems-tv/htdemucs/{slug}/vocals.wav`, and transcribe with WhisperX large-v3 ja to `data/timing-cache-tv-stem/{slug}.json` (slug-keyed schema matching `data/timing-cache-tv/`). All steps idempotent (skip if output exists). `PYTHONIOENCODING=utf-8` mandatory on the WhisperX step.
   - Acceptance: After running the pipeline against all 60 TV songs, `data/audio-tv/`, `data/vocal-stems-tv/htdemucs/`, and `data/timing-cache-tv-stem/` each contain exactly 60 entries; rerunning any step produces zero new work.

2. **NW-based derive script**: A new derive script replaces the per-verse romaji LCS in `10b-derive-tv-lessons.ts` with monotonic global alignment.
   - Current: `scripts/seed/10b-derive-tv-lessons.ts` (499 lines) runs per-verse romaji LCS against `data/timing-cache-tv/`, gated by `MAX_SPAN_RATIO=2.0` and `MIN_MATCHED_CHARS=8`. Returns `[no_detected_verses]` on clean Demucs-stem input because per-verse matched chars scatter across the whole TV transcript.
   - Target: A script (replacement at `10b-derive-tv-lessons.ts` or successor like `10b-derive-tv-lessons-nw.ts`) that runs Needleman-Wunsch global alignment between full-lesson romaji (concatenated verse-by-verse with verse-boundary markers) and TV-stem WhisperX romaji from `data/timing-cache-tv-stem/{slug}.json`. NW algorithm is locked; scoring parameters (starting points: match=+2, mismatch=-1, gap=-1) are tunable during plan/execute. Verse presence threshold ≥40% matched chars within the verse range. Verse timing: `tv_start` = TV time of first matched char in verse range; `tv_end` = TV time of last matched char; gap-midpoint expansion preserved from existing 10b logic.
   - Acceptance: Running the new script against all 60 TV songs produces 60 valid `data/lessons-cache-tv/{slug}.json` files that pass `LessonSchema.safeParse`, including all 4 prior stragglers; zero `[no_detected_verses]` outputs.

3. **Catalog rollout to production**: All 60 TV `song_versions.lesson` rows are updated with NW-derived content.
   - Current: `data/lessons-cache-tv/` contains 56 LCS-derived lessons (sign-flow's hand-fixed); 4 stragglers have no file; `song_versions.lesson` for `version_type='tv'` reflects the broken LCS state in production Neon.
   - Target: All 60 TV `song_versions.lesson` rows updated via the existing unmodified `scripts/seed/10c-load-tv-lessons.ts`, gated by spot-check pass (Requirement 4) before rollout begins.
   - Acceptance: `SELECT COUNT(*) FROM song_versions WHERE version_type='tv' AND lesson IS NULL` returns 0; `SELECT COUNT(*) FROM song_versions WHERE version_type='tv'` returns 60; the audit script (Requirement 5) reports zero degenerate lessons across all 60 rows.

4. **Spot-check validation gate**: 8 representative songs (2 each from JLPT N5/N4/N3/N2) pass an objective per-verse onset criterion before catalog rollout.
   - Current: There is no validation step between deriving a TV lesson and `10c` updating the DB; `10c` only schema-validates.
   - Target: A documented spot-check workflow that selects 8 named songs (2 per JLPT level — slugs and levels recorded in the plan), and for each measures every verse's `start_time_ms` against the audio onset of the corresponding lyric in the TV cut (audio onset = the WhisperX word-start time of the verse's first matched character on the Demucs stem). Pass = 100% of verses in 100% of 8 songs land within ±500ms of audio onset. Catalog rollout (Requirement 3) blocked until all 8 pass.
   - Acceptance: A spot-check report (file or console output) names all 8 songs with JLPT level, lists the per-verse onset deltas, and shows every verse below the ±500ms tolerance; if any song fails, it is re-derived (parameter tuning, manual segment anchor, or other plan-phase remedy) and re-checked rather than skipped or auto-promoted.

5. **Audit script for degenerate TV lessons**: A regression-guarding script flags lessons that loaded successfully but are structurally unusable.
   - Current: No script reports "loaded but degenerate" TV lessons. Sign-flow's 5-verse, 38s-gap lesson loaded cleanly via `10c` because it satisfied the schema.
   - Target: A script (e.g., `scripts/seed/audit-tv-lessons.ts`) that reads `song_versions.lesson` for all `version_type='tv'` rows and flags lessons where (a) verses-per-TV-second density falls below a per-song density floor (TV duration sourced from `data/timing-cache-tv-stem/{slug}.json` last-word end OR last verse's `end_time_ms` — plan-phase detail), OR (b) any single verse spans more than 15s. Output: per-flagged-slug printout naming the failing metric and its value.
   - Acceptance: After Requirement 3 completes, the audit script reports zero flagged songs across the full 60-song catalog. Running the audit against sign-flow's pre-rework broken lesson (preserved in git or recreated for verification) flags it correctly.

6. **Stragglers must produce loadable lessons or have a logged disposition**: All 4 `[no_detected_verses]` stragglers either ship with valid lessons or have an explicit, documented decision closing them out.
   - Current: `my-answer-seamo`, `mountain-a-go-go-too-captain-straydum`, `newsong-tacica`, `whats-up-people-maximum-the-hormone` have no `data/lessons-cache-tv/{slug}.json`; their `song_versions.lesson` is null. Tracked in [.planning/todos/pending/2026-04-18-fix-4-tv-lesson-derivation-stragglers.md](../../todos/pending/2026-04-18-fix-4-tv-lesson-derivation-stragglers.md).
   - Target: Each of the 4 either (a) loads a valid TV lesson via the new pipeline that passes the audit script and the spot-check tolerance for the songs included in the validation set, OR (b) has a documented decision (re-source TV YouTube ID, drop from TV catalog, or defer with rationale) recorded in the phase artifacts and the existing todo file is closed.
   - Acceptance: Per-straggler status is one of `{loaded-and-passing, loaded-and-flagged-by-audit-with-rationale, removed-from-catalog-with-rationale, deferred-with-rationale}`; no straggler exits this phase in an unresolved/silent state.

## Boundaries

**In scope:**
- TV Demucs+WhisperX pipeline (yt-dlp → htdemucs → WhisperX large-v3 ja) writing to `data/audio-tv/`, `data/vocal-stems-tv/htdemucs/`, `data/timing-cache-tv-stem/`
- NW-based derive script replacing per-verse LCS in `10b-derive-tv-lessons.ts`
- Re-derivation of all 60 TV lessons (including the 4 stragglers)
- Catalog rollout to Neon for all 60 TV `song_versions.lesson` rows
- 8-song JLPT-balanced spot-check validation gate (±500ms verse onset tolerance)
- Audit script for degenerate TV lessons (verse-density floor + max-span 15s)

**Out of scope:**
- Full-version pipeline changes — already complete (307/307 stem-isolated); this phase does not touch `ab-demucs-isolate.py`/`ab-transcribe-stems.py` behavior on `public/audio/` paths
- Reordered TV cuts (chorus-first openings) — NW assumes contiguous verse order; anime OPs hold this property; non-OP cuts are deferred
- Replacing TV YouTube source IDs when the TV cut itself is unusable — handled separately by [find-youtube-replacements.ts](../../../scripts/seed/find-youtube-replacements.ts)
- Schema changes to `song_versions` or modifications to `10c-load-tv-lessons.ts` — the load script is reused unchanged
- Tuning NW for non-Japanese languages or mixed-language verses beyond what 10b's normalization already handled
- Production caching/CDN for TV audio (`data/audio-tv/` stays local-only, not deployed)

## Constraints

- **Algorithm:** Needleman-Wunsch global alignment is locked. Scoring parameters (`match=+2`, `mismatch=-1`, `gap=-1`) are starting points only — plan/execute may tune per Japanese phoneme classes (e.g., vowel-vowel mismatch, consonant mismatch) if spot-check fails.
- **WhisperX environment:** `PYTHONIOENCODING=utf-8` is mandatory on the transcription step; without it WhisperX fails on Japanese console output on Windows.
- **Idempotency:** Every pipeline step must skip already-completed artifacts on rerun, supporting interrupted batch runs.
- **Throughput:** Demucs htdemucs runs at ~0.3× realtime on CPU. The full 60-song pipeline is a one-shot batch (estimate ~5–8 hours wall-clock total). No per-song time bound enforced.
- **Deployment dependency:** Production rollout is gated on commit `33daafd` (LyricsPanel karaoke lead-in) being live in production — the spot-check tolerance assumes the lead-in window is in effect.
- **Phase ordering:** Phase 11.1 (Add-Song Pipeline) must be stable before this phase consumes its conventions; any deltas from 11.1 carry through 11.2.
