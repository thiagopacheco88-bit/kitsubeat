## Audit Script Design

### TV Duration Source Decision

**Chosen:** Last verse's `end_time_ms` from the lesson itself.

**Rationale:** Simpler — no extra IO to `data/timing-cache-tv-stem/{slug}.json`. Covers 95%+ of the catalog where the last verse has a non-zero end time. The D-07 CONTEXT.md allows either option; the lesson-based approach is consistent and sufficient for the density check.

**Fallback situation:** If the last verse has `end_time_ms=0` (low-coverage verse from the NW derive), the audit emits a `no-tv-duration` flag rather than a false-clean density pass.

### Self-Test: Sign-Flow Pre-Rework Shape

The `--self-test` mode uses this fabricated lesson (mirrors the sign-flow degenerate state):
- 5 verses, last verse ends at 85s → density = 5/85 = **0.059 < 0.08 floor** → FLAGGED
- Verse 3: `start=15000, end=53000` → span = **38000ms > 15000ms max** → FLAGGED

Both flags must be raised for the self-test to exit 0 (SPEC-REQ-5 acceptance).

### Flags Emitted

| Kind | Condition |
|------|-----------|
| `density` | `verses.length / tvDurSec < 0.08` |
| `max-span` | `verse.end_time_ms - verse.start_time_ms > 15000` |
| `no-tv-duration` | last verse `end_time_ms === 0` |
| `no-verses` | `lesson.verses` is empty/missing |

### Modes

## Snapshot/Restore Design

### Snapshot Script

Reads `song_versions JOIN songs WHERE version_type='tv'` and writes `[{slug, lesson}]` to `tv-lessons-pre-rework-snapshot.json` in the phase directory. The `slug` field is on the `songs` table (not `song_versions`), so the join is required.

The file is committed to git per D-09 (`.planning/` is not covered by the `data/` gitignore).

### Restore Script

Mirrors the `10c-load-tv-lessons.ts` WHERE clause exactly:
```sql
UPDATE song_versions
SET lesson = ?, updated_at = NOW()
WHERE song_id = (SELECT id FROM songs WHERE slug = ?)
  AND version_type = 'tv'
```

In code:
```typescript
.update(songVersions)
.set({ lesson: row.lesson, updated_at: new Date() })
.where(and(eq(songVersions.song_id, songId), eq(songVersions.version_type, "tv")))
```

The `song_id` is resolved from a pre-loaded `Map<slug → song_id>` (single SELECT upfront) rather than a per-row subquery.

**ASVS L1 validation:** `validateSnapshot()` checks every row for `{slug: string, lesson: any}` shape before any DB write is attempted.

**Default behavior:** DRY RUN. Prints planned UPDATE count + slug list. `--confirm` is the only path to writes. This satisfies T-11.2-08 (tamper threat mitigation).
