Create `scripts/seed/spot-check-tv-onsets.ts` — a CLI that takes a slug (or `--all-spot-check`) and prints per-verse onset deltas + a per-song verdict.

**Header:**
```ts
/**
 * spot-check-tv-onsets.ts — SPEC-REQ-4 validation gate.
 *
 * For a given TV slug, compares each verse's `start_time_ms` (in
 * data/lessons-cache-tv-nw/{slug}.json) against the WhisperX word.start time
 * of the verse's first matched character on the Demucs stem
 * (data/timing-cache-tv-stem/{slug}.json).
 *
 * Pass criterion (per SPEC.md): every verse's delta within ±500ms of audio onset.
 *
 * Skipped: verses with start_time_ms === 0 (low-coverage emission — the deriver
 * explicitly claimed no TV timing for this verse).
 */
```

**Argparse:**
- `--slug X` for a single song
- `--slugs X,Y,Z` for the 8-song spot-check batch
- `--tolerance-ms N` (default 500 per SPEC.md)
- `--lessons-dir D` (default `data/lessons-cache-tv-nw`; allows pointing at a tuning copy)

**Algorithm per slug (mirrors NW char-stream construction in 10b-nw):**

1. Load lesson JSON from `{lessonsDir}/{slug}.json`.
2. Load stem timing from `data/timing-cache-tv-stem/{slug}.json`.
3. Build the same `streamA` (full-lesson romaji with verse-boundary markers) and `streamB` (TV-stem romaji + per-char time index) that 10b-nw built. **Reuse the helpers**: import `normRomaji` and `tokenAlignText` from `10b-derive-tv-lessons-nw.ts` (they were copied verbatim from old 10b per Plan 02 D-02).
4. Re-run NW alignment (or expose 10b-nw's alignment as a callable from the script — the cleaner option). Compute per-verse first-matched-char time `predicted_audio_onset_ms`.
5. For each verse:
   - If `verse.start_time_ms === 0`: report `[SKIP] verse {n} — no TV claim`.
   - Else: `delta = verse.start_time_ms - predicted_audio_onset_ms`. Status = `PASS` if `|delta| <= tolerance` else `FAIL`.

**Output format (markdown table — designed to paste into SPOT-CHECK-REPORT.md):**
```
## sign-flow (JLPT N3)

| Verse | lesson.start_time_ms | predicted_onset_ms | delta_ms | status |
|-------|----------------------|--------------------|----------|--------|
| 1 | 6700 | 6800 | -100 | PASS |
| 2 | 13200 | 12950 | +250 | PASS |
| 3 | 24500 | 25100 | -600 | FAIL |
| 4 | ... | ... | ... | ... |
| 5 | ... | ... | ... | ... |

VERDICT: 1 verse fails (verse 3); spot-check FAILS for sign-flow.
```

**Exit code:** 0 if all verses across all slugs pass; non-zero if any verse fails.

**Do NOT introduce new alignment logic** — reuse what Plan 02 already built. The point of this tool is to verify, not realign.

**Write 4 unit tests per `<behavior>`.** Tests use synthetic lesson + stem JSONs (no real catalog data needed) so they run in milliseconds.
