## NW Core Design

### Algorithm

Standard O(N×M) Needleman-Wunsch global alignment with Int32Array DP table:
- `match = +2`, `mismatch = -1`, `gap = -1`
- Traceback produces `{aIndex, bIndex, type}` per alignment position
- `aIndex = null` for gap-a entries; `bIndex = null` for gap-b entries

### Stream Construction

**streamA (full lesson):** For each verse, append `tokenAlignText(tok)` for each token, then `VERSE_BOUNDARY_MARKER` (U+0001). Track `verseRanges[{verseNumber, charStart, charEnd}]` in streamA positions.

**streamB (TV-stem):** Concatenate all `word.text` strings from `data/timing-cache-tv-stem/{slug}.json`, romanize with `toHepburnRomaji`, then `normRomaji`.

**TV time index:** For each word, map each char to `word.start` ms, except the last char which maps to `word.end`. This gives tighter verse end times when the last matched char lands at a word boundary.

### Per-Verse Projection

For each `verseRange` in streamA:
1. Count matched chars (`aToB.get(ai)` hits) in range `[charStart, charEnd]`
2. Compute `coverage = matchedChars / verseLengthChars`
3. If `coverage < 0.40`: skip verse (no TV timing claim)
4. If `coverage >= 0.40`: `startMs = tvCharToStartMs[firstMatch.bIndex]`, `endMs = tvCharToEndMs[lastMatch.bIndex]`

### Gap-Midpoint Expansion

`computeVerseTimes(rawSpans, tvFirstWordStartMs)` — preserved verbatim from LCS predecessor:
- Clamps first verse start to TV audio's first word
- For each adjacent pair, sets `endMs[i] = startMs[i+1] = midpoint`
- Adds 1000ms sustain buffer to last verse

## TV Time Interpolation Strategy

Per-char mapping using `word.start` for intermediate chars and `word.end` for the last char of each word. Rationale: when NW selects the last char of a word as a verse boundary match, using `word.end` gives a more accurate `endMs` than reusing `word.start`. The Plan 06 spot-check (±500ms tolerance) will validate this choice.

## Verse Presence Threshold Behavior (Low-Coverage)

Verses below VERSE_PRESENCE_THRESHOLD (0.40 = 40%) are excluded entirely from the TV lesson. This avoids:
- Zero-timing verses (`start_time_ms=0, end_time_ms=0`) that break the monotonic invariant
- Polluting the lesson with verses the TV cut doesn't contain

The exclusion approach differs from the plan's suggestion of "emit with zero timing" — emitting zeroed verses would fail the monotonic check and confuse the downstream `LyricsPanel` component. The SPEC-REQ-2 goal of "no [no_detected_verses] outputs" is met for any song with at least one verse above threshold.
