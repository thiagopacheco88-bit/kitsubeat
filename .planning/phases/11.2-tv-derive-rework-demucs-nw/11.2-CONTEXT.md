<decisions>
## Implementation Decisions

### Pipeline script shape

- **D-01:** TV Demucs+WhisperX pipeline ships as NEW files mirroring the `ab-*` pair shape (positional slugs, idempotent skip-if-exists, importlib-loaded `04-extract-timing.py` runtime):
  - `scripts/seed/tv-demucs-isolate.py` — yt-dlp → htdemucs (`data/audio-tv/{slug}.mp3` → `data/vocal-stems-tv/htdemucs/{slug}/vocals.wav`)
  - `scripts/seed/tv-transcribe-stems.py` — WhisperX large-v3 ja against the stem (`data/timing-cache-tv-stem/{slug}.json`); reuses `run_whisperx()` and `write_timing_json()` from `04-extract-timing.py` via importlib (same pattern as `ab-transcribe-stems.py`)
  - `PYTHONIOENCODING=utf-8` mandatory on the transcribe step; `.venv/Scripts` must be on PATH (per memory: WhisperX fails with WinError 2 at `load_audio` otherwise)
- **D-02:** New NW derive script = `scripts/seed/10b-derive-tv-lessons-nw.ts`. Old LCS script moved to `scripts/seed/_attic/10b-derive-tv-lessons-lcs.ts`. The windowed-LCS dead-end `10b2-derive-tv-monotonic.ts` also goes to `_attic/`. The new script reuses `normRomaji`, `tokenAlignText`, kuroshiro setup, and gap-midpoint expansion from the LCS version — only the alignment core changes (per-verse LCS → global NW with verse-boundary markers in the full-lesson stream).
- **D-03:** Audit script = `scripts/seed/audit-tv-lessons.ts` (matches existing `audit-catalog.ts`, `audit-lesson-coverage.ts`, `audit-corrupted-lyrics.ts` naming).

### Straggler triage

- **D-04:** Pre-fix mountain-a-go-go's full-version lesson BEFORE running the NW catalog. The TV failure is upstream (full-lesson tokens were generated as romaji, not Japanese kanji/kana — guaranteed 0% NW overlap regardless of algorithm). Regenerate via the existing `03-generate-content.ts` flow forcing JP tokens; then NW handles the song like any other. The other 3 stragglers (`my-answer-seamo`, `newsong-tacica`, `whats-up-people-maximum-the-hormone`) go through the new pipeline as normal songs and get triaged based on outcome.
- **D-05:** Per-song fallback ladder for straggler failures and post-rollout regressions:
  - **Step 0 (vocals-absent fast-path):** Inspect the WhisperX stem transcript. If the TV cut has no usable Japanese vocals (silence, credits voiceover, karaoke instrumental, English-only screaming) — skip to Step 3 directly. Examples from the existing todo: `newsong-tacica` (transcript = "ご視聴ありがとうございました" outro voiceover); a TV cut whose `youtube_id` points to a karaoke track.
  - **Step 1:** Attempt YouTube replacement using the existing `find-youtube-replacements.ts` / `find-live-replacements.ts` pattern. Re-run the new TV pipeline on the replacement.
  - **Step 2:** Hand-curate via segment-anchor projection (model after `scripts/debug/rebuild-sign-flow-tv.ts` — generalize into `scripts/seed/lib/segment-anchor.ts` if more than one straggler needs it).
  - **Step 3:** `DELETE FROM song_versions WHERE version_type='tv' AND song_id=...` with rationale logged in phase artifacts. The frontend hides the TV/Full toggle naturally when only one version exists for a song (verify `SongContent.tsx` handles this; add guard if needed).

### Spot-check selection + audit thresholds

- **D-06:** Spot-check song selection = **adversarial**: songs known to stress alignment — chorus-repetition heavy, fast vocals, kanji/kana mix, mid-song English bridges. **Sign-flow MUST be in the set** as the trigger case for the phase. 2 songs per JLPT level (N5/N4/N3/N2). Specific 8 slugs picked at plan-phase or execute-phase (not locked here — depends on which songs surface as adversarial).
- **D-07:** Audit thresholds (locked in code in `audit-tv-lessons.ts`):
  - Density floor: `verses.length / tv_duration_seconds < 0.08` flags the lesson. (Sign-flow's broken state was 5/85 ≈ 0.059 — flagged. A typical 8-verse 90s anime OP = 0.089 — passes.)
  - Max-span: any single verse where `(end_time_ms - start_time_ms) > 15_000` flags the lesson.
  - TV duration source: prefer last verse's `end_time_ms` from the lesson; fall back to last word's `end` in `data/timing-cache-tv-stem/{slug}.json`. Plan-phase decides which is canonical.
  - Audit input: read `song_versions.lesson` from DB (`version_type='tv'`) — flags what users actually see, not on-disk staging files. (Optional second mode against on-disk files is Claude's discretion.)

### Rollout + rollback

- **D-08:** Catalog rollout uses **parallel directory, diff-and-promote**:
  1. New NW derive writes to `data/lessons-cache-tv-nw/` (NEW dir, distinct from `data/lessons-cache-tv/`).
  2. Audit + 8-song spot-check run against the parallel directory contents.
  3. Spot-check passes → rename swap: `mv data/lessons-cache-tv data/lessons-cache-tv-pre-rework && mv data/lessons-cache-tv-nw data/lessons-cache-tv`.
  4. Run unmodified `10c-load-tv-lessons.ts` to push the swapped canonical directory to Neon.
- **D-09:** Pre-rollout snapshot taken BEFORE step 4 of D-08:
  - Dump `SELECT slug, lesson FROM song_versions WHERE version_type='tv'` to `.planning/phases/11.2-tv-derive-rework-demucs-nw/tv-lessons-pre-rework-snapshot.json`. **This file IS committed to git** (the `data/` gitignore does not cover `.planning/`).
  - Restore script: small `restore-tv-lessons-from-snapshot.ts` in the same phase dir, reads the JSON, rewrites `song_versions.lesson` rows.
- **D-10:** Post-rollout regression handling = **fix-forward by default**:
  - If a song regresses (audit catches it OR user reports off highlights), rerun the new pipeline on that one slug (`tv-demucs-isolate.py {slug} → tv-transcribe-stems.py {slug} → 10b-derive-tv-lessons-nw.ts --slug {slug} → 10c-load-tv-lessons.ts --slug {slug}`).
  - Demucs stems are deterministic given the same audio; the pipeline is idempotent. Snapshot-based rollback (D-09) is the escape hatch for systemic problems (e.g., NW algorithm regression affecting many songs).

### Claude's Discretion

- **NW scoring tuning:** Start with uniform char weights (`match=+2`, `mismatch=-1`, `gap=-1`) per SPEC. Only escalate to vowel/consonant/coda phoneme-class weights if the 8-song spot-check uncovers systematic failure on a specific song. Don't pre-build the phoneme-class layer.
- **Audit run mode:** DB-mode (against `song_versions.lesson`) is the canonical mode. An optional `--from-disk` flag for running against `data/lessons-cache-tv/` files during pipeline development is welcome but not required.
- **Segment-anchor utility extraction:** If exactly one straggler needs hand-curation, keep the logic inline in a phase-specific debug script. If two or more, extract into `scripts/seed/lib/segment-anchor.ts`. Decide during execute-phase based on actual straggler outcomes.
- **WhisperX batch size:** Default to 16 per `ab-transcribe-stems.py`; lower if RAM-constrained on the local machine doing the 60-song batch.
- **TV duration source for audit (lesson vs. stem timing):** Either is acceptable; pick whichever is simpler to compute and consistent.

<specifics>
## Specific Ideas

- **Sign-flow is the trigger case** for this phase and MUST be one of the 8 spot-check songs at its JLPT level.
- **Audit script lives beyond this phase** — its design intent is regression prevention. Consider running it post-deploy as part of any TV-touching workflow (could become a CI gate or a `npm run audit:tv` script in `package.json`).
- **NW pseudocode hint:** monotonic global alignment over the concatenated full-lesson romaji stream (with verse-boundary marker chars) and the TV-stem WhisperX romaji stream. Per-verse `tv_start` / `tv_end` fall out of the alignment naturally — for each verse, `tv_start` = TV-time of the first matched char in the verse's region, `tv_end` = TV-time of the last matched char. Existing gap-midpoint expansion logic (10b's `computeVerseTimes`) tightens inter-verse boundaries.
- **Post-rollout, run the audit one more time against production DB** as a final gate before declaring the phase complete (acceptance criterion in SPEC.md).

</specifics>
