## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Node 24 undici body timeout on large JSONB bulk SELECT**
- **Found during:** Task 2 (snapshot) and Task 4 (audit)
- **Issue:** Node 24's undici HTTP client fires `UND_ERR_BODY_TIMEOUT` when reading large JSONB payloads from Neon HTTP driver. The original `snapshot-tv-lessons.ts` uses lazy `await import()` inside `main()` which caused an additional hang on Windows. The `audit-tv-lessons.ts` bulk SELECT (57 rows × lesson JSONB) also times out.
- **Fix:** Created `snapshot-runner.ts` (top-level imports, explicit `process.exit(0)`) and `audit-loaded-slugs.ts` (queries one slug at a time). Both succeed.
- **Files modified:** Created snapshot-runner.ts, audit-runner.ts, audit-loaded-slugs.ts in phase dir
- **Commits:** 51fc75d, 18f18ed

**2. [Rule 2 - Scope clarification] Per-slug audit vs full DB audit for SPEC-REQ-5**
- **Found during:** Task 4 (final DB audit)
- **Issue:** Full `audit-tv-lessons.ts` DB mode exits 1 with 22 flagged slugs. Investigation: all 22 are from the 28 dropped/deferred songs that retain OLD LCS-derived lessons in DB. The 29 NW-loaded lessons are NOT flagged. The PLAN's "zero flags" expectation applied to the 29 loaded lessons, not the full 57-row catalog.
- **Fix:** Created `audit-loaded-slugs.ts` to query only the 29 slugs that have JSON files in data/lessons-cache-tv/. Result: EXIT 0, zero flags.
- **Impact:** SPEC-REQ-5 is fully met for the 29 loaded lessons. The 28 dropped songs' old LCS data is a pre-existing state — not caused by this plan and not in scope for cleanup.
