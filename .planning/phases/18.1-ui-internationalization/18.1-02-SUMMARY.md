## What Was Built

### next.config.ts — Build Chain Update

Added `createNextIntlPlugin` import and `withNextIntl` wrapper. The final export is now:
`withSentryConfig(enableAnalyzer(withNextIntl(nextConfig)), {...})` — Sentry stays outermost, analyzer stays second, withNextIntl wraps the base config. Also added `"/**": ["./src/messages/**/*.json"]` to `outputFileTracingIncludes` to prevent Vercel from missing dynamically imported locale JSON files on cold starts.

### src/middleware.ts — Middleware Chain

Added `createIntlMiddleware` and `routing` imports. Created `intlMiddleware = createIntlMiddleware(routing)` instance at module level. Added `return intlMiddleware(req)` as the final line inside the `clerkMiddleware` callback — after the admin gate (which returns early with `return;` or `NextResponse.redirect`) and after the terms gate (which either redirects or falls through). Admin routes never reach `intlMiddleware`. All non-admin non-redirect routes now receive locale routing, Accept-Language detection, and `kb_locale` cookie management.

### src/app/[locale]/layout.tsx — Locale-Aware Layout

Created new locale-aware root layout for `/pt-BR/*` and `/es/*` routes:
- `generateStaticParams()` exports `routing.locales.map((locale) => ({ locale }))` for static rendering
- `params: Promise<{ locale: string }>` receives locale from URL segment
- `hasLocale(routing.locales, locale)` guard — calls `notFound()` on any value outside `['en','pt-BR','es']` (T-18.1-04 threat mitigation)
- `setRequestLocale(locale)` called before any `getTranslations()` — enables static rendering
- `<html lang={locale}>` — correct hreflang attribute for locale-prefixed routes
- `<NextIntlClientProvider>` wrapping `{children}` inside PageTransitionWrapper
- All existing cookie reads (kb_theme, kb_consent), auth/admin/gamification state logic preserved verbatim from root layout

### src/app/layout.tsx — Root Layout with Provider

Added `NextIntlClientProvider` and `getLocale` imports. Added `const locale = await getLocale()` before return. Wrapped `PageTransitionWrapper` (and `{children}`) with `<NextIntlClientProvider locale={locale}>`. This is the critical fix for `useTranslations()` on English routes (`/songs`, `/`, etc.) and admin routes (`/admin/*`) — those routes never pass through `[locale]/layout.tsx` so they need the provider here. Root layout does NOT use `setRequestLocale` or `hasLocale` — those belong only in the locale layout.

### src/app/actions/locale.ts — syncLocaleToClerk Server Action

`"use server"` action with:
- `VALID_LOCALES = ['en', 'pt-BR', 'es'] as const` — const assertion enables type narrowing
- Whitelist check before any Clerk API call — invalid locale causes immediate `return` (T-18.1-05 threat mitigation)
- `auth()` derives `userId` server-side — no caller-supplied ID (T-18.1-07 threat mitigation)
- Unauthenticated callers return early — `kb_locale` cookie drives routing without Clerk
- `updateUserMetadata` MERGES publicMetadata — `terms_version` key from onboarding.ts is not wiped
- Silent catch — Clerk sync failure does not block the user since cookie is the primary routing signal
