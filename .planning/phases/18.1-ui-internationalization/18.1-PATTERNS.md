**NOTE on safe merge (RESEARCH A2):** `updateUserMetadata` in Clerk MERGES publicMetadata keys (does not replace). Verified against Clerk v7 docs. The `terms_version` key set by `onboarding.ts` will NOT be wiped by a locale write. A read-then-merge is still recommended as a defensive pattern:
```typescript
"use server";
import { auth, clerkClient } from "@clerk/nextjs/server";

export async function syncLocaleToClerk(locale: string): Promise<void> {
  const VALID_LOCALES = ['en', 'pt-BR', 'es'] as const;
  if (!(VALID_LOCALES as readonly string[]).includes(locale)) return;

  const { userId } = await auth();
  if (!userId) return;  // Unauthed — kb_locale cookie is sufficient

  try {
    const client = await clerkClient();
    // updateUserMetadata merges publicMetadata — does not wipe existing keys
    await client.users.updateUserMetadata(userId, {
      publicMetadata: { locale },
    });
  } catch {
    // Fail silently — cookie drives routing, Clerk sync is background enhancement
  }
}
```

## Admin Routes Safety Note

**Source:** `src/middleware.ts` lines 18, 35–60; RESEARCH.md Pitfall 1 + Anti-Pattern 1
**Apply to:** ALL implementors of `src/app/[locale]/layout.tsx`

The `/admin/*` routes MUST NOT be placed inside `src/app/[locale]/`. They stay at `src/app/admin/`. The existing middleware admin gate runs an early `return;` before `intlMiddleware(req)` is called — admin routes never reach next-intl. Adding `/admin/*` under `[locale]` would make Next.js interpret `admin` as the locale param and call `hasLocale('admin')` → `notFound()`.
