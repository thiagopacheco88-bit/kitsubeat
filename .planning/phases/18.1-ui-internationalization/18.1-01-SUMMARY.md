## What Was Built

### next-intl Configuration (3 files)

`src/i18n/routing.ts` — defineRouting with locales `['en', 'pt-BR', 'es']`, defaultLocale `'en'`, `localePrefix: 'as-needed'` (EN stays at root), and `localeCookie: { name: 'kb_locale', maxAge: 31536000 }`.

`src/i18n/request.ts` — getRequestConfig that awaits requestLocale, validates against routing.locales via hasLocale(), then spread-merges all 6 namespace JSON files dynamically imported per locale.

`src/i18n/navigation.ts` — createNavigation exports: `Link`, `redirect`, `usePathname`, `useRouter`, `getPathname` — locale-aware drop-in replacements for Next.js navigation primitives.

### Message Files (18 files)

6 namespaces across 3 locales:
- `common` — nav labels, language names, skip link
- `songs` — page heading, subheading, filter labels, empty states
- `exercises` — session controls, exercise types, instructions, summary, premium upsell
- `journal` — heading, subheading, article metadata labels
- `settings` — profile, language, theme, account, data export labels
- `errors` — generic, not-found, locale switch failure, song/exercise-specific errors

EN strings are complete source-of-truth. PT-BR and ES are fully translated (not stubs) — Wave 4 translation pass is not needed for these strings.

### Wave 0 Test Stubs (4 files)

- `i18n-locale-routing.spec.ts` — 6 `test.skip` e2e tests covering PT-BR/ES/EN route rendering and hreflang headers (I18N-01/02/07)
- `i18n-language-picker.spec.ts` — 4 `test.skip` e2e tests covering globe button, dropdown, locale switch + cookie, keyboard dismiss (I18N-03)
- `articles-locale.test.ts` — 9 `it.todo` unit stubs for getArticlesByLocale + getArticleSourceByLocale (I18N-06)
- `SongGrid-language-filter.test.tsx` — 7 `it.todo` unit stubs for language filter chips (I18N-05)

All stubs exit without crash in vitest (9 todos confirmed).
