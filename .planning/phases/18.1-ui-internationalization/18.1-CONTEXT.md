# Phase 18.1: UI Internationalization — Context

**Gathered:** 2026-05-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Add PT-BR and ES UI language support to KitsuBeat using next-intl — locale routing, translation string extraction, language picker, preference persistence, song language filter, and journal article translations. The Japanese learning content itself (lyrics, furigana, grammar explanations) is not translated — it is the product. This phase covers the UI chrome and navigation layer.

</domain>

<decisions>
## Implementation Decisions

### Locale Routing
- **D-01:** Use **URL prefix routing** — `/pt-BR/songs`, `/es/songs`. English stays at the root `/` (no `/en/` prefix). next-intl default approach.
- **D-02:** English root `/` is canonical — existing indexed URLs stay intact with no forced redirects. PT-BR and ES get prefixed routes.
- **D-03:** Auto-detect locale from browser `Accept-Language` header on first visit. No language-picker modal on first load.

### Language Picker UX
- **D-04:** Globe icon dropdown in the **top nav bar** (3 options: English / Português-BR / Español) + accessible from **user profile/settings page**.
- **D-05:** Unauthenticated language switch → save to **cookie** + redirect to locale-prefixed URL (e.g., `/pt-BR/songs`). On authenticated signup, migrate cookie preference to **Clerk user metadata**.
- **D-06:** No language picker modal or prompt on first visit — auto-detect + always-visible nav picker is sufficient.

### Translation Scope
- **D-07:** **Full UI translated** — nav, buttons, error states, empty states, exercise instructions, feedback messages, onboarding text, settings labels. Everything a PT-BR or ES speaker sees as app interface.
- **D-08:** Japanese learning content is **explicitly excluded** — lyrics, furigana, grammar explanations, vocabulary entries stay in Japanese. These are the product, not UI chrome.
- **D-09:** Song language filter (wiring existing DB `language` column) is **included in this phase** — adds filter chip to songs page to show PT/EN/ES/JA songs.

### Journal Content Strategy
- **D-10:** Translate **all 28 existing English journal articles** to PT-BR and ES for maximum SEO benefit. Each locale gets its own MDX files in `src/content/journal/pt-BR/` and `src/content/journal/es/`.
- **D-11:** Translation method: **Claude Code inline**, one article at a time — no API cost, no batch script.
- **D-12:** On the journal listing page, user's locale language articles appear **first**, English articles appear below with an EN language badge. No filtering tabs needed.
- **D-13:** next-intl handles `hreflang` canonicals automatically — no duplicate-content SEO penalty.

### Preference Persistence
- **D-14:** Unauthed: locale in **cookie** (drives middleware routing). Authed: synced to **Clerk user metadata** (`publicMetadata.locale`). On login, cookie preference wins and is persisted to Clerk.

### Claude's Discretion
- Translation file structure and namespace organization (e.g., `common.json`, `exercises.json`, `journal.json`)
- Exact next-intl middleware configuration and cookie name
- String key naming conventions

</decisions>
