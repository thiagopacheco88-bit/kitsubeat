## What Shipped (Tasks 1-4)

### Task 1 — `scripts/seed/19-curate-vocab-images.ts` (commit `801f61d`)

**Exports:** `runCurate({ limit })`, `runVerify()`, `URL_PATTERN`, `TSV_PATH`.

- `runCurate`: queries `vocab_global` joined with `vocabulary_items`, filters POS to `('noun','verb')`, gates on `image_url IS NULL` for resume-safety, orders by appearance_count DESC, emits TSV at `data/vocab-images-staging.tsv`.
- `runVerify`: reads the TSV, queries DB per row, asserts `image_url` is non-null AND matches `URL_PATTERN`. Returns `{ok, populated, missing, invalid, total}` and exits 0/1 accordingly.
- `refreshVocabGlobal()` invoked at start (Pitfall 2 mitigation — frequency rank reflects current lesson content).
- Conditional-main pattern: file importable from tests without auto-running `main()`. Cross-platform path handling (Windows backslash + endsWith fallback).
- `URL_PATTERN = /^https:\/\/images\.unsplash\.com\/.+/` — exact regex per D-12.

### Task 2 — `scripts/seed/19b-load-vocab-images.ts` (commit `bf55af1`)

**Exports:** `runLoad({ tsvPath })`, `parseTsv(content)`.

- Reads TSV, validates each `image_url` against `URL_PATTERN` imported from the curate script (single source of truth — D-12 regex never duplicated).
- Per-row UPDATE without transaction wrapper — partial progress survives crashes. Re-runs are no-ops on rows where DB matches TSV (Postgres no-op for identical UPDATE per D-10).
- Empty `image_url` cells are silently skipped (operator-deferred rows).
- Logs `[invalid] {form} ({id}): URL does not match Unsplash CDN pattern: {url}` for rejected rows; final summary `[done] loaded=N skipped=M invalid=K total=T`.
- `parseTsv` extracted as pure function (testable without DB).

### Task 3 — `tests/integration/seed-19-curate-vocab-images.test.ts` (commit `7fd78e1`)

**Tests:** 3 cases under `describeIfTestDb` (skip-guard on `TEST_DATABASE_URL`).

1. `emits TSV with at most 50 rows and only noun/verb POS` — asserts row count ≤ 50 and 5th column ∈ `{noun, verb}` for every row.
2. `rows are sorted by frequency DESC` — re-queries `vocab_global` per emitted row, asserts non-increasing `appearance_count`.
3. `skips already-curated rows on re-run` — sets `image_url` on row #1, re-runs `runCurate`, asserts target ID absent from new TSV.

`beforeEach` wipes `vocabulary_items.image_url` (destructive, test DB only — skip-guard prevents production-DB targeting). `afterAll` deletes the TSV to keep workspace clean.

### Task 4 — `tests/integration/seed-19b-load-vocab-images.test.ts` extension (commit `a508c3b`)

Added 4 imports (`writeFileSync`, `unlinkSync`, `tmpdir`, `pathJoin`, `runLoad`) at module top; appended a second `describeIfTestDb` block ("runLoad() AC-8 invocation") with 3 cases:

5. `runLoad UPDATEs valid Unsplash URLs` — 2-row TSV, asserts `{loaded:2, skipped:0, invalid:0, total:2}` + DB rows updated.
6. `runLoad rejects non-Unsplash URLs` — 1-row TSV with `https://example.com/...`, asserts `{loaded:0, invalid:1}` + DB unchanged.
7. `runLoad skips rows with empty image_url` — mixed valid+empty TSV, asserts `{loaded:1, skipped:1}`.

Sentinel `dictionary_form` values `テスト_LOAD_A` / `テスト_LOAD_B` avoid catalog collisions; `afterAll` cleans up rows + temp TSV files. Original 4 Wave-0 tests untouched (verified via `git diff` additions-only).

**Total integration tests in `seed-19b-load-vocab-images.test.ts`: 4 (Wave 0) + 3 (this plan) = 7.**

### AI-image-generation pivot (operator decision)

**Operator stated intent: images will be generated by an AI session, not manually curated from Unsplash.** Plan 11.4-03 as designed does not fit this approach end-to-end. The future AI session must either (a) revise Plan 11.4-03 to support generated images, or (b) author a sibling plan (e.g. Plan 11.4-04) and leave 11.4-03 as the Unsplash-curation reference path for v4.0 rollout.

**Concrete deltas the AI-generation path needs to address:**

- **URL gate** — the `URL_PATTERN` constant in `scripts/seed/19-curate-vocab-images.ts` hard-gates `^https://images\.unsplash\.com/.+`. Generated images won't match. Either loosen the regex to whitelist the chosen CDN host, or replace `URL_PATTERN` with a CDN-agnostic URL-validity check.
- **Hosting target** — generated images need a CDN-accessible URL. Options: Cloudflare R2, AWS S3, Vercel Blob, Supabase Storage. Pick one and document the bucket/account/auth pattern in `.env.local`. Cost note: 50 images at ~200KB each is ~10MB — well within free tiers of all four. v4.0 (~1,409 images) is ~280MB — also free-tier on R2/Vercel Blob.
- **Loader flow** — the manual TSV step is unnecessary for AI generation. Replace with: `generate(vocab) → upload to CDN → UPDATE vocabulary_items.image_url = <cdn_url>`, all in one pass. The integration test surface (`tests/integration/seed-19-curate-vocab-images.test.ts` and `tests/integration/seed-19b-load-vocab-images.test.ts`) likely needs a rewrite for the new pipeline shape.
- **Generation prompt design** — the AI generator will need a per-vocab prompt that produces a meaning-matched image. Reference field: `vocab.meaning_en` (already populated for every row). Style guidance is wide open — the LearnCard/FeedbackPanel surfaces are square (1:1) per D-05, so request square output.
- **B-1 still applies** — whatever loader pattern the AI-generation pipeline uses, it MUST call `revalidateSongCache(slug)` after writes. Production cache staleness is not a curation-method-specific concern.
- **Threat-model delta** — generated-image hosting introduces a new trust boundary (CDN host's content). Plan 11.4-03's STRIDE register only covered the Unsplash-CDN path. The future plan should re-do the STRIDE pass for the chosen CDN.
