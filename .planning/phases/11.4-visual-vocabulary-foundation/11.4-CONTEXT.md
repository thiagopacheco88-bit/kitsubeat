<domain>
## Phase Boundary

Add `image_url` infrastructure to the `vocabulary_items` table and conditionally render images on the **LearnCard** (first-encounter just-in-time teach surface from Phase 08.4) and **FeedbackPanel "More" accordion** (post-answer surface from Phase 08.3) when an image URL is present. Curate **50 Unsplash CC0 images** for the top-frequency concrete vocab as the validation set.

Foundation only — full ~1,409-word rollout is deferred to v4.0. This phase ships the data column, the schema passthrough, the two render surfaces, and a 50-row curated dataset that proves the surface works end-to-end.

**Out of scope** (will not be done here):
- Bulk rollout beyond the 50 validation images
- Custom image hosting / Supabase storage mirror
- Cross-song image aggregation (e.g., "this image also appears for X")
- Per-image mastery or interaction tracking
- Image generation (DALL-E / Midjourney / Stable Diffusion) — Unsplash curation only
- New exercise types built around images (image→meaning, etc.) — surface is decorative for now

</domain>

## Implementation Decisions

### D-01: Storage column
- New nullable column `image_url text` on `vocabulary_items` table.
- Single text column — full URL stored as-is (e.g. `https://images.unsplash.com/photo-...`). No separate width/height/license columns; the URL embeds Unsplash CDN provenance and Unsplash's policy makes their CDN URLs CC0-implicit.
- Populated post-hoc by the curation loader; existing rows have `NULL` and render with no image.

### D-02: Migration numbering (corrected)
- Migration file: **`drizzle/0014_vocab_image_url.sql`**.
- WORKLOG.md draft said `0009_vocab_image_url.sql`, but `drizzle/0009_song_plays.sql` through `drizzle/0013_dual_source_lyrics.sql` are already shipped. Next free number is **0014**.
- ROADMAP success criterion #1 ("migration 0009 applied") is **superseded** by D-02 — planner uses 0014.

### D-03: Schema passthrough (Zod)
- `VocabEntrySchema` in `scripts/types/lesson.ts` gets an optional `image_url: z.string().url().optional()` (or `.nullable().optional()` matching the `kanji_breakdown` pattern). Optional so existing lessons without enrichment still validate.
- Field is **passthrough only** — generation prompt is NOT updated to ask Claude to invent image URLs (Unsplash curation lives outside the generation pipeline). The field exists on the schema so the FE can read it from the lesson JSONB if it is ever embedded there, but the canonical source remains the `vocabulary_items` row joined on `vocab_item_id`.

### D-04: Render surfaces (LOCKED)
- **LearnCard** (Phase 08.4 surface): image renders **above the kanji/furigana surface block** when present. Image is centered with fixed dimensions to prevent layout shift. Skeleton placeholder occupies the same dimensions while loading.
- **FeedbackPanel** (Phase 08.3 surface): image renders **inside the existing "More" accordion**, stacked **above the mnemonic block** when present. Both LearnCard and FeedbackPanel hide the image area entirely when `image_url` is null/absent.
- **Optional third surface**: `MasteryDetailPopover.tsx` — Claude's discretion (D-05 below).

### D-05: Image dimensions & aspect ratio
- **Aspect ratio: square (1:1)** across both surfaces.
  - Why: Anki Image Occlusion / WaniKani precedent. Neutral framing for both noun and verb subjects. Easy to enforce against Unsplash crop URL params.
- **LearnCard size**: ~220px centered max-width (fits indigo-card padding without dominating the kanji surface).
- **FeedbackPanel "More" accordion size**: ~120px thumbnail (secondary surface — leaves visual space for the mnemonic + kanji breakdown).
- **Skeleton dimensions match the rendered image** — fixed `width` + `height` attributes on `<img>` (or `aspect-square` Tailwind class on a wrapper div) so layout reserves space before the image loads. This is what satisfies success criterion #5 (no layout shift).

### D-06: Image rendering approach
- **Plain `<img loading="lazy">` element**, NOT `next/image`.
  - Why: Avoids `next.config.ts` `remotePatterns` whitelisting for `images.unsplash.com`. The 50-image validation set is too small to justify the Next.js image optimization pipeline.
  - Lazy loading is native browser behavior; sufficient for two off-screen-by-default surfaces (LearnCard appears JIT, FeedbackPanel image lives behind an accordion toggle).
  - If v4.0 expands to thousands of images and LCP becomes a concern, revisit and migrate to `next/image` then.

### D-07: Failure handling
- **Silent hide on error** — `onError` handler on the `<img>` element sets a local `imageFailed` state that collapses the image area entirely (no broken-image icon, no fallback placeholder).
- Image is **decorative** — a memory aid, not load-bearing UI. The card/panel must remain fully usable when image fails or is absent.
- Log `console.warn` once per failed URL with the vocab_item_id so a future audit script can surface dead URLs. No telemetry for v1.

### D-08: Alt text (LOCKED)
- `alt` attribute = English-resolved meaning string from `localize(vocab.meaning, 'en')`.
- Why English: most accessibility tooling expects English; the meaning field is already populated in EN for every row; matches success criterion #6 verbatim.
- Empty string is **not used** — every populated `image_url` row has a non-empty `meaning.en` because that's part of the existing vocabulary_items invariant.

### D-09: Curation criteria — what counts as "concrete"
- **Frequency-rank top 50** among rows where `part_of_speech` ∈ `{noun, verb}`.
  - Excluded POS values: `particle`, `expression`, `adverb`, `adjective`, `other`. Adjectives may be revisited later (e.g. red 赤い is imageable) but are excluded for the validation set to maximize hit rate.
  - Frequency = appearance count in `vocab_global` materialized view (already aggregates across song versions).
- The script emits a **suggested Unsplash search query** per row (typically the English meaning + "object" or "action" hint) to make operator curation faster.
- Operator can manually swap any of the 50 candidates if a frequency-ranked word turns out to be untranslatable visually — the staging-file workflow makes this trivial.

### D-10: Curation script flow — TSV staging + loader
- **Two-step pattern** mirroring `scripts/seed/11-enrich-vocab.ts`:
  1. Curate script (D-11) emits a TSV staging file: `data/vocab-images-staging.tsv` with columns `vocab_item_id | dictionary_form | reading | meaning_en | suggested_query | image_url`. Initial `image_url` column is empty.
  2. Operator fills `image_url` for each row by hand using Unsplash search.
  3. Loader script reads completed rows from the TSV and `UPDATE`s `vocabulary_items.image_url` per row, idempotent — re-running skips rows whose DB value already matches the TSV value.
- **Resume-friendly**: leaving the operator stage half-finished is fine. Re-running the loader picks up only the filled rows.

### D-11: Script numbering (corrected)
- Curate script: **`scripts/seed/19-curate-vocab-images.ts`**.
  - WORKLOG.md draft said `13-curate-vocab-images.ts`, but `13-dedup-grammar-rules.ts`, `13-fetch-anime-metadata.ts`, `14-seed-reward-slots.ts`, `14-semantic-merge-grammar-rules.ts`, `15-split-oversized-verses.ts`, `16-filter-live-versions.ts`, `17-find-live-replacements.ts`, `18-apply-live-replacements.ts` are taken. Next free integer is **19**.
- Loader script: **`scripts/seed/19b-load-vocab-images.ts`** (sub-letter pattern matches `01b-`, `03b-`, `04b-` precedent).
- ROADMAP success criterion #7 (`scripts/seed/13-curate-vocab-images.ts`) is **superseded** by D-11 — planner uses 19/19b.

### D-12: QA gate — validation strategy
- **URL pattern regex** in the loader: rejects any non-Unsplash URL at insert time. Pattern: `^https://images\.unsplash\.com/.+` (CC0 license enforcement is a function of the host — the Unsplash CDN host implies their license policy).
- **Operator eyeball pass**: after the 50 rows load, operator opens a debug route or runs a one-off script that queries the 50 image URLs and writes a static HTML preview file for visual sign-off. No automated subject-vs-meaning check (LLM vision-check is out of scope for the 50-image validation).
- **DB-level audit**: re-run the curate script in `--verify` mode after load — assert that all 50 target rows have a populated `image_url` and the URL passes the regex.

### D-13: Hosting (LOCKED — from WORKLOG)
- **Direct Unsplash CDN URLs**, no Supabase storage mirror, no local CDN proxy.
  - Why: 50-image validation set; Unsplash CDN reliability is sufficient; mirroring adds storage/refresh complexity that v4.0 rollout (~1,409 images) can decide on if needed. License-wise, hot-linking to `images.unsplash.com` is what Unsplash's API license explicitly permits.

### D-14: Plan structure (LOCKED — from WORKLOG)
- **3 plans**, ~4h total, mapped to acceptance criteria:
  - **11.4-01 (~1h)**: Schema migration `0014_vocab_image_url.sql` + Drizzle schema field + `VocabEntrySchema` passthrough field. Covers AC #1, #2.
  - **11.4-02 (~1.5h)**: UI integration in `LearnCard.tsx` + `FeedbackPanel.tsx` (with optional `MasteryDetailPopover.tsx`). Skeleton dimensions, `<img loading="lazy">`, `onError` silent hide, `alt={localize(meaning,'en')}`. Covers AC #3, #4, #5, #6.
  - **11.4-03 (~1-2h)**: `scripts/seed/19-curate-vocab-images.ts` curate + `19b-load-vocab-images.ts` loader + 50-image staging fill + DB load + verify pass. Covers AC #7, #8.

### Claude's Discretion
- **`MasteryDetailPopover.tsx`** as a third surface — opportunistic addition. If reuse fits naturally (popover already renders a vocab thumbnail-style header), include it; otherwise skip. ROADMAP success criteria do NOT require it.
- **Skeleton visual style** — solid neutral fill, shimmer animation, or simple bordered box — pick what matches the rest of the app's loading visual language (no spinner inside the skeleton — too noisy on a small thumbnail).
- **Concrete `width`/`height` numerics** — D-05 sets ~220px and ~120px as guidance; planner can land on exact values that snap to the existing Tailwind spacing scale (e.g., `w-56 h-56` and `w-28 h-28`).
- **Suggested Unsplash search query string** — D-09 suggests "meaning + object/action hint"; exact wording is a curation-quality call.
- **Whether to add a `data-testid` for image presence** — Phase 08.1 Playwright suite does not currently spec image presence; if a regression test makes sense at write time, add one.

<specifics>
## Specific Ideas

- The image is a **decorative learning aid**, not a primary content surface. Treat absence as the default rendering case; presence is a bonus signal. This shapes D-07 (silent failure) and D-04 (hide image area entirely when null).
- The 50-image validation set exists to **prove the surface works end-to-end** before committing engineering effort to a 1,409-word rollout in v4.0. Spend curation time on the 50 with highest learner-impact: the most-frequent concrete nouns and verbs across the catalog.
- **Picture-superiority effect on recall** is the underlying user-facing thesis (per WORKLOG.md). The phase doesn't measure it — measurement is a v4.0 concern after the rollout. Phase 11.4 just unblocks the validation surface.

</specifics>
