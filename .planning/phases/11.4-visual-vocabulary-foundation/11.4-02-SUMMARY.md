## Decisions Made

- **D-08 honored, in code:** `meaning_en` is derived inside the page.tsx `.map()` merge via `localize(entry.meaning as Localizable, 'en')`. The Question type carries it as a peer field; LearnCard uses `meaning_en ?? meaningText` (the localized prop), and FeedbackPanel uses `meaning_en ?? ""` (decorative-image fallback). No new DB column was added — single source of truth remains `vocabulary_items.meaning` plus `localize()`.
- **D-07 honored, in code:** both surfaces wire an `onError` handler that emits a `console.warn` with the URL + `vocabItemId`, then flips a local `imageFailed` flag. The conditional render checks `image_url && !imageFailed`, so the image area collapses cleanly without showing a broken-image icon.
- **D-04 ordering enforced and tested:** the FeedbackPanel image is the literal first JSX child of the accordion body. The unit test asserts `img.compareDocumentPosition(memoryTipLabel) & DOCUMENT_POSITION_FOLLOWING` to make the ordering machine-checkable.
- **Pitfall 4 enforced and tested:** the `<img>` carries no `onClick` prop, no inline `onClick` attribute, and the wrapping `<div>` carries none either. The third LearnCard test asserts `img.onclick === null`.
- **Pitfall 3 enforced:** width/height are emitted as numeric JSX expressions (`{224}`, `{112}`) — not strings, not omitted. Tests assert `getAttribute("width") === "224"` (the rendered HTML attribute serializes back to a string, but the upstream prop is numeric).
- **Test fixture disambiguation:** the FeedbackPanel DOM-order test uses `screen.getByText("Memory tip")` (exact, case-sensitive) instead of the regex `/memory tip/i` because the localized mnemonic body in the test fixture happens to share the same text as the label, which made the regex match two elements. The exact-match is sufficient because the literal label string never changes.

## Post-verification Deviation: D-04 amendment

**Title:** FeedbackPanel image promoted out of "More" accordion to top-level (UAT-driven).

**Original D-04 lock (CONTEXT 2026-04-2x):** image renders inside the "More" accordion, before the mnemonic block.

**Amended D-04 (CONTEXT 2026-05-01):** image renders at the top of the FeedbackPanel body, immediately after the "Correct! / Not quite" status header and before the vocab block. Mnemonic, kanji breakdown, and detailed explanation remain inside the "More" accordion. `hasMoreContent` no longer counts `image_url`, so an image-only question shows no "More" button.

**Why:** discoverability. UAT confirmed that the accordion-only placement effectively hid the image — even motivated operator testing missed it across ten questions in a row. Promoting the image to top-level matches the LearnCard's prominence and makes the visual learning aid actually surface during exercises (which is the entire point of Phase 11.4).

**Files modified by the amendment:**
- `src/app/songs/[slug]/components/FeedbackPanel.tsx` — moved the conditional `<img>` block from inside `data-testid="feedback-more-accordion"` to immediately after the status-header `<div>`. Removed `!!question.image_url` from `hasMoreContent`.
- `src/app/songs/[slug]/components/__tests__/FeedbackPanel.test.tsx` — updated test 1 to assert image is at top-level (not inside the accordion); test 2 (omit-when-absent) and test 3 (image-precedes-mnemonic in DOM order) unchanged in spirit and still pass. All 3/3 green post-amendment.
- `.planning/phases/11.4-visual-vocabulary-foundation/11.4-CONTEXT.md` — D-04 section header marked "LOCKED — AMENDED 2026-05-01" and the amendment is appended as an inline blockquote under the bullet list.
