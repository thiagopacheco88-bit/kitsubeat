## Summary

This research is scoped narrowly: CONTEXT.md D-01 through D-14 already lock the architecture. The planner's gaps are all *concrete code shapes* — exact migration command, exact Drizzle query for top-50 frequency, exact `<img>` HTML attributes for CLS, exact merge point for `image_url` in the page-level enrichment join, and exact precedent for the TSV-staged loader.

The most important non-obvious finding: **`vocabulary_items.mnemonic` and `kanji_breakdown` are NOT stored in the lesson JSONB** — they live in the `vocabulary_items` table only and are merged into the lesson at request time by `src/app/songs/[slug]/page.tsx` via a single batched `inArray` `SELECT`. Plan 11.4-02 must extend that exact merge to carry `image_url` (not the lesson backfill route). The lesson generation pipeline does not change.

**Primary recommendation:** Extend `src/app/songs/[slug]/page.tsx` lines 47-87 by adding `image_url: vocabularyItems.image_url` to the enrichment SELECT and merging it into each `VocabEntry` exactly as `mnemonic` and `kanji_breakdown` are. The `Question` type gets one new optional field. Both render surfaces become a 6-line conditional `<img>` block. The curate/load script pair mirrors `scripts/seed/11-enrich-vocab.ts` row-by-row idempotency, but with a TSV staging step (operator fills `image_url` cell), distinct from 11-enrich-vocab's inline-LLM pattern.

### Pattern 6: vocab_global frequency-rank query

**What:** Group `vocab_global` rows by `vocab_item_id`, COUNT, JOIN `vocabulary_items` for POS filter, ORDER BY count DESC, LIMIT 50.

**Concrete query (Drizzle SQL template — for `19-curate-vocab-images.ts`):**
```typescript
// scripts/seed/19-curate-vocab-images.ts
import { sql } from "drizzle-orm";
import { getDb } from "../../src/lib/db/index.js";

interface FrequencyRow {
  vocab_item_id: string;
  dictionary_form: string;
  reading: string;
  romaji: string;
  meaning: unknown;          // jsonb — Localizable shape
  part_of_speech: string;
  jlpt_level: string | null;
  appearance_count: number;
}

const db = getDb();
const rows = await db.execute<FrequencyRow>(sql`
  SELECT
    vi.id            AS vocab_item_id,
    vi.dictionary_form,
    vi.reading,
    vi.romaji,
    vi.meaning,
    vi.part_of_speech,
    vi.jlpt_level::text AS jlpt_level,
    COUNT(*)::int    AS appearance_count
  FROM vocab_global vg
  JOIN vocabulary_items vi ON vi.id = vg.vocab_item_id
  WHERE vi.part_of_speech IN ('noun', 'verb')
    AND vi.image_url IS NULL                 -- skip already-curated rows on re-run
  GROUP BY vi.id, vi.dictionary_form, vi.reading, vi.romaji, vi.meaning, vi.part_of_speech, vi.jlpt_level
  ORDER BY appearance_count DESC, vi.dictionary_form ASC
  LIMIT 50
`);

const raw = Array.isArray(rows) ? rows : (rows.rows ?? []);  // Neon vs node-pg shape
```

**Gotchas:**
- `vocab_global` has one row per `(vocab_item_id, song_id, version_type)`. A song with both tv+full versions counts a vocab item TWICE in this raw count — that is the documented behavior of the view (see `src/lib/db/queries.ts:594-595` "Pitfall 2"). For frequency-rank purposes this is **acceptable** because tv+full both expose the word to learners. If we wanted DISTINCT-by-song, add `COUNT(DISTINCT vg.song_id)` instead. **Recommend keeping `COUNT(*)` because the rank is approximate by nature for a 50-image validation set.** [VERIFIED: src/lib/db/queries.ts:594-595]
- `vocab_global` is a **materialized view** — freshness depends on `refreshVocabGlobal()` being called. The view is refreshed on song update via `refreshVocabGlobal()` in `queries.ts:305-322`. As of phase research date the catalog is stable and recent migrations did not touch lesson content; the view should be current. **Recommend Plan 11.4-03 invokes `refreshVocabGlobal()` once at script start as a defensive measure** — it is concurrent-safe (won't block reads) and adds <1s on this catalog size. [VERIFIED: queries.ts:305-322]
- `vocabulary_items.romaji` IS a column (NOT NULL per schema) [VERIFIED: schema.ts:166]; safe to SELECT.
- `meaning` is `jsonb` (Localizable shape `{en: "...", "pt-BR": "...", ...}`) — drizzle returns it as `unknown`; cast on read.
- The `WHERE vi.image_url IS NULL` clause is the resume predicate — re-running the curate script after some rows are loaded skips them and picks the next 50 in rank. This is the cleanest analog of `11-enrich-vocab.ts`'s `isNull(vocabularyItems.mnemonic)` skip gate.

**Source:** [VERIFIED: schema.ts:160-187 column shape; schema.ts:540-569 view definition; queries.ts:305-322 refresh helper; queries.ts:594 Pitfall 2 doc]

### Pattern 7: TSV staging — exact format

**Existing precedent:** `scripts/seed/11-enrich-vocab.ts` does NOT use TSV — it does inline-LLM per-row updates. There is no exact "TSV staging" precedent to copy verbatim. The closest analog is the operator-fill-then-load workflow described in CONTEXT D-10. **The TSV format is therefore a new convention; the planner sets it.**

Recommend the format used by `data/vocab-images-staging.tsv`:
```
# vocab_item_id	dictionary_form	reading	meaning_en	part_of_speech	suggested_query	image_url
4f2a...e1	水	みず	water	noun	water (object)
8c1b...d3	食べる	たべる	to eat	verb	eat (action)
```

**Conventions:**
- TAB-separated (not CSV — meanings often contain commas).
- First line is a `# ` comment header for operator readability; loader skips lines starting with `#`.
- Operator fills the empty 7th column (`image_url`) by hand, leaves blank to defer.
- Loader reads each row; `image_url` empty/whitespace = skip (resume-friendly).
- All other fields are read-only — operator does NOT edit them.
- Encoding: UTF-8 (Japanese text in `dictionary_form` and `reading`).

**Loader idempotency:**
- Loader reads the row, splits on TAB, validates `image_url` matches `^https://images\.unsplash\.com/.+`, then UPDATEs `vocabulary_items.image_url` keyed by `vocab_item_id`.

## Common Pitfalls

### Pitfall 1: Migration number drift
**What goes wrong:** Generating `0014_*.sql` against an out-of-date local DB produces a sequential number that conflicts with another developer's pending migration.
**Why it happens:** Drizzle Kit picks the next free integer based on `drizzle/meta/_journal.json`, not the database state.
**How to avoid:** Before `npm run db:generate`, run `git pull` and `ls drizzle/*.sql | tail -1` to confirm 0013 is still the highest. CONTEXT D-02 already acknowledges this risk.
**Warning signs:** `drizzle/meta/_journal.json` shows entries other than 0013 as the latest; remote tip has migrations 0014-001x already.

### Pitfall 2: vocab_global stale frequency
**What goes wrong:** Top-50 selection ranks a word that no longer appears (e.g., a song was just deleted).
**Why it happens:** Materialized view refresh is on song update, not on schema change. Phase work that doesn't touch songs leaves freshness up to chance.
**How to avoid:** Plan 11.4-03 invokes `refreshVocabGlobal()` once at script start (CONCURRENTLY-safe per `queries.ts:307`). Adds <1s.
**Warning signs:** Curated word doesn't appear in any rendered LearnCard during smoke test.

### Pitfall 3: Layout shift despite Tailwind classes
**What goes wrong:** Image renders, then the surrounding content jumps as the browser re-flows.
**Why it happens:** `aspect-square` + `w-56` only sets CSS aspect-ratio + width; without HTML `width`/`height` attrs the browser may not reserve box space until image bytes arrive.
**How to avoid:** Always set `width={224}` and `height={224}` as HTML attrs (numbers, not strings) on the `<img>` element. The numbers must match the rendered px size (224 = `w-56` at 16px root). Same for FeedbackPanel: `width={112} height={112}` for `w-28 h-28`.
**Warning signs:** Visual jolt when scrolling to the LearnCard; CLS > 0.1 in Lighthouse.

### Pitfall 4: Image click swallows tap-to-dismiss
**What goes wrong:** User taps image to read more; LearnCard does not dismiss.
**Why it happens:** Adding `onClick` to the `<img>` (or any wrapper around it) shadows the outer `onClick={onDismiss}` at LearnCard.tsx:49. Or `e.stopPropagation()` on the image's `onError` accidentally also fires on click.
**How to avoid:** The image element receives ONLY `src`, `alt`, `width`, `height`, `loading`, `onError`, `data-testid`, `className`. NO `onClick`. NO outer wrapper with `onClick`. The wrapping `<div className="mb-3 flex justify-center">` has no event handlers.
**Warning signs:** Tap on image stays on card; tap elsewhere advances.

### Pitfall 5: Unsplash URL with optional params loosens the regex
**What goes wrong:** Operator pastes `https://images.unsplash.com/photo-...?ixid=foo&q=80&w=400` and `^https://images\.unsplash\.com/.+` accepts it (good); but a typo'd `https://unsplash.com/photo-...` (missing `images.`) is rejected (also good).
**Why it happens:** Operator workflow is human-driven. The regex must accept canonical CDN URLs and reject the page-URL variant.
**How to avoid:** Use the regex `^https://images\.unsplash\.com/.+` exactly as D-12 specifies. Reject `unsplash.com/...` — it would 404 the `<img>` request anyway, but rejecting at insert is clearer.
**Warning signs:** Operator complains a copied URL was rejected — likely they grabbed the page URL not the CDN URL. Curate script's emitted suggested_query should hint they want the right-click → "Copy image address" URL.

### Pitfall 6: `meaning_en` for alt text is missing in FeedbackPanel
**What goes wrong:** D-08 mandates `alt={localize(meaning, 'en')}`. FeedbackPanel currently doesn't have a `meaningText` prop or access to `vocabInfo.meaning` (VocabInfo at `generator.ts:45-51` doesn't carry `meaning`).
**Why it happens:** Phase 08.3 didn't need English text in FeedbackPanel — it uses `translationLang` for body copy.
**How to avoid:** Pattern 5 above (option b): add `meaning_en?: string` to the Question type, populate in `page.tsx` merge as `localize(entry.meaning as Localizable, 'en')`, read in both LearnCard and FeedbackPanel for alt text.
**Warning signs:** FeedbackPanel image has empty `alt` attribute or non-English alt text. Accessibility audit fails AC #6.
