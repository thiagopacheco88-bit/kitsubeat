### ICO Synthesis Approach

`sharp` v0.34.5 does NOT have a native `.ico()` output method [VERIFIED: runtime test]. The correct approach is manual ICO binary construction:

1. Use `sharp(logo).resize(16,16).png().toBuffer()` and `sharp(logo).resize(32,32).png().toBuffer()`
2. Construct ICO binary: 6-byte header + 2×16-byte directory entries + PNG frame data
3. ICO magic bytes `00000100` (reserved=0, type=1 (icon), count=N)

### Pattern 3: ICO binary construction with sharp

```typescript
// scripts/brand/synthesize-favicon.ts
import sharp from "sharp";
import { readFileSync, writeFileSync } from "fs";

async function synthesizeFavicon(
  logoPath: string,
  outputPath: string
): Promise<void> {
  const [buf16, buf32] = await Promise.all([
    sharp(logoPath).resize(16, 16).png().toBuffer(),
    sharp(logoPath).resize(32, 32).png().toBuffer(),
  ]);

  const headerSize = 6;
  const dirEntrySize = 16;
  const numImages = 2;
  const offset16 = headerSize + dirEntrySize * numImages;
  const offset32 = offset16 + buf16.length;
  const ico = Buffer.alloc(offset32 + buf32.length);

  // ICO header
  ico.writeUInt16LE(0, 0);           // reserved
  ico.writeUInt16LE(1, 2);           // type = 1 (icon)
  ico.writeUInt16LE(numImages, 4);   // count

  // Directory entry 1 — 16×16
  ico.writeUInt8(16, 6);  ico.writeUInt8(16, 7);
  ico.writeUInt8(0, 8);   ico.writeUInt8(0, 9);
  ico.writeUInt16LE(0, 10); ico.writeUInt16LE(32, 12);
  ico.writeUInt32LE(buf16.length, 14);
  ico.writeUInt32LE(offset16, 18);

  // Directory entry 2 — 32×32
  ico.writeUInt8(32, 22); ico.writeUInt8(32, 23);
  ico.writeUInt8(0, 24);  ico.writeUInt8(0, 25);
  ico.writeUInt16LE(0, 26); ico.writeUInt16LE(32, 28);
  ico.writeUInt32LE(buf32.length, 30);
  ico.writeUInt32LE(offset32, 34);

  buf16.copy(ico, offset16);
  buf32.copy(ico, offset32);
  writeFileSync(outputPath, ico);
}
```

[VERIFIED: binary construction approach confirmed correct via runtime test — produces 2807-byte ICO with magic bytes `00000100`]

### Anti-Patterns to Avoid

- **Hardcoding hex colors in SVG paths:** `stroke="#f97316"` — use `stroke="currentColor"` always. Both light and dark themes must render correctly.
- **Adding `.ico()` call to sharp chain:** sharp 0.34.5 has no `.ico()` method — runtime TypeError. Use the manual binary construction pattern above.
- **Changing TierIcon's `<svg>` wrapper attributes:** The test uses `getByTestId("tier-icon-bamboo")` — the `data-testid` is on the `<svg>` element. Only the child path/rect/line elements change.
- **Modifying layout.tsx beyond the metadata block:** The fox-face SVG at lines 104–116 is the Phase 14.1 lock — do not touch. Only add `twitter:` key to the `metadata` export.
- **Adding `"use client"` to layout.tsx:** It is already a server component; metadata export requires it to remain a module-level export (not a client component).
- **Using PNG transparency in apple-touch-icon.png:** iOS ignores transparency in touch icons — opaque dark background required per D-04.

## Common Pitfalls

### Pitfall 1: sharp .ico() does not exist
**What goes wrong:** `sharp(src).resize(16,16).ico().toBuffer()` throws `TypeError: ...ico is not a function`
**Why it happens:** sharp 0.34.5 supports PNG/JPEG/WebP/AVIF etc. but not ICO output natively
**How to avoid:** Use manual Buffer binary construction (see Pattern 3 above)
**Warning signs:** If you see `.ico()` in the synthesis script, it will fail

### Pitfall 2: Breaking the TierDivider test contract
**What goes wrong:** Tests fail if `data-testid` attributes are renamed or removed from the `<svg>` wrapper
**Why it happens:** `getByTestId("tier-icon-bamboo")` queries the DOM for the attribute
**How to avoid:** `data-testid` is on the `<svg>` element — keep it there. Only child path/ellipse/rect/line elements change.
**Warning signs:** Tests checking `getByTestId("tier-icon-*")` fail

### Pitfall 3: Transparent apple-touch-icon fails on iOS
**What goes wrong:** iOS renders a black or white square instead of the icon
**Why it happens:** iOS applies a rounded-rect mask; transparent pixels become black/white depending on OS version
**How to avoid:** brand-prompts.md must specify opaque dark background for apple-touch-icon generation. Current `public/apple-touch-icon.png` already has correct dimensions (180×180) but has alpha (transparent) — the new one must have `channels:3` or equivalent flat dark bg
**Warning signs:** `sharp(path).metadata()` returns `hasAlpha: true` for apple-touch-icon

### Pitfall 4: Adding metadata.twitter breaks TypeScript
**What goes wrong:** Type error if twitter card value is not a valid literal
**Why it happens:** `Metadata.twitter.card` accepts specific literals: `'app'`, `'player'`, `'summary'`, `'summary_large_image'`
**How to avoid:** Use `card: 'summary_large_image'` exactly (matches D-10)
**Warning signs:** `tsc --noEmit` error mentioning `twitter.card`

### Pitfall 5: Changing layout.tsx fox-face SVG (Phase 14.1 lock)
**What goes wrong:** Visual regression on nav wordmark; Phase 14.1 acceptance criteria break
**Why it happens:** Lines 104–116 are explicitly locked
**How to avoid:** The metadata insertion is ONLY at the `metadata` object — no changes below line 29

### Pitfall 6: logo.png has wrong dimensions in placeholder
**What goes wrong:** If favicon.ico is synthesized from the placeholder logo.png, it will be synthesized from 616×625px art, not 512×512px kitsune art
**Why it happens:** Current logo.png is 616×625 — wrong dimensions and wrong content
**How to avoid:** Wave 2 synthesis script must only run AFTER user places the new 512×512px `logo.png`. Add a guard: `if (metadata.width !== 512 || metadata.height !== 512) throw new Error(...)`.
**Warning signs:** `sharp('./public/logo.png').metadata()` returns `{width: 616, height: 625}`

### Pitfall 7: Current og-image.png has transparent background
**What goes wrong:** OG share cards may render with transparent/white background in some platforms
**Why it happens:** Current `og-image.png` has `channels:4` (alpha present) per sharp metadata
**How to avoid:** brand-prompts.md must specify no transparency for OG/Twitter cards. D-05 specifies dark full-bleed background (#0a0a0a).

```typescript
// scripts/brand/verify-brand-assets.ts
import sharp from "sharp";
const EXPECTED = [
  { path: "public/logo.png", width: 512, height: 512, allowAlpha: true },
  { path: "public/apple-touch-icon.png", width: 180, height: 180, allowAlpha: false },
  { path: "public/og-image.png", width: 1200, height: 630, allowAlpha: true },
  { path: "public/twitter-image.png", width: 1200, height: 630, allowAlpha: true },
];
for (const spec of EXPECTED) {
  const meta = await sharp(spec.path).metadata();
  if (meta.width !== spec.width || meta.height !== spec.height)
    throw new Error(`${spec.path}: expected ${spec.width}×${spec.height}, got ${meta.width}×${meta.height}`);
  if (!spec.allowAlpha && meta.hasAlpha)
    console.warn(`WARNING: ${spec.path} has alpha — iOS touch icon requires opaque background`);
  console.log(`OK: ${spec.path} — ${meta.width}×${meta.height}`);
}
```
