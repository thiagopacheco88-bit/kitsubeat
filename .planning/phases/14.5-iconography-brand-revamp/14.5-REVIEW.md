Five files reviewed spanning the brand revamp: a documentation prompt guide, a React server component, the root Next.js layout, and two Node.js scripts for asset verification and favicon synthesis.

No critical issues found. The ICO binary construction in `synthesize-favicon.ts` is arithmetically correct and the magic bytes match between the synthesize and verify scripts. Two warnings: the verify script silently allows alpha channels on `og-image.png` and `twitter-image.png` even though the spec mandates opaque backgrounds for those assets — a transparency error in either file would pass verification. ## Warnings

### WR-01: verify-brand-assets.ts allows alpha on og/twitter images — contradicts spec

**File:** `scripts/brand/verify-brand-assets.ts:24-25`

**Issue:** `og-image.png` and `twitter-image.png` are configured with `allowAlpha: true`, so `verify-brand-assets.ts` never checks whether those files have opaque backgrounds. The spec in `brand-prompts.md` lines 26-27 explicitly states both must have an opaque dark background (`#0E0E0E`, no transparency). A transparent og or twitter image would pass the verify script but render incorrectly in social media card previews (platforms typically composite against a white or undefined background).

**Fix:**

```typescript
const EXPECTED = [
  { path: "public/logo.png",             width: 512,  height: 512,  allowAlpha: true  },
  { path: "public/apple-touch-icon.png", width: 180,  height: 180,  allowAlpha: false },
  { path: "public/og-image.png",         width: 1200, height: 630,  allowAlpha: false }, // opaque required
  { path: "public/twitter-image.png",    width: 1200, height: 630,  allowAlpha: false }, // opaque required
];
```

And update the error message for the og/twitter case to be distinct:

```typescript
} else if (!spec.allowAlpha && meta.hasAlpha) {
  const hint = spec.path.includes("apple-touch-icon")
    ? "iOS renders black square otherwise"
    : "social media platforms composite against white/undefined background otherwise";
  console.error(`FAIL: ${spec.path} has alpha channel — MUST have opaque background (${hint})`);
  failures++;
}
```

### WR-02: Both scripts resolve paths relative to CWD — break silently if run from wrong directory

**File:** `scripts/brand/verify-brand-assets.ts:32`, `scripts/brand/synthesize-favicon.ts:18`

**Issue:** Both scripts call `resolve(spec.path)` / `resolve("public/logo.png")` which resolves relative to `process.cwd()`. If either script is run from a subdirectory (e.g., `cd scripts && npx tsx ...`), it silently resolves to the wrong absolute path and throws a file-not-found error with a confusing message (`ERROR: Input file is missing...`) rather than a clear diagnostic.

**Fix:** Use `__dirname` (or `import.meta.url` for ESM) to anchor paths to the script's location:

```typescript
// At the top of each script, after imports:
import { resolve, dirname } from "path";
import { fileURLToPath } from "url";

// For CJS-compiled tsx:
const PROJECT_ROOT = resolve(__dirname, "../..");  // scripts/brand/ -> project root

// Then replace resolve(spec.path) with:
const fullPath = resolve(PROJECT_ROOT, spec.path);
```

Alternatively, add a CWD guard at the top of `main()`:

```typescript
if (!existsSync(resolve("public"))) {
  console.error("ERROR: Run this script from the project root (the directory containing public/).");
  process.exit(1);
}
```

## Info

### IN-01: TierIcon switch has no exhaustive default — silent undefined return on impossible input

**File:** `src/app/path/components/TierDivider.tsx:65-143`

**Issue:** The `switch (kind)` in `TierIcon` covers all three union members (`"bamboo"`, `"torii"`, `"mountain"`) but has no `default` branch. TypeScript's union ensures this is currently unreachable, but the function will implicitly return `undefined` rather than `never` if the type is widened or an untyped caller is introduced. Adding a `default` makes exhaustiveness checking explicit.

**Fix:**

```typescript
default:
  kind satisfies never;
  return null;
```

This leverages the `satisfies never` pattern — TypeScript errors at compile time if a new `iconKind` is added to `TierMeta` without a corresponding case.

### IN-02: layout.tsx metadata missing `openGraph.url` — og:url absent from social cards

**File:** `src/app/layout.tsx:24-28`

**Issue:** The `openGraph` metadata block omits the `url` field. Without `og:url`, Open Graph scrapers fall back to the page URL, which may be correct in practice, but Facebook and LinkedIn debuggers report a warning and some aggregators deduplicate incorrectly. This is an info item — functionality is not broken.

**Fix:**

```typescript
openGraph: {
  title: "KitsuBeat",
  description: "Learn Japanese through anime songs",
  url: "https://kitsubeat.com",   // canonical URL
  images: ["/og-image.png"],
},
```

### IN-03: brand-prompts.md uses Unix `cp` command — fails on native Windows PowerShell

**File:** `docs/icon-generation/brand-prompts.md:73-74, 109-110`

**Issue:** The post-generation instructions use `cp public/og-image.png public/twitter-image.png`. This works in Git Bash, WSL, and macOS terminals, but fails in native PowerShell (`cp` is an alias for `Copy-Item` in PowerShell 5 but not all environments have it, and the path separator behavior differs). Since the dev environment is Windows 11, this is worth noting.

**Fix:** Add a PowerShell alternative in the doc:

```markdown
# Unix / Git Bash:
cp public/og-image.png public/twitter-image.png

# PowerShell (Windows native):
Copy-Item public/og-image.png public/twitter-image.png
```

### IN-04: synthesize-favicon.ts sets `bitCount=32` for PNG-in-ICO frames — minor ICO spec deviation

**File:** `scripts/brand/synthesize-favicon.ts:57, 69`

**Issue:** The ICO spec states that `bitCount` in the directory entry describes the BMP bit depth. For PNG-compressed frames embedded in ICO files, the field should conventionally be set to `0` (unknown/irrelevant). Setting `32` is harmless — all major browsers and Windows parse it correctly — but `0` is more spec-conformant for PNG frames and avoids any edge-case parser confusion.

**Fix:**

```typescript
// Directory entry 1 — 16×16
ico.writeUInt16LE(0, 12);   // bitCount = 0 for PNG-in-ICO (not 32)

// Directory entry 2 — 32×32
ico.writeUInt16LE(0, 28);   // bitCount = 0 for PNG-in-ICO (not 32)
```
