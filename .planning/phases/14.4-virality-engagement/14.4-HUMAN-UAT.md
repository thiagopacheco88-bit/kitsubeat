## Tests

### 1. Daily reminder timezone coverage (Hobby plan trade-off)
expected: The cron fires at `0 19 * * *` (19:00 UTC daily). The SQL filter `EXTRACT(HOUR FROM now() AT TIME ZONE streak_tz) = 19` means only users in UTC timezone receive reminders. Users in UTC+1 (London summer), UTC+9 (Tokyo), etc. are never matched. Confirm this is acceptable for MVP or document the limitation.
result: accepted — MVP acceptable, Hobby plan limitation documented

### 2. Weekly recap vocab count semantics
expected: Route counts `user_vocab_mastery` rows where `lastReviewedAt >= 7 days ago`. SPEC says "rows whose stage advanced" — reviews without stage advancement would also count. Confirm this broader count is acceptable for v1.
result: accepted — broader count acceptable for v1

### 3. ISO week key correctness under year-boundary edge case
expected: `getISOWeekKey()` in weekly-recap route should return `"2025-W01"` for input date `2024-12-30` (ISO 2025-W01). If the function returns `"2024-W53"` instead, year-boundary weeks would have mismatched period_key and duplicate recap emails could fire.
result: fixed — replaced with ISO 8601 Thursday-anchor algorithm; 2024-12-30 now correctly returns 2025-W01 (commit 8a52f87)
