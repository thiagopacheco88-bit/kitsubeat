# Phase 14.4 Plan 03: Email + Cron Infrastructure Summary

**One-liner:** Resend email send helper + HTML templates (daily reminder, weekly recap) + cron auth guard + both hourly/weekly cron routes with idempotency via email_sent_log composite PK + vercel.json schedule config.

## What Was Built

**Task 1 — Install resend + cron auth + email modules** (commits `755ddd6` RED, `2d6a391` GREEN)

*TDD approach: RED commit with 16 failing tests (4 files), GREEN commit with all 5 implementations.*

**`src/lib/cron/auth.ts`** — `assertCronSecret(request: NextRequest): Response | null`:
- Returns 401 Response when `Authorization` header is missing
- Returns 401 Response when header value doesn't match `Bearer ${CRON_SECRET}`
- Returns 401 Response when `CRON_SECRET` env var is unset (always-fail)
- Returns `null` on valid auth (passes control back to caller)

**`src/lib/emails/layout.ts`** — shared email HTML helpers:
- `wrapLayout(body)` — full HTML document with table layout, header + footer
- `renderHeader()` — KitsuBeat brand header in `#0f0f13` bg with `#ff6b6b` accent
- `renderFooter()` — "Manage preferences" link to `/profile`
- All colors as hex literals (CSS vars are not supported in Outlook/email clients)

**`src/lib/emails/send.ts`** — `sendEmail(payload): Promise<SendEmailResult>`:
- Dry-run branch when `RESEND_API_KEY` unset — returns `{ sent: false, dry_run: true }`
- Dry-run logs `[email-dry-run] { kind, userId, subject }` — NEVER logs email address or API key
- Lazy-init Resend instance (avoids crash when key is unset)
- p-limit(1) concurrency + 200ms delay between sends (stays under 5 req/sec rate limit)
- Error path returns `{ sent: false }` without crashing

**`src/lib/emails/dailyReminder.ts`** — `render({ firstName, streakCurrent, hoursLeft })`:
- Subject: `"{N} hours left to extend your {M}-day streak"` (anti-loss-frame per D-17)
- Forbidden phrases absent: "don't lose", "ends in", "you'll fail", "miss out"
- HTML body with study CTA button in brand red
- Plain-text fallback included

**`src/lib/emails/weeklyRecap.ts`** — `render({ firstName, vocabLearned, songsTouched, streakCurrent, streakBest, nextUp })`:
- 4 sections in fixed order: Vocab Learned → Songs Touched → Streak → Up Next
- Subject: `"Your week with KitsuBeat: N vocab + M songs"` (falls back to `"Your week with KitsuBeat"` when both 0)
- Zero-value sections show `"—"` placeholder
- Plain-text fallback included

- `export const dynamic = "force-dynamic"` (no `runtime = "nodejs"` anti-pattern)

### Auto-fixed Issues

**1. [Rule 1 - Bug] clerkClient() returns Promise — must be awaited before .users.getUser**
- **Found during:** Task 2 TypeScript check (TS2339 error)
- **Issue:** Plan specified `clerkClient().users.getUser(user.id)` but `clerkClient()` from Clerk v5 is async and returns `Promise<ClerkClient>` — `.users` does not exist directly on the Promise
- **Fix:** `const clerk = await clerkClient(); const clerkUser = await clerk.users.getUser(user.id);` (matches pattern from `src/middleware.ts:32` and `src/app/api/admin/songs/route.ts:120`)
- **Files modified:** `src/app/api/cron/daily-reminder/route.ts`, `src/app/api/cron/weekly-recap/route.ts`
