# Phase 14.4 Plan 02: Data Layer + Streak-Saver Summary

**One-liner:** Pure streak-saver state machine + 4 new DB queries + session-integration extended with activity_events emit and streak-saver grant/consume hooks, with userPrefs round-tripping socialActivityEnabled.

## What Was Built

**Task 1 — Queries + streak-saver module + userPrefs round-trip** (commits `ed7f5a5` RED, `a38f076` GREEN)

*TDD approach: RED commit with failing tests first, GREEN commit with implementation.*

**`src/lib/streak/saver.ts`** — new pure module:
- `applyStreakSaver(input, newState)` → `StreakSaverResult` (grant/consume/no-op logic per D-12)
- Grant rule: `milestoneHit===7 && token===0` → token becomes 1
- Consume rule: `!graceApplied && prevStreak>1 && newStreak===1 && token===1` → restore streak, clear token, set pending
- `StreakSaverInput` + `StreakSaverResult` interfaces exported

**`src/lib/streak/saver.test.ts`** — 7 tests, all passing:
- grants token on milestone=7
- no double-grant when token already 1
- consumes on reset (prevStreak>1, newStreak=1, graceApplied=false)
- does NOT consume on grace-applied session
- restores streakCurrent = previousStreakCurrent + 1 on consume
- sets nextPending=true on consume
- no-op when token=0 and reset

**`src/lib/db/queries.ts`** — 4 new Phase 14.4 exports:
- `getNowPlayingCounts()` → `Map<string, number>` (unstable_cache 60s, ≥3 HAVING filter, opt-in gate on auth users, anon plays kept)
- `getRecentMasteryEvents(limit=10)` — last 10 song_mastered events from opt-in users with song title + slug
- `getTickerFirstName(userId)` — Clerk first-name via unstable_cache 1h TTL (fallback "Someone")
- `getActiveOptInUsersForDailyReminder()` — users at local 19:00 with active streak not logged today
- `getActiveOptInUsersForWeeklyRecap()` — all opt-in users with streak + path context

**`src/lib/user-prefs-shared.ts`** — added `socialActivityEnabled: boolean` to `UserPrefs` interface (default OFF per SPEC REQ-3)

**`src/app/actions/userPrefs.ts`** — round-tripped `socialActivityEnabled`:
- `getUserPrefs()`: SELECT `social_activity_enabled`, return `socialActivityEnabled: false` as default
- `updateUserPrefs()`: normalize `socialActivityEnabled → social_activity_enabled` patch, include in upsert `.values()`

**Task 2 — session-integration extension + integration test fills** (commit `b1137ce`)

**`src/lib/gamification/session-integration.ts`** extended:
- **Step 4.5** (new): after `deriveStars` comparison, if `previousStars < 3 && newStars === 3`, looks up song UUID + tv-preferred `song_version_id` via correlated subquery, inserts into `activity_events` with `ON CONFLICT (user_id, song_id) DO NOTHING` (idempotency per D-07)
- **Step 5.5** (new): after `advanceStreak`, calls `applyStreakSaver` with `previousStreakCurrent` (named variable), `streak_saver_token`, `milestoneHit`, `graceApplied`, `todayInTz`. Returns `saverResult`.
- **UPDATE SET** (modified): uses `saverResult.nextStreakCurrent` instead of `streakResult.newState.streakCurrent`, includes `streak_saver_token: saverResult.nextToken` and `streak_saver_pending: saverResult.nextPending`
- **Return value**: `streakCurrent` and `streakBest` use `saverResult.nextStreakCurrent` for consistency
