## Area 1: Email + Cron Infrastructure

### Cron infrastructure choice

| Option | Description | Selected |
|--------|-------------|----------|
| Vercel Cron via `vercel.json` | Native; Hobby tier = 2 jobs (we need 2); zero new infra | ✓ |
| External (GitHub Actions / Cron-Job.org / Upstash QStash) | Extra ops surface; no value-add when Vercel-native fits | |
| Inngest / Trigger.dev | Overkill for 2 timed routes | |

**Reasoning:** Project already deploys via Vercel (`vercel-build` script in package.json:12). Hobby cron limit (2) fits exactly. → D-01.

### Email send strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Resend SDK + serial loop with `p-limit` concurrency=5 | `p-limit` already a dep; ~30s for 5K users; per-row idempotency simple | ✓ |
| Resend `/emails/batch` (max 100/call) | Fewer round-trips but partial-failure reconciliation against `email_sent_log` adds bookkeeping | |
| Background queue (Inngest / Vercel Queues) | Overkill for 2 cron paths | |

**Reasoning:** `p-limit@^6.2.0` already installed. Serial path keeps `email_sent_log` write-then-send semantic clean. → D-02.

### Email template stack

| Option | Description | Selected |
|--------|-------------|----------|

| `react-email` | Adds dep + dev preview server; toolchain heavy for 2 templates | |
| Resend hosted templates | Vendor lock-in; no local preview; breaks copy-review-in-PR workflow | |

**Reasoning:** 2-template scope doesn't justify a templating framework. → D-03.

### Vercel function timeout

| Option | Description | Selected |
|--------|-------------|----------|

## Area 2: Data Layer (activity_events + Now-Playing)

### activity_events emission boundary

| Option | Description | Selected |
|--------|-------------|----------|
| Inside `applyGamificationUpdate`, transition-detect `previousStars < 3 && newStars === 3` + `ON CONFLICT DO NOTHING` | Belt-and-suspenders idempotency | ✓ |
| Blind `ON CONFLICT DO NOTHING` always | Adds INSERT per session save even when stars don't change | |
| Post-write trigger / external caller | Disconnects emission from star-derivation that justifies it | |

**Reasoning:** `previousStars` / `newStars` already in scope at session-integration.ts:222 for the XP step-up logic. → D-07.

### activity_events schema shape

| Option | Description | Selected |
|--------|-------------|----------|
| Composite UNIQUE `(user_id, song_id)` + `song_version_id NOT NULL` | Idempotency contract per SPEC; carries version context | ✓ |
| `song_version_id` nullable | Loses version context for ticker click-through | |
| Composite UNIQUE `(user_id, song_id, event_type)` | Unnecessary for single-value event_type now | |

**Reasoning:** SPEC limits `event_type` to song_mastered now; UNIQUE migrates cleanly when more events expand. → D-08.

### First-name read for ticker

| Option | Description | Selected |
|--------|-------------|----------|
| `unstable_cache` keyed by user_id, TTL 1h | 10 ticker rows × Clerk fetch = wasteful; 1h staleness acceptable | ✓ |
| Per-render Clerk fetch | Slow; risks rate limit | |
| Mirrored `users.first_name` + Clerk webhook | Webhook plumbing for near-static field | |

**Reasoning:** First-name changes are rare. Mirroring trigger: only if user-rename UX complaints arise. → D-09.

### Now-playing query + opt-in filter

| Option | Description | Selected |
|--------|-------------|----------|
| Single batched query; opt-in filter on auth users only; anon plays kept; `unstable_cache` 60s | Resolves REQ-1 + REQ-3 tension; meaningful chip at low-opt-in stages | ✓ |
| Count all plays regardless of opt-in | Contradicts REQ-3 | |
| Per-card N+1 query | Rejected on perf | |

**Reasoning:** Anonymous (NULL user_id) plays count toward chip — no opt-in row exists for them; no privacy violation. → D-10.
