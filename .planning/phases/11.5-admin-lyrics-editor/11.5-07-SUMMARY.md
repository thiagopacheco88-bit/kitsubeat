# Phase 11.5 Plan 07: Publish Flow Summary

**One-liner:** Atomic db.batch publish (INSERT lyrics_versions + guarded UPDATE song_versions + DELETE draft) with kuromoji re-tokenization, stale-publish 409 detection, and StalePublishModal in the editor.

## What Was Built

### Task 1: kuroshiro-tokenizer.ts dictPath + publish-tx.ts atomic batch template

**`scripts/lib/kuroshiro-tokenizer.ts`** — Modified to accept `InitKuroshiroOptions`:

- `initKuroshiro(opts: InitKuroshiroOptions = {})` — backward-compatible optional opts
- `opts.dictPath` overrides the `import.meta.url`-relative dict resolution (D-19 Pitfall 2)
- Existing callers (all scripts) pass nothing → still use old resolution path unchanged

**`src/lib/admin/publish-tx.ts`** — New file: `publishLyricsVersion` + `StalePublishError`:

- Pre-batch stale check: `SELECT active_lyrics_version_id, COALESCE(MAX(version_number),0)+1 AS next_n FROM song_versions LEFT JOIN lyrics_versions`
- Throws `StalePublishError(currentActiveId)` when base_version_id != current active
- `db.batch([...])` with 3 statements (confirmed directly available in drizzle-orm@0.41.0):
  - (a) INSERT INTO lyrics_versions (source='human', parent_version_id=baseVersionId)
  - (b) GUARDED UPDATE song_versions SET active_lyrics_version_id + jsonb_set('{verses}') WHERE id AND active = baseVersionId
  - (c) DELETE FROM lyrics_drafts WHERE song_version_id AND editor_id
- `jsonb_set(COALESCE(lesson,'{}'), '{verses}', $json)` preserves vocabulary/grammar_points siblings (Pitfall 7)

### Task 2: publish server action + 3 integration tests

**`src/app/admin/lyrics/actions/publish.ts`** — `"use server"` + `runtime = "nodejs"`:

- `requireAdminUser()` — editorId always from server-side Clerk (PUBLISH-T-03)
- `retokenizeVerses()`: `initKuroshiro({ dictPath: path.resolve(cwd, "node_modules/@sglkc/kuromoji/dict") })` → `tokenizeLyrics(surfaceText)` → LyricsToken[] → maps to Token[] with `posToGrammarType()` + `lookupOrCreateVocabId()`
- Re-tokenization failure is non-fatal (try/catch, logs error, continues with existing tokens)
- `lookupOrCreateVocabId(dictionaryForm, reading, romaji)`: SELECT by (dictionary_form, reading) → INSERT ON CONFLICT DO NOTHING → re-read; includes romaji + part_of_speech in INSERT (NOT NULL columns — Rule 1 auto-fix)
- `renumberVerses(processedVerses)` — verses renumbered 1..N by start_time_ms before publish
- `publishLyricsVersion(...)` — atomic db.batch
- `revalidateSongCache(slug)` — post-batch cache bust
- StalePublishError → `{ ok: false, error: "stale_publish", currentActiveId }`

## kuroshiro Per-Token API

`tokenizeLyrics(text)` from `scripts/lib/kuroshiro-tokenizer.ts` returns `LyricsToken[]` with:
- `surface`, `reading` (hiragana), `romaji` (hepburn), `pos` (Japanese POS), `pos_detail_1`, `basic_form`

This is a rich per-token API. `publish.ts` uses `tokenizeLyrics` directly (not an extended `tokenizeRich`). The surface text passed is the concatenation of existing verse tokens — this works correctly for standard verse editing flows.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] vocabulary_items INSERT missing NOT NULL columns**
- **Found during:** Task 2 implementation (schema audit)
- **Issue:** Plan template inserted only `(id, dictionary_form, reading, created_at)` — but `vocabulary_items.romaji` and `vocabulary_items.part_of_speech` are NOT NULL columns per schema.ts:265-266. Would have caused constraint violation on miss path.
- **Fix:** Added `romaji`, `part_of_speech = 'other'`, `meaning = '{"en":""}'::jsonb` to INSERT
- **Files modified:** `src/app/admin/lyrics/actions/publish.ts`
- **Commit:** b222125

**2. [Rule 1 - Bug] TypeScript discriminated union narrowing failure**
- **Found during:** Task 3 TypeScript check
- **Issue:** `PublishOutput` has `{ ok: false; error: string }` as a union member which is a supertype of `{ ok: false; error: "stale_publish"; currentActiveId: ... }`. TypeScript cannot narrow by `r.error === "stale_publish"` alone because the `string` branch also matches.
- **Fix:** Added `&& "currentActiveId" in r` to the condition; TS then narrows to the stale branch
- **Files modified:** `src/app/admin/lyrics/components/PublishButton.tsx`
- **Commit:** 819b453

**3. [Rule 2 - Missing error handling] Re-tokenization failure non-fatal**
- **Found during:** Task 2 implementation review
- **Issue:** If kuromoji initialization fails (dict missing, etc.), the plain await would abort the publish entirely
- **Fix:** Wrapped `retokenizeVerses()` call in try/catch; logs error and continues with existing tokens (best-effort)
- **Files modified:** `src/app/admin/lyrics/actions/publish.ts`
- **Commit:** b222125
