### Gaps Summary

**1 gap (SPEC-9 — kanji breakdown UI trigger):**

The kanji breakdown editor server infrastructure is complete: `saveKanjiBreakdown` action updates `vocabulary_items.kanji_breakdown` and revalidates all songs sharing the vocab. The integration test stub covers cross-song propagation. The client-side UI code (toggle button, per-character inputs, confirm dialog) is all present in VerseRow.tsx.

However, the toggle button `{hasKanji && vocab && <button>}` will never render because `vocab` is always undefined: `vocabMap` in page.tsx is always empty `{}` because the `Token` type in `src/lib/types/lesson.ts` does not carry `vocab_item_id`. The mapping from token surface to vocab row cannot be established without this field.

The acceptance criterion "editing radical_hint for 鉄 updates vocabulary_items" cannot be exercised through the editor UI until `Token.vocab_item_id` is added. The SUMMARY for Plan 04 explicitly documents this as a known deviation, with a forward-compat `TokenWithVocab` type already in place for when the extension lands.

**Root cause:** Token schema gap (upstream of phase 11.5). The kanji breakdown editor was architecturally blocked from the start by an existing data model constraint.

**Suggested path forward:** In a future phase (or via a quick schema extension), add `vocab_item_id: string | null` to the `Token` type in `src/lib/types/lesson.ts` and populate it in the lesson generation pipeline. Once that lands, page.tsx vocabMap population logic can be activated (the code hook is already in place at lines 180-183).
