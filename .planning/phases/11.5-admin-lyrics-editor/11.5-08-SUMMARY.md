# Phase 11.5 Plan 08: Swap Video Summary

**One-liner:** YouTube video swap end-to-end: server action with URL validation + guarded status flip + detached orchestrator + per-step DB writes + poller + retry-from-failed-step with flagged_unfixable escalation.

## What Was Built

### Task 1: scripts/seed/swap-video-pipeline.ts + 2 integration tests

**`scripts/seed/swap-video-pipeline.ts`** — Detached orchestrator (D-09):

- CLI args: `--slug=X`, `--new-youtube-id=Y`, `--steps=audio,whisper,lesson`, `[--resume-from=<step>]`
- Uses `neon-serverless Pool` (not neon-http) per RESEARCH §"Pre-DB script bootstrap"
- Per-step DB write BEFORE execSync: `UPDATE song_versions SET pipeline_step=<name>, pipeline_started_at=COALESCE(...)` (D-10)
- On step failure (first try): `UPDATE pipeline_status='rerun_failed', pipeline_step=<failed>`
- On step failure (retry = `--resume-from` was passed, D-12): also `UPDATE songs SET quality_status='flagged_unfixable', quality_notes=COALESCE(...)||'Pipeline failed at <step>: <error> (<ts>)'`
- On all steps success: `UPDATE pipeline_status='idle', pipeline_step=NULL`
- Pitfall 13: orchestrator clears status regardless; 05-insert-db.ts controls lyrics_versions writes
- Looks up `song_version_id` and `song_id` by slug (existing per-slug filter pattern)

**`tests/integration/swap-pipeline.test.ts`** — 3 tests (all gated on `describe.skipIf(!TEST_DB)`):
1. Guarded UPDATE rejects double-trigger when pipeline_status != 'idle' (Pitfall 12)
2. song_video_history insert is appendable + queryable by song_version_id (SPEC #21)
3. pipeline_step write reflects correctly in subsequent SELECT

**`tests/integration/rerun-failure.test.ts`** — 3 tests (all gated on `describe.skipIf(!TEST_DB)`):
1. Second-failure path sets quality_status='flagged_unfixable' + quality_notes matches pattern
2. First-failure sets pipeline_status='rerun_failed' only (no flagged_unfixable)
3. quality_notes COALESCE appending works for multiple failure entries

### Task 2: swap-video.ts server action + pipeline-status/route.ts polling endpoint

**`src/app/admin/lyrics/actions/swap-video.ts`** — `"use server"` + `runtime = "nodejs"`:

- `requireAdminUser()` — admin.id sourced server-side (SWAP-T-04)
- URL validation: `new URL()` parse + `ALLOWED_HOSTS` hostname allowlist + `VIDEO_ID_RE = /^([a-zA-Z0-9_-]{11})$/` anchored regex (T-11.5-05)
- Supports `?v=`, `youtu.be/<id>`, `/embed/<id>` URL forms
- Reads `old_youtube_id` for audit log before UPDATE
- Guarded UPDATE: `WHERE pipeline_status = 'idle' RETURNING id` (SWAP-T-01 / Pitfall 12)
- isRetry path: skips idle guard, flips from `rerun_failed` back to `rerun_in_progress`
- Inserts `song_video_history` row on every swap (SPEC #21, changed_by = admin.id)
- Spawns `npx tsx scripts/seed/swap-video-pipeline.ts` with `detached: true`, `stdio: 'ignore'` + `child.unref()` (SWAP-T-02)

**`src/app/api/admin/song/[id]/pipeline-status/route.ts`** — GET endpoint:

- Admin-gated via `requireAdminUser()` → 403 on non-admin
- Returns `pipeline_status`, `pipeline_step`, `pipeline_started_at`, `quality_status`, `quality_notes`
- `force-dynamic` + `runtime = "nodejs"` per timing route pattern

## Deviations from Plan

None — plan executed exactly as written. Minor adaptations:

1. **PipelineStatusPoller fires immediate poll**: Plan spec shows `setInterval` only. Added an immediate `poll()` call before the interval to reduce first-render latency from 3s to ~0s. This is an enhancement, not a behavioral change.

2. **spawn uses `npx tsx`**: Plan template shows `spawn("npx", ["tsx", ...])`. The server action uses this pattern — `npx tsx` is more reliable for node_modules resolution than a direct tsx binary path in server action context.

3. **isRetry guard bypass**: The plan spec's guarded UPDATE only runs for new swaps. For retry, the plan says "flip back without idle guard" — implemented as a separate UPDATE when `isRetry=true`. Both paths insert a `song_video_history` row (audit completeness).
