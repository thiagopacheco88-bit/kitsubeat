# Phase 11.5 Plan 09: Flag Broken Summary

**One-liner:** Quality+pipeline catalog filter on 6 public selectors + page 404 branch + flagSong/clearFlag server actions + FlagControls admin UI.

## What Was Built

### Task 1: quality+pipeline filter on public catalog selectors (TDD)

**RED commit:** `e17f123` — Integration test (`tests/integration/catalog-flag-filter.test.ts`) with 3 cases:
1. Flagging a song removes it from the catalog filter result (SPEC #22)
2. Rerunning pipeline removes song from catalog filter (D-13)
3. Clearing the flag restores visibility

**GREEN commit:** `9002abd` — Modified `src/lib/db/queries.ts`:

All 6 public catalog selectors updated with the same WHERE clause addition:
- `getAllSongs` — `AND quality_status = 'active' AND EXISTS (...pipeline_status = 'idle')`
- `getFeaturedSongs` — same
- `getBeginnerSongs` — same
- `getRecentSongs` — same
- `getTopAnimeFranchises` — same
- `getTopArtists` — same

**Selectors updated:** 6 (all targeted by the plan)

`getSongBySlug` was **not** modified — it returns full rows including `quality_status` and `pipeline_status` per version. The page-layer check covers the 404 path without affecting admin/debug consumers.

### Task 2: Public song page 404 branch + Playwright e2e

**Commit:** `be577ed`

`src/app/songs/[slug]/page.tsx` — added two explicit checks after `if (!song) notFound()`:
1. `if (song.quality_status !== "active") notFound()` — covers flagged_wrong_song + flagged_unfixable
2. `if (!hasIdleVersion) notFound()` — covers D-13 (no version with pipeline_status='idle')

`getSongBySlug` returns the full songs row (all columns via `db.select().from(songs)`) + versions array — `quality_status` and `pipeline_status` were already available. **No DB query change needed.**

Playwright e2e (`tests/e2e/flagged-song-404.spec.ts`) — 4 cases: active→200, flagged_wrong_song→404, flagged_unfixable→404, clear→200.

### Task 3: flagSong + clearFlag server actions + FlagControls UI

**Commit:** `67eac79`

**`src/app/admin/lyrics/actions/flag-song.ts`** (`"use server"` + `runtime = "nodejs"`):
- `flagSong({ songId, slug, status, notes })` — sets quality_status + quality_notes, revalidates cache
- `clearFlag({ songId, slug })` — resets quality_status='active', quality_notes=null, revalidates cache
- Both: `requireAdminUser()` guard + `revalidateSongCache(slug)` + `revalidatePath("/songs")` (FLAG-T-03)

**`src/app/admin/lyrics/components/FlagControls.tsx`** (`"use client"`):
- Radio buttons: `active` | `flagged_wrong_song` | `flagged_unfixable` (data-testid per value)
- Notes textarea (visible only when status !== 'active')
- Apply/Clear flag button (data-testid="flag-apply")
- Feedback message (data-testid="flag-feedback")
- Amber/yellow styling to clearly signal danger zone

**`src/app/admin/lyrics/components/VerseEditor.tsx`** — new optional props:
- `songId?: string`
- `initialQualityStatus?: "active" | "flagged_wrong_song" | "flagged_unfixable"`
- `initialQualityNotes?: string | null`
- FlagControls rendered below SwapVideoModal when `props.songId` is present

**`src/app/admin/lyrics/page.tsx`** — added `quality_notes: songs.quality_notes` to SELECT; passes `songId`, `initialQualityStatus`, `initialQualityNotes` to VerseEditor.
