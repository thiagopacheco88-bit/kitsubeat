## Risks Surfaced from Pattern Mapping

These are existing-code risks the planner needs to plan AROUND (already documented in RESEARCH §9 — listed here because they directly affect which pattern is safe to copy):

1. **`db.transaction(async tx => ...)` is unavailable** — see RESEARCH §9 Pitfall 1 + the in-source comment at `src/app/actions/review.ts:14-15`. Publish must use `db.batch([...])` per RESEARCH §7. **Do NOT copy any in-repo pattern that uses `db.transaction()`** — none should exist, but if one is found, it's a bug to fix separately.

2. **`scripts/lib/kuroshiro-tokenizer.ts:53-56` resolves dict path relative to `import.meta.url`** — when imported from a server action, this breaks. Planner MUST add a `dictPath?: string` param to `initKuroshiro()` AND pass `path.resolve(process.cwd(), "node_modules/@sglkc/kuromoji/dict")` from the publish action.

3. **Inline-style React in `/admin/timing` is the locked aesthetic** — do NOT introduce Tailwind, shadcn, or a design system. CONTEXT D-21 + RESEARCH "Established Patterns" are explicit.

4. **Migrations are NOT applied via `drizzle-kit migrate`** — the project uses hand-written `IF NOT EXISTS`-guarded SQL (Phase 11.4 noted that `db:generate` would pollute the file). Application is manual via Neon console or `scripts/apply-migrations.ts`. Plan must include the application step.

5. **No middleware exists today** — middleware breakage during Vercel build (RESEARCH §9 Pitfall 15) is a real risk because Vercel will start building `src/middleware.ts` even though only localhost uses it. Set `config.matcher` to `["/admin/:path*"]` ONLY and ensure Clerk env vars are at minimum present (even as dummies) on Vercel.
