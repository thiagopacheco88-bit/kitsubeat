# Phase 11.5 Plan 03: Route Shell Summary

**One-liner:** /admin/lyrics RSC route shell with SongSearch client component (4-field text filter, flagged-song badges, URL-state via async searchParams) and enriched /api/admin/songs returning all songs including flagged.

## What Was Built

### Task 1: /api/admin/songs enrichment (additive)

The existing route returned `id`, `version_type`, `slug`, `title`, `artist`, `anime`, `timing_verified`, `timing_youtube_id` for the timing editor. It had no admin guard and no quality/pipeline fields.

**Change type: additive (NOT a rewrite).** Kept all existing fields intact so `/admin/timing`'s `SongList.tsx` remains unbroken. Added:
- `song_version_id` alias (same value as `id` — used by SongSearch.tsx)
- `song_id`, `season_info` (needed by lyrics SongSearch)
- `quality_status`, `quality_notes` (SPEC #22 admin badge)
- `pipeline_status`, `pipeline_step` (admin operational visibility)
- `active_lyrics_version_id` (plan 04/05 will use this)
- `requireAdminUser()` guard with `AdminRequiredError` catch (belt + braces per T-11.5-01)
- `runtime = "nodejs"` + `force-dynamic` exports
- Ordering changed from `timing_verified ASC, title ASC` to `title ASC` (admin-friendly)
- No `quality_status` filter — admin sees ALL songs (SPEC #22)

### Task 2: /admin/lyrics page.tsx + SongSearch.tsx

**page.tsx** (RSC, ~65 lines):
- `export const dynamic = "force-dynamic"; export const runtime = "nodejs"`
- Reads `searchParams.songId` and `searchParams.version` via `await searchParams` (Next.js 15 async pattern)
- Passes `initialSongVersionId` prop to `<SongSearch />`
- When `songId` present: renders `data-testid="editor-placeholder"` block showing selected song UUID + version (plan 04 will replace this branch with the real VerseEditor)
- When `songId` absent: renders `data-testid="empty-editor"` dashed-border invitation

**SongSearch.tsx** (client component, ~175 lines):
- `"use client"` directive
- `useEffect` → `fetch("/api/admin/songs")` on mount (no TanStack Query — D-22)
- `useMemo` substring filter: `[title, artist, anime, season_info].join(" ").toLowerCase().includes(q)`
- Loading/error states rendered as early returns (before the search input)
- Table with 6 columns: Title, Artist, Anime/Position, Version (TV amber / Full blue badge), Status (quality + pipeline badges), Open link
- Flagged songs: `data-testid="flag-<id>"` span with `color: #dc2626` when `quality_status !== "active"`
- Pipeline badge when `pipeline_status !== "idle"`
- Open link href: `/admin/lyrics?songId=<song_version_id>&version=<version_type>` (SPEC #2)
- Selected row highlighted blue when `song_version_id === initialSongVersionId`
- Inline-style palette matches `/admin/timing` aesthetic (CONTEXT D-21 lock)

### Task 3: Playwright e2e spec

`tests/e2e/admin-lyrics-shell.spec.ts` — 3 tests:
1. Renders search input + empty editor on first load
2. Typing in search input filters the song list
3. URL state preservation: ?songId=X&version=tv loads editor area

**Auth guard pattern evolution (deviation documented below):** Three iterations were needed before finding the correct Playwright guard pattern. Final implementation uses `navigateAndCheckAuth()` which:
1. Navigates with `waitUntil: "domcontentloaded"`
2. Waits 1s for Clerk redirect chain to settle
3. Checks URL pathname (not full URL string) — avoids false positive on `clerk-sync-keyless?returnUrl=...admin%2Flyrics`
4. Waits up to 3s for `[data-testid="song-search-input"]` — detects both redirect AND API-403 (no Clerk credentials) cases
5. Returns bool; caller returns early if false

**Test result:** 3 skipped, exit 0. Acceptable per plan — "Tests pass if Clerk auth is set up; otherwise skip cleanly."

## Deviations from Plan

### [Rule 1 - Bug] Playwright test.skip() does not abort async test body

**Found during:** Task 3

**Issue:** The plan's reference spec used `test.skip(true, reason)` inside async test bodies after `await` calls. In Playwright, `test.skip(true, reason)` called after awaits does not abort execution — the test continues running and fails on subsequent assertions.

**Fix:** Replaced `test.skip(true, reason)` + `return` with a bool-returning `navigateAndCheckAuth()` guard function. Callers check the bool and return early. `test.skip(true, reason)` still called for proper Playwright skip reporting, followed immediately by `return`.

**Files modified:** tests/e2e/admin-lyrics-shell.spec.ts

**Commit:** cfb7093

### [Rule 1 - Bug] Clerk keyless-sync URL contains /admin/lyrics in returnUrl parameter

**Found during:** Task 3 (iteration 2 of guard fix)

**Issue:** Clerk middleware redirects to `/clerk-sync-keyless?returnUrl=http%3A%2F%2Flocalhost%3A7000%2Fadmin%2Flyrics`. The URL string contains "admin/lyrics" in the query param, making string-based `url.includes("/admin/lyrics")` return a false positive (treating redirect as "on admin page").

**Fix:** Changed guard to use `new URL(url).pathname.startsWith("/admin/lyrics")` — checks only the path segment, not query params.

**Files modified:** tests/e2e/admin-lyrics-shell.spec.ts

### [Rule 1 - Bug] Clerk API 403 makes SongSearch show error state (not search input)

**Found during:** Task 3 (iteration 3 of guard fix)

**Issue:** Even when URL stays on `/admin/lyrics` (Clerk in permissive keyless mode), `requireAdminUser()` in the API route throws `AdminRequiredError` → API returns 403 → SongSearch catches HTTP 403 → renders `<p>Error: HTTP 403</p>` instead of the search input. URL-based check alone was insufficient to detect "auth not set up."

**Fix:** Added `page.waitForSelector('[data-testid="song-search-input"]', { timeout: 3_000 })` to `navigateAndCheckAuth()`. A timeout here correctly signals "auth not working" regardless of URL.

**Files modified:** tests/e2e/admin-lyrics-shell.spec.ts

### [Rule 2 - Missing] Added boxSizing: border-box to search input

**Found during:** Task 2 implementation review

**Issue:** The 100% width input with padding would overflow its container without `boxSizing: "border-box"`.

**Fix:** Added `boxSizing: "border-box"` to the input's inline style.

**Files modified:** src/app/admin/lyrics/components/SongSearch.tsx
