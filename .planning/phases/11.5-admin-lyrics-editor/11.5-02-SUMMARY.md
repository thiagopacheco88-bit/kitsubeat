### [Rule 3 - Env Setup] E2E tests run against dedicated server (port 7300) with pk_live_ key format

**Found during:** Task 3

**Issue:** The plan's acceptance criteria requires `npx playwright test tests/e2e/admin-auth.spec.ts` to exit 0. The playwright config uses `reuseExistingServer: true` and an existing server on port 7000 was running (parent project's dev server without our middleware). Running tests against this server produced failures because the middleware didn't exist on that server. Additionally, `pk_test_` formatted Clerk keys cause a dev-browser HTTPS redirect in Clerk development mode, which Playwright follows and gets an SSL error.

**Fix:**
1. Started a dedicated dev server on port 7300 with `pk_live_` formatted key (`pk_live_Y2xlcmsuZXhhbXBsZS5jb20k` — a validly formatted but non-functional key sufficient for the logged-out redirect test)
2. Updated `playwright.config.ts` to support `PLAYWRIGHT_BASE_URL` env var override (defaults to http://localhost:7000 for backward compatibility)
3. Updated `playwright.config.ts` to pass Clerk env vars through to webServer when present in caller environment

**Runtime behavior confirmed by curl:**
- `http://localhost:7300/admin/timing` → 307 redirect to `/` ✓
- `http://localhost:7300/admin/lyrics` → 307 redirect to `/` ✓
- `http://localhost:7300/` → 200 OK (public route unaffected) ✓

**Test command that passes:**
```bash
PLAYWRIGHT_BASE_URL=http://localhost:7300 npx playwright test tests/e2e/admin-auth.spec.ts
```

**Standard command note:** `npx playwright test tests/e2e/admin-auth.spec.ts` (without env) requires Clerk credentials in `.env.local` AND the dev server started with those credentials. In normal operation (post-Clerk-account-setup), `npm run dev` reads `.env.local` automatically.

**Files modified:** playwright.config.ts
