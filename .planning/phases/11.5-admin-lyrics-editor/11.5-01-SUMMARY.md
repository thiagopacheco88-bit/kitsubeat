# Phase 11.5 Plan 01: Schema Migration Summary

**One-liner:** Idempotent SQL migration 0015 creating 3 tables, 3 enums, 7 new columns, backfilling 329 song_versions rows into lyrics_versions.

## What Was Built

### drizzle/0015_admin_lyrics_editor.sql (139 lines)

Hand-written idempotent SQL migration for the admin lyrics editor data foundation:

- 3 enums: `lyrics_version_source` ('auto','ai-assist','human','regen'), `pipeline_status` ('idle','rerun_in_progress','rerun_failed'), `quality_status` ('active','flagged_wrong_song','flagged_unfixable') — all wrapped in `DO $$ EXCEPTION` blocks for idempotency
- `lyrics_versions` table with self-FK `parent_version_id`, UNIQUE constraint on `(song_version_id, version_number)`, 2 indexes
- `lyrics_drafts` table with composite PK `(song_version_id, editor_id)`, CASCADE on song_versions delete
- `song_video_history` table with index on `(song_version_id, changed_at DESC)`
- 4 new columns on `song_versions` (active_lyrics_version_id, pipeline_status, pipeline_step, pipeline_started_at) + partial index
- 2 new columns on `songs` (quality_status, quality_notes) + partial index
- Backfill CTE creating `source='auto'` lyrics_versions rows for every existing song_version with a lesson, with `COALESCE(sv.lesson->'verses', '[]'::jsonb)` NULL safety guard

### src/lib/db/schema.ts (modified)

- Added `primaryKey` and `AnyPgColumn` imports
- 3 new pgEnum exports: `lyricsVersionSourceEnum`, `pipelineStatusEnum`, `qualityStatusEnum`
- Extended `songs` table with `quality_status` and `quality_notes`
- Extended `songVersions` table with 4 new columns (active_lyrics_version_id as plain uuid to avoid forward-reference, pipeline_status, pipeline_step, pipeline_started_at)
- 3 new table exports: `lyricsVersions`, `lyricsDrafts`, `songVideoHistory`
- 5 new TypeScript inferred types exported

### tests/integration/migration-0015-backfill.test.ts

Wave 0 stub with `describe.skipIf(!TEST_DB)` guard. 3 tests covering:
1. Row count parity (lv_auto == sv_with_lesson)
2. active_lyrics_version_id set for all rows with lesson
3. COALESCE edge case (empty verses produces [] not NULL violation)

## Decisions Made

1. `active_lyrics_version_id` declared as plain `uuid` in Drizzle schema (no `.references()`) to avoid mutual import issue between `songVersions` and `lyricsVersions`. The DB-level FK is enforced by the SQL migration (`REFERENCES "lyrics_versions"("id") ON DELETE NO ACTION`). Drizzle query builder functionality is unaffected.

2. Integration test stub skips cleanly with `describe.skipIf(!TEST_DB)` when `TEST_DATABASE_URL` is not set. Pre-existing test failure in `regression-stale-lesson-data.test.ts` (ExerciseTab import violation) is out of scope for this plan.

3. Temporary `.env.local` copy to worktree was used during Task 3 to allow migration script to find DB credentials, then deleted (not committed).
