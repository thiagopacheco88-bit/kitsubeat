# Phase 11.5 Plan 04: Verse Editor Summary

**One-liner:** Per-song RSC page loading active lyrics_versions.verses with VerseEditor + VerseRow client components exposing SPEC #5–#9/#12/#13/#14 editable fields, backed by 13 pure-utility unit tests and a kanji_breakdown cross-song integration test stub.

## What Was Built

### Task 1: Pure utilities + unit tests (TDD)

**`src/lib/admin/timing-overlap.ts`** — `detectOverlap(verses)` returns `OverlapWarning[]` with kinds `overlap | non_monotonic | degenerate`. Purely functional (no DB/network/React imports). SPEC #12: overlap warnings are informational only — they do NOT block publish.

**`src/lib/admin/verse-renumber.ts`** — `renumberVerses<V>(verses)` sorts by `start_time_ms` then renumbers 1..N contiguously. Used at publish time (Plan 07 flow); draft preserves edit context per SPEC #14.

**Tests:** 7 cases for detectOverlap + 6 cases for renumberVerses = 13 tests, all green (`npx vitest run src/lib/admin/timing-overlap.test.ts src/lib/admin/verse-renumber.test.ts`).

### Task 2: UI components + page.tsx update

**`src/app/admin/lyrics/page.tsx`** — Replaces the `data-testid="editor-placeholder"` branch (Plan 03 stub) with real data loading:
1. SELECT song_version + songs WHERE `songVersions.id = songVersionId` (URL param via async searchParams)
2. SELECT lyrics_versions WHERE `id = active_lyrics_version_id` → extracts `verses: Verse[]`
3. Passes `verses`, `baseVersionId`, `baseVersionNumber`, `vocabMap` to `<VerseEditor />`
- Empty-editor branch (`data-testid="empty-editor"`) preserved exactly as Plan 03 wrote it
- SongSearch and URL state binding from Plan 03 preserved

**`src/app/admin/lyrics/components/AdminPlayerEmbed.tsx`** — Thin wrapper:
- Imports `PlayerProvider` from `/songs/[slug]/components/PlayerContext` (no fork needed)
- Imports `YouTubeEmbed` from `/songs/[slug]/components/YouTubeEmbed`
- Passes `videoId={youtubeId}` (YouTubeEmbed uses `videoId` prop, not `youtubeId`)
- Omits `songVersionId` and `userId` — no play recording in admin context

**`src/app/admin/lyrics/components/VerseEditor.tsx`** — Top-level client component:
- Wraps `<AdminPlayerEmbed>` around the verse list
- Local `useState<Verse[]>` for draft (Plan 05 replaces with zustand store)
- Calls `detectOverlap(draft)` and passes warnings per verse to `VerseRow`
- Insert before first (`data-testid="insert-before-first"`) + insert after N (`data-testid="insert-after-{N}"`)
- Delete via confirm dialog
- Warning count displayed in header

**`src/app/admin/lyrics/components/VerseRow.tsx`** — Per-verse editable surface:
- ▶ seek button: `player.seekTo(verse.start_time_ms)` (SPEC #12 + PlayerContext)
- Timing inputs: `start_time_ms` / `end_time_ms` with `onBlur` callbacks (SPEC #12)
- Token grid: `reading` input (`data-testid="reading-V-I"`, SPEC #5), surface display, `romaji` input (`data-testid="romaji-V-I"`, SPEC #6), kanji toggle when vocab_item_id present (`data-testid="kanji-toggle-V-I"`)
- Per-language translations: `data-testid="translation-V-locale"` (SPEC #7)
- Literal meaning textarea: `data-testid="literal-V-en"` (SPEC #8)
- Cultural context textarea: `data-testid="cultural-V-en"` (SPEC #8)
- Kanji breakdown editor (expanded on toggle): per-character inputs for meaning/on_yomi/kun_yomi/radical_hint + compound_note textarea; onBlur calls `saveKanjiBreakdown` via dynamic import (SPEC #9 + ISSUE-02)
- Overlap warning banner displayed (yellow bg, non-blocking)
- Delete button: `data-testid="delete-V"`

**`src/app/admin/lyrics/actions/save-kanji-breakdown.ts`** — STUB `"use server"` action that throws `NotImplementedError`. Reserves the file path so VerseRow's dynamic import resolves at type-check time. Plan 05 Task 4 replaces the body with the real UPDATE + revalidate.

## PlayerContext Reusability Assessment

PlayerProvider and YouTubeEmbed are directly reusable from `/songs/[slug]/components/` without any fork:
- PlayerProvider exports cleanly (`PlayerProvider`, `usePlayer`, `PlayerImperativeApi`)
- YouTubeEmbed takes `videoId` (not `youtubeId` — see deviation below)
- The admin embed omits `songVersionId` and `userId`, disabling play recording (admin bypass condition in YouTubeEmbed also suppresses recording in dev)
- No song-page-only state leaks into the admin context — `forceMount`, `showFurigana`, etc. are unused but harmless

## Deviations from Plan

### [Rule 1 - Bug] YouTubeEmbed prop is `videoId` not `youtubeId`

**Found during:** Task 2 — read YouTubeEmbed.tsx before writing AdminPlayerEmbed

**Issue:** Plan spec called the prop `youtubeId` but the actual component signature is `videoId`.

**Fix:** AdminPlayerEmbed passes `videoId={youtubeId}` (maps internal prop name to component prop name). No behavior change.

**Files modified:** `src/app/admin/lyrics/components/AdminPlayerEmbed.tsx`

### [Rule 1 - Bug] Schema column is `lyrics_offset_ms` not `lesson_offset_ms`

**Found during:** Task 2 — read schema.ts before writing page.tsx

**Issue:** Plan spec referenced `lesson_offset_ms` but the Drizzle schema has `lyrics_offset_ms`.

**Fix:** page.tsx uses `lyrics_offset_ms`. VerseEditor prop renamed `lyricsOffsetMs` (not `lessonOffsetMs`).

**Files modified:** `src/app/admin/lyrics/page.tsx`, `src/app/admin/lyrics/components/VerseEditor.tsx`

### [Rule 2 - Missing] Token type lacks vocab_item_id — kanji toggle deferred

**Found during:** Task 2 — read src/lib/types/lesson.ts

**Issue:** The plan's interface spec shows `vocab_item_id` on `Token`. The real `Token` type in `lesson.ts` does not have this field — it lives on `VocabEntry` (a separate object). Without `vocab_item_id` on tokens, the kanji breakdown toggle cannot be activated.

**Fix:** VerseRow introduces a `TokenWithVocab = Token & { vocab_item_id?: string | null }` local extended type for forward-compatibility. The kanji toggle is gated on BOTH `hasKanji && vocab` — a condition that cannot be met with the current Token shape. The editor surface is structurally correct and Plan 05/06 can wire it by adding `vocab_item_id` to Token.

**Files modified:** `src/app/admin/lyrics/components/VerseRow.tsx`

**Note:** This is NOT a blocking deviation — the remaining SPEC #5/#6/#7/#8/#12/#13/#14 functionality works correctly today. SPEC #9 (kanji_breakdown) is architecturally in place but requires Token schema extension.

### [Rule 2 - Missing] Verse type lacks surface field — new-verse creation adapted

**Found during:** Task 2 — read src/lib/types/lesson.ts

**Issue:** Plan's interface spec includes `surface: string` on Verse. The real type does not have it.

**Fix:** `handleInsertAfter` in VerseEditor omits `surface` from the new verse object. No behavior impact.

**Files modified:** `src/app/admin/lyrics/components/VerseEditor.tsx`

### [Rule 2 - Missing] vocabMap is empty pending Token schema extension

**Found during:** Task 2 — confirmed Token has no vocab_item_id

**Issue:** page.tsx was designed to collect vocab_item_ids from tokens and load kanji_breakdown rows. With no vocab_item_id on Token, the collection yields nothing.

**Fix:** vocabMap is empty (`{}`); vocabularyItems import kept as forward-compat hook for Plan 05. The `void vocabularyItems` line suppresses the unused-import linter warning.

**Files modified:** `src/app/admin/lyrics/page.tsx`

## Known Stubs

1. **`save-kanji-breakdown.ts`**: Throws `NotImplementedError`. Plan 05 Task 4 replaces with real UPDATE + revalidateSongCache. Kept as stub here so VerseRow's dynamic import type-checks.

2. **`vocabMap` always empty**: Until `Token.vocab_item_id` is added (Plan 05/06), the kanji breakdown editor cannot display character inputs. The toggle button itself will never render in v1.
