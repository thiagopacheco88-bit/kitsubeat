# Phase 11.5 Plan 10: Regenerate Lessons Summary

**One-liner:** Per-verse claude-cli subprocess loop + single `source='regen'` publishLyricsVersion commit + RegenerateLessonsModal with confirm/progress/error UI wired into VerseEditor header.

## What Was Built

### Task 1: regenerate.ts server action + computeDirtyVersesSinceLastRegen helper + integration tests (TDD)

**RED commit:** `b1e945e` — 3 integration tests (skip cleanly without TEST_DATABASE_URL):
1. regen row has `source='regen'` + `parent_version_id=baseVersionId`
2. Regenerating N verses produces ONE `lyrics_versions` row (single-row contract)
3. `draft.dirty_verse_numbers` is the regen scope source (`computeDirtyVersesSinceLastRegen`)

**GREEN commit:** `4972b3a` — `src/app/admin/lyrics/actions/regenerate.ts`:

- `regenerateLessons(input)`:
  - `requireAdminUser()` guard (server-side Clerk — never from client)
  - Per-verse loop over `verseNumbersToRegen`: `buildVerseFillPrompt` → `runClaudePrintParseJson(prompt, VerseFillResponseSchema, { timeoutMs: 120_000 })`
  - On success: merges AI result (`tokens`, `translations`, `literal_meaning`, `cultural_context`) into `workingVerses`
  - On error: pushes `{ status: "failed", error: "code: message" }` to `perVerseResults` — does NOT abort loop
  - After loop: single `publishLyricsVersion({ source: "regen" })` + `revalidateSongCache(slug)`
  - `StalePublishError` caught and returned as `{ ok: false, globalError: "stale_publish: ..." }`

- `computeDirtyVersesSinceLastRegen(songVersionId)`: queries `lyrics_drafts.dirty_verse_numbers` for the most recent draft. Returns `[]` if no draft. (v1 — future improvement: diff vs last regen/auto version.)

### Task 2: RegenerateLessonsModal + wire button into VerseEditor

**Commit:** `b2f7ec4`

**`src/app/admin/lyrics/components/RegenerateLessonsModal.tsx`**:

- Two-phase UI: confirm phase → running/done phase
- **Confirm phase:** Lists N dirty verse numbers with token surface preview (first 60 chars); time estimate (~30-60s per verse); `data-testid="regen-verse-{n}"` per verse; `data-testid="regen-confirm"` disabled when `dirtyVerseNumbers.length === 0`
- **Running/done phase:** `data-testid="regen-status"` (running.../done/error); `data-testid="regen-result-{n}"` per verse (green=regenerated, red=failed, gray=skipped/pending); `data-testid="regen-global-error"` for StalePublishError; `data-testid="regen-close"` visible after run completes
- Modal non-dismissable during run (backdrop click gated on `!isRunning`)
- On success: `clearDraft()` (regen publish consumed the dirty draft)

**`src/app/admin/lyrics/components/VerseEditor.tsx`** — Added:

- `const [showRegen, setShowRegen] = useState(false)` state
- `data-testid="open-regenerate-modal"` button in header row (disabled when `dirtyVerseNumbers.length === 0`); shows count: `Regenerate (N)`
- `{showRegen && <RegenerateLessonsModal ... />}` mount at bottom of return

## UAT Notes

Manual UAT requires Thiago to:
1. Load a song in the editor
2. Edit 2 verses (wait for autosave to record dirty_verse_numbers)
3. Click "Regenerate (2)" → modal lists both verses
4. Click "Regenerate 2 verses" → modal switches to running state
5. After completion: `SELECT version_number, source FROM lyrics_versions WHERE song_version_id = '<id>' ORDER BY version_number DESC LIMIT 3` — newest row should be `source='regen'`
6. Public page reflects the regenerated content (active pointer moved)

**Per-verse regen duration sample:** Not yet measured (UAT pending). Each verse is ~30-60s based on claude-cli latency observed in Plan 06. For a typical 5-verse regen, expect 2.5-5 min total.

**StalePublishError during UAT:** Unlikely for solo admin session. Error surfaced in modal's globalError pane with reload instruction.

**dirtyVerseNumbers scope sufficiency:** The editor's `dirty_verse_numbers` (from the most recent auto-saved draft) is the correct v1 scope. An admin-edited verse is always in the dirty set if they've typed in it and waited 5s for autosave. The "since-last-regen diff" path is a v2 improvement — not needed for SPEC #23 acceptance.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Verse.surface does not exist on the Verse type**
- **Found during:** Task 2 (TypeScript check)
- **Issue:** Plan's template used `v?.surface?.slice(0, 60)` for the verse preview in the modal confirm list, but the `Verse` interface (src/lib/types/lesson.ts) has no `surface` field. Surface text lives on each `Token` in `verse.tokens[]`
- **Fix:** Replaced with `verseSurface(v)` helper: `v.tokens.map((t) => t.surface).join("")` — correctly reconstructs the surface text from the token array
- **Files modified:** `src/app/admin/lyrics/components/RegenerateLessonsModal.tsx`
- **Commit:** b2f7ec4
