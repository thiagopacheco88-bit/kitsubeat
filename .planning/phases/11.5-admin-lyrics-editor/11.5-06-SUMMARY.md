# Phase 11.5 Plan 06: AI Fill Summary

**One-liner:** Per-verse `claude --print` subprocess wrapper + Zod validation + snapshot-before-return server action + inline spinner/accept/reject UI for admin AI assistance.

## What Was Built

### Task 1: Subprocess Wrapper + Zod Schema + Prompt Builder (TDD)

**`src/lib/admin/claude-cli.ts`** — Subprocess wrapper (verbatim from RESEARCH §6):

- `runClaudePrint(prompt, opts)`: spawns `claude --print --output-format=json` with `stdio: ["pipe", "pipe", "pipe"]`; inherits `process.env` for `~/.claude/` credential pickup
- `child.stdin.end(prompt, "utf8")` single-call pattern (Pitfall 4 — no stdin deadlock)
- Auth-prompt heuristic: stderr scanned for "sign in" / "log in" / "claude login" / "auth" / "authenticate" → `code="auth_prompt"` (Pitfall 5)
- SIGKILL on timeout (NOT SIGTERM — processes may ignore SIGTERM); AbortSignal propagation for Next.js request cancellation
- `ClaudePrintError` with discriminated `code`: `"spawn_failed" | "non_zero_exit" | "timeout" | "invalid_json" | "auth_prompt"`
- `runClaudePrintParseJson<T>`: fence-strip regex (`/^```(?:json)?\n?/` + `/\n?```$/`) → JSON.parse → Zod schema.parse

**`src/lib/admin/verse-fill-zod.ts`** — Zod schema for AI fill response:

- `VerseFillResponseSchema`: strict object with optional `reading`, `romaji`, `tokens[]` (passthrough), `translations`, `literal_meaning`, `cultural_context`
- `TokenFillSchema`: passthrough (model may add extra fields without breaking validation)
- `LocalizableSchema`: `z.union([z.string(), z.record(z.string(), z.string())])` for multilingual fields

**`src/lib/admin/verse-fill-prompt.ts`** — Per-verse prompt builder (D-06):

- `buildVerseFillPrompt({songTitle, songArtist, songAnime, target, neighbours, fieldsToFill})`: builds 5-block prompt (metadata, target verse, neighbour anchors, fields to fill, output schema)
- Block helpers mirror `scripts/lib/lesson-prompt.ts` structure but scoped to one verse
- `fieldsToFill` drives which TypeScript fields appear in the schema block — only requested fields shown

**`src/lib/admin/claude-cli.test.ts`** — 8 unit tests:

1. Happy path: mock spawn emits envelope JSON → resolves with envelope + stdin.end called
2. Timeout: mock emits nothing → rejects with `code="timeout"` + kill called
3. Non-zero exit (no auth keywords): rejects with `code="non_zero_exit"`
4. Invalid JSON stdout: rejects with `code="invalid_json"`
5. Auth prompt (stderr "sign in"): rejects with `code="auth_prompt"`
6. ClaudePrintError carries stderr + stdout strings
7. `runClaudePrintParseJson`: strips `` ```json `` fences and validates
8. `runClaudePrintParseJson`: Zod failure throws

All 8 tests green.

### Task 2: Server Action + Integration Test (TDD)

**`src/app/admin/lyrics/actions/ai-fill.ts`** — `"use server"` + `runtime = "nodejs"`:

- `aiFillVerse(input)`: requireAdminUser() guard → buildVerseFillPrompt → runClaudePrintParseJson(prompt, VerseFillResponseSchema, { timeoutMs: 120_000 })
- On error: `ClaudePrintError` surfaced as `{ ok: false, error: "code: message" }` — no throw to admin
- `mergeVerse()`: applies AI patch to target verse (spreads translations, replaces tokens if provided)
- `writeAiAssistSnapshot()`: D-20 — writes `lyrics_versions` row with `source='ai-assist'` BEFORE `return { ok: true, ... }`
  - monotonic `version_number` via `COALESCE(MAX(version_number),0)+1`
  - `editor_id` from `requireAdminUser().id` (AIFILL-T-04 — never from client)
  - `parent_version_id = input.baseVersionId` (the draft's pin)
- Returns `{ ok: true, verse: VerseFillResponse, snapshotVersionId: string }`

**`tests/integration/ai-fill-snapshot.test.ts`** — 2 integration tests:

1. Inserted `ai-assist` row carries `source='ai-assist'` and `parent_version_id=baseVersionId`
2. Three clicks produce three rows (SPEC #11: every click writes regardless of accept/reject)

Tests skip cleanly without `TEST_DATABASE_URL` (exit 0).
