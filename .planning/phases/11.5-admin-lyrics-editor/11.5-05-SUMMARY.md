# Phase 11.5 Plan 05: Draft Store Summary

**One-liner:** Zustand store + 5s-debounced auto-save + server-first/localStorage-fallback page-load handshake wiring the admin verse editor to lyrics_drafts per-editor upserts.

## What Was Built

### Task 1: useAdminLyricsStore + 9 unit tests (TDD)

**`src/lib/admin/lyrics-store.ts`**

- `AdminLyricsState`: songVersionId, editorId, baseVersionId, baseVersionNumber, verses, dirtyVerseNumbers, saveStatus (idle/saving/saved/error), saveError, lastSavedAt, _hasHydrated
- 10 actions: `init`, `updateVerse`, `insertVerse`, `deleteVerse`, `reset`, `markSaving`, `markSaved`, `markError`, `setHasHydrated`, `clearDraft`
- `dedupeAdd(arr, n)`: ensures dirtyVerseNumbers never contains duplicates; sorted ascending
- No `persist` middleware — D-17 mandates a manual server-first/localStorage-fallback handshake, not automatic rehydration
- Test-env window hook: `__kbAdminLyricsStore` (mirrors kanaProgress.ts:85-87 pattern)

**`src/lib/admin/lyrics-store.test.ts`** — 9 tests: init, updateVerse, dedup, insertVerse(after), insertVerse(null), deleteVerse, save status transitions, markError, clearDraft. All green.

### Task 2: saveDraft server action + integration test (TDD)

**`src/app/admin/lyrics/actions/save-draft.ts`**

- `"use server"` + `runtime = "nodejs"` (Clerk currentUser requires Node runtime)
- `requireAdminUser()` — editor_id sourced from server-side Clerk session (DRAFT-T-03; client cannot forge)
- `onConflictDoUpdate({ target: [lyricsDrafts.song_version_id, lyricsDrafts.editor_id], set: { verses, dirty_verse_numbers, updated_at } })` — base_version_id NOT in SET clause (D-17/D-18)
- Returns `{ ok: true, updatedAt, editorId }`

**`tests/integration/save-draft.test.ts`** — 3 tests (raw SQL):
1. Insert: first save creates new lyrics_drafts row
2. Upsert: second save with same (song, editor) updates row, count unchanged
3. Per-editor isolation: different editor_id creates SECOND row for same song (T-11.5-07)

Tests skip cleanly when TEST_DATABASE_URL is not set. Exit 0.

### Task 3: VerseEditor wired + SaveStatus + page.tsx draft loading

**`src/app/admin/lyrics/components/VerseEditor.tsx`** — Replaces Plan 04's local `useState<Verse[]>`:

- Subscribes to useAdminLyricsStore (verses, dirtyVerseNumbers, markSaving/Saved/Error)
- Mount effect: server-first / localStorage-fallback handshake (D-17):
  1. If `props.initialDraftFromServer` present → use server draft
  2. Else → read `lyrics-draft:${songVersionId}:${editorId}` from localStorage (try/catch DRAFT-T-01)
  3. Call `init()` with winning verses; mark initialDirty verse numbers via updateVerse
- Auto-save effect: 5s debounce (`AUTOSAVE_DEBOUNCE_MS = 5000`), hash-based dedup to skip no-op saves
  - On success: server save then localStorage mirror
  - On failure: markError + localStorage-only write (D-17 fallback path)
- SaveStatus badge mounted in header
- Insert/delete wired to store actions (not local state)

**`src/app/admin/lyrics/components/SaveStatus.tsx`** — New component:

- `data-testid="save-status"`
- 4 visual states: idle (grey, "no edits" or "saved Ns ago"), saving (amber "saving…"), saved (green "saved ✓"), error (red "save failed: ... (kept in localStorage)")

**`src/app/admin/lyrics/page.tsx`** — Modified:

- Added `currentUser()` Clerk import → `editorId = user?.id ?? "anonymous"`
- Added `lyricsDrafts` query filtered by `eq(lyricsDrafts.editor_id, editorId)` — per-editor isolation (T-11.5-07)
- Passes `editorId`, `baseVersionId`, `initialDraftFromServer` to VerseEditor
- Added guard: if no active_lyrics_version_id → surface notice instead of mounting editor
- `lyricsOffsetMs` prop name kept (Plan 04 deviation — real schema column is `lyrics_offset_ms`)

### Task 4: saveKanjiBreakdown real implementation (SPEC #9 ISSUE-02)

**`src/app/admin/lyrics/actions/save-kanji-breakdown.ts`** — Replaces Plan 04 stub:

- `saveKanjiBreakdown(input)`: requireAdminUser() → UPDATE vocabulary_items.kanji_breakdown WHERE id=vocabId → countAffectedSongs → revalidateSongCache(slug) for each
- `countAffectedSongs(vocabId)`: raw SQL LATERAL JOIN across song_versions.lesson JSONB to find all slugs referencing the vocab_item_id
- Cache revalidation is best-effort (try/catch — do not abort save on failure)
- Plan 04 VerseRow kanji breakdown editor dynamic import now resolves to real implementation

## Manual UAT Checklist (5s debounce — for Thiago/sensei)

1. Visit `/admin/lyrics?songId=<id>` — editor mounts, verses load from server draft or published version
2. Edit verse 2 translation → blur → wait 5s → SaveStatus flips "saving…" then "saved ✓"
3. Neon SQL: `SELECT verses, dirty_verse_numbers FROM lyrics_drafts WHERE song_version_id = '<id>'` → row present
4. Reload page → edit persists (server-first hydration)
5. Browser DevTools → localStorage → key `lyrics-draft:<id>:<editor-id>` exists
6. Open same song as a different admin → they see published version, not your draft
